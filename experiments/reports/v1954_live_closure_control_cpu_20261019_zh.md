# 实时 checkpoint 闭包观察与预取控制 CPU 降本

日期：2026-10-19。基线为 main 的 `48197f2`。
本轮继续执行 CPU 控制降本；GPU 实验仍按用户要求暂停。

## 改动及边界

上一轮 96-node 完整预取剖析中，闭包观察成为最大的单项自身成本。
本轮检查确认 Python 3.11 将 18 个关键字参数的节点摘要构造编译为
临时字典加 `CALL_FUNCTION_EX`，节点 ID、component、FULL 索引和 key
也存在重复读取。

本轮保留不可变 dataclass 及原字段，按声明顺序传递可辨识的局部字段，
避免逐节点关键字字典；在单次捕获中复用上述读取。索引长度读取和严格
边界验证合并，仍通过 CPU tensor shape 取长度，不访问 GPU tensor 数据，
不删除长度上限，也不将 bool 或非 Python int 长度当作有效数量。

每次入口仍验证实时 FULL/Mamba 池布局、归属和容量，遍历完整祖先链。
节点与 component 类型、节点/父 ID、创建时间、环与数量上限、四类锁、
两类引用和 session 身份集合、pending 状态及 key 长度均继续核对。
没有按节点 ID 或指针跨调用缓存物理状态。捕获后的原生回收、分裂、
来源重验、提交、ACK 与执行依赖保持原路径。

构造顺序由独立字段值检查及旧版差分核对覆盖。测试还在同一 node 上
改变 FULL/Mamba 驻留、锁、引用、session 集合、创建时间、pending 和 key，
确认新捕获读到新值，旧摘要保持不可变；祖先上的非法锁/引用仍拒绝。

## 对照加载修正

`benchmark_closure_geometry_cpu.py` 原来只提取旧闭包函数，放进新版
observer 的 globals，因此会共享新版辅助函数和数据类型。
`benchmark_checkpoint_ancestry_cpu.py` 原来加载旧 physical，却仍导入
新版 observer。两者均不能公平测量本次 observer 的变化。

现在两套基准复用已有冻结加载器，分别载入基线的 event_channel、
observer、physical 和 runtime，并重新绑定它们之间的引用。报告保留
这些完整来源的 SHA256。完整提交基准原本已使用该加载器。
旧结果仍保留，本轮使用修正后的基准，不把旧混合来源结果当作基线。

闭包基准的固定时钟原来是 `Mock`，会记录每次调用，在计时中增加分配、
保留调用历史并改变垃圾回收时机。首轮和同源复测都在单节点 tensor
场景出现一次毫秒级样本。另一次带 GC 回调的离线诊断观察到约 39.468ms
的二代回收；该诊断的回收发生在计时外的序列化处，不能反推首轮具体
调用栈。现在将固定时钟改为普通函数，不记录调用；不禁用 GC、不清洗
原始样本。V1955 是修正时钟后的完整 30 场景结果。V1951/V1952 原本
没有这个 Mock，不受修正影响。

## 闭包与 checkpoint 路径

V1950/V1953/V1955 包含 static、paged static、shared 三种池布局，深度
1/4/16/64/256 和 range/实际 CPU int64 tensor 两种索引，共 30 组。
每组 101 个保留样本，3 个预热样本，测量顺序交替；序列化在计时外。
样本间改变 leaf 的驻留、锁、引用、session 身份及 pending，逐字段核对。

采用普通固定时钟的最终 V1955，线程 CPU P50 全部降低，范围为
3.79%–17.57%；均值降低 4.13%–17.90%。深度 64 时：

| 布局 | 索引 | 基线 us | 候选 us |
| --- | --- | ---: | ---: |
| Static | range | 294.322 | 248.644 |
| Static | CPU tensor | 308.223 | 262.199 |
| Paged static | range | 294.953 | 247.749 |
| Paged static | CPU tensor | 316.060 | 262.827 |
| Shared | range | 301.159 | 257.567 |
| Shared | CPU tensor | 315.942 | 270.136 |

这里的深度是非根节点数，根节点也被观察。不能将深度当作实际 trace
的分布，也不能将这些时间按全部 decode 次数累加。

首轮 static/depth1/tensor 的均值为 21.425→39.487us，其中候选有
单个 1920.254us 样本；P50 为 21.515→20.602us。该异常保留在原始
样本中，没有删除后重算均值。V1953 同源复测也出现类似异常，不能称为
未复现的随机噪声。修正时钟后的 V1955 中，同场景均值
19.930→18.467us，P50 为 20.075→18.557us，最大样本为
20.947/20.009us。保留全部三轮，不将修正计时装置当成额外生产优化。

V1952 覆盖 H2D/PREPARE、8/64/256/1024 深度、1/4 leaf，以及 0/4 个
输入边界外输出节点。每组 51 样本、3 个预热样本，32 组完整观察和
32 组单独规划分别核对计划。完整观察 CPU P50 降低 7.51%–16.75%。
64 深度、没有输出尾部时：

| 完整观察 | Leaf 数 | 基线 us | 候选 us |
| --- | ---: | ---: | ---: |
| H2D | 1 | 406.524 | 355.478 |
| H2D | 4 | 1441.933 | 1242.414 |
| PREPARE | 1 | 381.164 | 326.562 |
| PREPARE | 4 | 1418.276 | 1208.856 |

单独规划算法未改，32 组 P50 变化为约 -2.02% 至 +1.36% 的小幅波动，
不计为规划器优化。共享祖先与安全输入边界下计划相同。

## 完整预取提交

V1951 的 40 组覆盖 JOIN/tool、4/16/64/65/96 节点、诊断开关、
原生/回退预算，并提供尾部回收入口。每组 101 样本、10 个预热样本。
运行真实 Python 观察、规划、来源重验和物理登记，native enqueue
使用 CPU stand-in；重置、状态检查和 cProfile 在计时外。

原生预算、诊断关闭，线程 CPU P50：

| 来源 | 计划节点 | 实际提交 | 基线 us | 候选 us |
| --- | ---: | ---: | ---: | ---: |
| JOIN | 4 | 4 | 389.151 | 380.811 |
| JOIN | 16 | 16 | 800.034 | 785.178 |
| JOIN | 64 | 64 | 1862.050 | 1794.884 |
| JOIN | 65 | 64 | 2033.392 | 1971.734 |
| JOIN | 96 | 64 | 2291.224 | 2210.878 |
| Tool | 4 | 4 | 373.962 | 367.048 |
| Tool | 16 | 16 | 694.747 | 674.244 |
| Tool | 64 | 64 | 1863.647 | 1819.887 |
| Tool | 65 | 64 | 2026.604 | 1986.526 |
| Tool | 96 | 64 | 2290.612 | 2222.147 |

64 节点 JOIN/tool 分别只改善 3.61%/2.35%，明显小于闭包局部降幅。
40 组中 39 组 P50 更低；诊断开启、回退预算的 64-node tool 为
2189.908→2209.844us，回退 19.936us/0.91%。完整范围为
-0.91% 至 +3.75%，不宣称每种完整路径均加速。

恢复目标、顺序、必要状态、pending 数量/字节和驻留预算相同。
65/96-node 真实尾部仍重新规划，未更改数量或容量限制。
9 组 prefill 依赖检查的判定、原生对象/调用频率及 pending 相同；
时延仍有小幅正负变化，例如 64 条命令、数据未就绪为
24.760→25.131us，不将未修改的依赖路径计作改善。

## 验证与下一步

一次扩展 CPU 回归为 1948 passed、无 skip；初步的 96 项 observer
检查包含在该集合内，不重复计数。覆盖 observer、physical、runtime、
会话、准入、工具/JOIN、PREPARE、handoff、部分恢复、重验、驻留与
transfer 等关联路径。使用 `CUDA_VISIBLE_DEVICES=99999`，
显式绑定合格 `sglang-v86-chat-token-cache-cpu-20261019` checkout，
包含真实 CPU radix/allocator/reclaim 检查，没有模型服务或 DMA。

最新 96-node tool 剖析中，真实尾部规划、原生操作核算和登记仍是主要
自身成本，闭包捕获也仍有成本。只靠删除逐节点临时分配不能解决全部
高频控制工作；后续继续依据实际调用频率和完整路径成本选择优化项。
不删除最终来源、容量、所有权或执行依赖验证来换取计时改善。

本轮不改变预测模型或启动时机，也未得到新的在线预取复用、吞吐或 JCT
结果。GPU 暂停标记和禁止自动接续状态保持；24-root 仍只是待恢复候选。
