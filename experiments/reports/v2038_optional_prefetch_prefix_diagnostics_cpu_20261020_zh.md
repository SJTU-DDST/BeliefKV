# 预取同步 token 诊断改为按需开启

日期：2026-10-20（北京时间）。基线 `83d0709`。本轮只使用 CPU；
新 GPU 实验最早于北京时间 06:00 在资源空闲时开始。

## 定位与修改

预取发出回调 `on_prefetch_issued` 会沿各目标的原生 key 路径独立复制
token 前缀，首次服务再与请求输入逐 token 比较。此前完整 JOIN/tool
提交夹具没有接入这个真实 telemetry 回调，不能用其微秒计时覆盖本段。

原生 RadixKey 的 token_ids 已是 array，不能把 list.extend/fromlist 的
单独差距视为实际机会。本轮读取冻结 V88 的真实 RadixKey AST，测实际
数组路径。额外 token 比较只生成 target_prefixes 诊断；原生 FULL 复用
证明使用节点/分配对象、代际、祖先关系、物化前缀长度和驻留，Mamba
另有 forward/source/destination 证明。

现在新实验默认 `PREFETCH_PREFIX_DIAGNOSTICS=0`，省去额外 token 快照
及相应比较，保留原生复用证明和 ACK 生命周期。原生 key 路径及长度仍
读取，不能用一个估计长度替代物化前缀检查。记录增加
target_prefix_diagnostics=captured/disabled/unavailable，缺少 token
快照不表示 FULL 或 Mamba 没有复用。

排查文本差异时设为 1，独立快照、原 131072-token 上限和比较保留。
启动器会规范化该值并覆盖继承的底层环境；计划、逐 arm 服务端 launch、
ready、resume 和汇总都记录/校验它。旧计划没有此字段时，恢复仍启用
旧诊断，避免新默认值改变历史合同。没有变更迁移策略、引擎或模型。

## 完整 CPU 回调对照

V2034 比较真实发出回调、显式模拟的 verified ACK 和首次服务证据处理。
8K/32K/131K/262K 输入、1/16/42 个目标、关闭/开启诊断，共 24 组；
每组 151 样本、10 次预热，新旧交替，使用相同原生 key、cache、请求
输入和 action 对象，分别维护 telemetry 库存。

所有 ACK、非诊断首次服务字段、原生 FULL 复用结论和库存生命周期相同。
比较排除新增的诊断状态字段；关闭时另外排除有意省去的 target_prefixes，
没有宣称两侧完整诊断 payload 不变。开启时 token 诊断也一致。
ACK 前没有发布复用记录，模拟 ACK 后才消费与发布；这些不是实际 DMA
或线上复用信用。

42 个目标、关闭额外诊断的线程 CPU P50：

| 输入 token | 发出：基线/候选 ms | 首用：基线/候选 ms | 省去 token 数组 MB |
| ---: | ---: | ---: | ---: |
| 8192 | 0.6371 / 0.2502 | 0.5414 / 0.2079 | 1.409 |
| 32768 | 2.6502 / 0.2598 | 1.6154 / 0.2112 | 5.636 |
| 131072 | 9.3758 / 0.2658 | 5.6321 / 0.2156 | 22.544 |
| 262144 | 4.7438 / 0.2621 | 4.7443 / 0.2106 | 11.534 |

这里是独立 CPU token 诊断数组，不能当成 FULL KV 传输字节。
262K 下原先只有 21 个祖先前缀不超过 131K，复制量因此小于 131K 的
42 目标场景；不能据此认为大上下文更便宜。

关闭诊断的 12 组中，11 组发出回调更快；262K 单目标原本就跳过复制，
4.052→4.140us，多 0.088us。开启诊断的 12 组保留额外字段/开关判断，
发出回调多约 0.001–7.411us；最大为 8K/42 目标。全部原始 wall/thread
样本、ACK 和首次服务控制均保留，不宣称所有路径都加速。

## 初次测量与限制

最初一次新夹具错误地断言 ACK 阶段不应有任何日志，实际原有行为会
发布 action_ack。该次在写报告前失败；修正为只禁止提前的 action_use，
没有修改生产 ACK 行为。

V2033 的初版使用独立输入地址，并在收集快照统计时额外保留了数组列表，
改变释放时机；开启诊断控制曾有 32K/16 目标 0.279→0.809ms 的回退。
该数据保留。V2034 使用相同 native 对象，统计只保留数组数目/字节标量，
随后恢复本来的生命周期；初次大回退未复现，保留最终小回退。
两轮样本数和 CPU 环境也不同，不将所有差异归因为其中一个因素。

计时包括真实 Python 回调及受控遍历，不包括真实 allocator、CUDA、
DMA、writer 线程、文件序列化或并发 key 变更。没有用旧 trace 的频次
乘局部成本估计 JCT，也不能把 97% 左右的局部降幅当整体控制成本降幅。
