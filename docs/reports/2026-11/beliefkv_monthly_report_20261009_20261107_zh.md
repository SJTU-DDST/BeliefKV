## 二、成果说明

### 1. 调度与 KV 协同降低 workflow JCT

基于 ThunderAgent 工作集框架，结合实际工具和 JOIN 阻塞状态，
协调 agent 准入、工具等待期的 KV 卸载、增量 Host 备份和 JOIN/EOS 恢复。
使释放的容量面向真实待执行 agent，并将恢复与其实际模型服务衔接，
同时保留正在执行 agent 的连续性。

| 已完成匹配对照 | 平均完整 JCT | 共同窗口输出吞吐 |
| --- | --- | --- |
| 相同优化引擎下，Full 对 ThunderAgent acting-decay | 1083.13 s → 964.29 s，降低 10.97% | 提高 2.47% |
| 原默认引擎下，Full 对 native SGLang | 1215.27 s → 1052.99 s，降低 13.35% | 提高 1.63% |

两组均使用 56 个不同项目、200 GB Host、持续到达和固定 18 个测量成员，
保留每个测量 workflow 的完整正常尾部。每一行内部的工作量与资源匹配，
两行采用的引擎配置不同，不将收益相加或混作同一组实验。

Trace 采集、baseline 适配和评测建设作为上述结果的验证支撑，不单列成果。
短 workflow 排序和预测器探索尚未建立稳定增益，也不将本表系统收益归给它们。

### 2. 工具替换检查的控制成本降低约一半

针对控制路径中大量没有有效配对的重复检查，实施 donor 预筛、
消费者需求与释放计划复用、普通 hint 刷新合并，以及后台重试节流。
保留工具返回、容量变化等真实事件的及时响应和动作前原生安全检查。

在相同 1583.26 秒共同窗口内，工具替换检查线程 CPU 从旧两轮的
47.10 / 54.85 秒降至约 25.48 秒，减少 45.9%–53.6%。
这是该项控制路径的成本下降，不是全部 CPU 开销下降，也不直接等于 JCT 收益。

## 三、口头汇报稿

本月主要取得两项进展。第一，完善了面向工具和 JOIN 阻塞的调度与 KV
协同方案，使缓存容量释放、上下文恢复和 agent 实际执行形成闭环。
在已完成对照中，相对 ThunderAgent 的平均 workflow 完成时间降低约 11%，
另一组相对 native SGLang 的对照降低约 13%。第二，优化调度控制路径，
通过预筛、复用和事件合并，将工具替换检查的 CPU 开销降低约一半。
下一阶段重点是验证持续压力下收益的稳定性，并提高 workflow 调度的独立收益。

## 四、下一阶段

完成更强持续压力下的匹配对照，验证调度竞争、完整 JCT 和收益稳定性。
短 workflow 排序及新设计继续按端到端净收益筛选，不以预测准确率、
测试数量或实现完成替代性能成果。
