# 工具预取选择的重复预算计算

日期：2026-10-23，北京时间。应用基线为 main 的 `fcd4d12`。
V128 仍执行原冻结应用 `04191b0`，本轮改动未注入运行中的比较。

## 修改

工具选择器先计算原生预算检查预取槽，随后恢复计划再次读取请求槽、
运行 batch、可回收量、保护字节并计算相同预算。V2894 使用完整工具
选择器和既有 CPU cache 夹具复现：4、16、64 节点三种情况下均调用两次，
新增的单次读取断言在旧代码上全部按预期失败。

现在先保留本次选择的预算及其空闲池观察，读取恢复计划时暂不重复应用
预算，再用同一份预算裁剪计划。仅当预算来自 `native_next_prefill`、
恢复计划与预算的空闲池观察相同时复用。观察变化时仍重新读取预算。
变量只存活于本次同步调用，不跨轮缓存；原容量回收后的重算、事件排空、
提交前身份与容量复核、账本和原生 allocator 检查继续执行。

没有恢复目标的缓存观察仍跳过预算；没有预取槽时仍先返回，不进行长路径
规划。原机会缓存的有效期、工具窗口、JOIN/EOS、优先级与驻留策略未改。
没有新增计时器、线程、跨轮失效表或在线日志。

## CPU 对照

V2896 用固定旧源码和当前源码，正常 GC、交替执行顺序、101 个采样轮次，
对照 24 个完整 dispatch 案例，包括 JOIN/工具、三种路径深度、
原生/兼容预算和记录开关。原生发行回调、记录、实际恢复目标、完整物理
期望及待完成账本均一致；夹具没有真实 GPU、DMA 或 Host 竞争。

保留全部场景，包括没有直接修改的 JOIN 及兼容预算下的小幅波动。

略有变慢。不能把微秒级选择器降本解释为 Full 整轮吞吐或 JCT 的提升，
也不按预取字节给这些 CPU 案例加权。
