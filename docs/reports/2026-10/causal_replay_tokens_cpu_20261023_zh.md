# JOIN 波动与精确 token 回放准备

日期：2026-10-23，北京时间。应用基线为 main 的 `e371f05`。
本次只增加辅助实验模块和测试；V129 native 采集继续使用独立冻结副本，
没有将本次修改注入运行中的源采集。

## 先更正 JOIN 数量口径

最新完整 V128 证据来自 V2915/V2916 和关闭后台组的完整审计：

| 指标 | Full | 关闭后台 prepare |
| --- | ---: | ---: |
| Harness JOIN 总数 | 66 | 75 |
| 完成前有正 FULL 计划 | 61 | 50 |
| 完成前提交且确认复用 | 61 | 38 |
| 上一行 FULL，GB 十进制 | 9.906258 | 2.784768 |

“50”不是该组总 JOIN 数，也不意味着其他 JOIN 都漏触发。prepare 为
parent 保留可恢复的 Host 副本，并使已有备份的冷页可以释放 HBM，
有助于将 EOS 机会转成实际传输。关闭后台备份组仍保留 spawn 等路径，
不是没有任何 D2H。两组的轨迹、输入和输出均不同，因此字节量之比
不是 prepare 的净收益或 JCT 加速比。

同版其他组 JOIN 为 84、92，native 为 78。此前关闭后台与关闭工具模型
两组中，单个 system automation 任务从 4 轮变为 18 轮，贡献总差异
17 次中的 14 次。固定任务、seed 和 temperature 不能保证动态工具、
并发 batch 下的模型轨迹一致；该轮分歧的首个直接原因仍未定位。
不能为凑 JOIN 数强制模型多轮委派或拒绝自然结束。

## 两种实验各自回答的问题

动态端到端实验继续保留模型自主 spawn、嵌套和自然结束，完整报告
JOIN、工作量、guard、JCT、吞吐与正常长尾。预先登记的一次 native
真实轨迹采集提供辅助对照源，不根据其结果挑选有利轨迹。

辅助回放固定该轨迹的精确模型工作量和已经发生的委派决定，工具保留
原持续时间与并行关系，后继等待本轮实际前驱完成。它能消除这一辅助
比较中的 JOIN 数量差异，但不代表新的在线动态自主决策，也不能取代
原始端到端结果。原 GPU 服务时长不能重新变成回放中的固定等待。

## 本次实现

`CapturedTokenCorpus` 校验完整原生请求总体、因果身份、精确输入输出
哈希、同 scope 的已完成前缀引用，以及所录制的六项停止参数和非 abort
结束原因。旧日志缺少停止证据、不完整总体、截断记录和源文件变化都会
拒绝。索引只保留文件位置；按任意就绪顺序重建输入，使用有界 LRU，
不把全部长历史常驻内存。返回值独立于缓存，调用方修改不会污染基准。

`CapturedOutputLogitsProcessor` 使用原生 `Req.output_ids` 的当前长度
选下一个录制 token，不维护随 batch 行号移动的游标。混批重排、过滤、
撤回后重新执行均按实际请求进度选择；重复的 speculative 行会拒绝，
本次不声称支持 speculative decoding。

输出序列耗尽时要求原生路径已经结束，不另造 EOS，也不把观察到的输出
长度改写为新的 min/max token 上限。后续 backend 仍须保留原始
max/min、ignore_eos、stop 字符串/正则/token ID，并校验实际输出和
finish reason。未来输出只供私有回放数据路径使用，不能成为调度信息。
