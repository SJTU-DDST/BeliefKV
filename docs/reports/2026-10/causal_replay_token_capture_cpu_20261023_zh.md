# 依赖回放的精确 token 输入录制

日期：2026-10-23，北京时间。应用基线为 main 的 `f86ab8d`。
V128 仍执行冻结应用 `04191b0`；Full 正在运行，随后为 native_matched。
本轮没有修改冻结应用、引擎、prompt、任务集或当前实验环境。

## 为什么需要补齐输入

三个最新完成消融的逐 workflow 工作量差异仍大，不能用总请求数或
总输出接近证明相同工作量下的收益。固定真实轨迹的依赖回放可以辅助
隔离系统模块，但必须保留精确前缀共享、输出工作量及实际解锁关系。

V2910 核查最新完成的 no_child_reclaim：7841 个原生模型请求、输入
506192029 token、输出 1878091 token 的身份和用量可用，但没有精确
prompt/output 录制。root 最终 trajectory 不包含每个 child 的完整历史，
长度、哈希及前缀跨度也不能逆推出 token 序列。检查器保留这项未知，
没有用填充 token、推测的 child 输入或旧 oracle 回放冒充等价输入；
`--require-complete` 返回 2，并保留未通过的 JSON 报告。

现有 OracleGPUReplay 还会设置 ignore_eos 并固定生成长度，且其冻结
边界模型不能原子表示同一模型结果中的普通工具与 spawn。它不能直接
作为当前 EOS 预取设计的合格对照。

## 实现与成本

新增 `BELIEFKV_REPLAY_TOKEN_CAPTURE=1`，默认关闭。
启用后在 `server/request_tokens.jsonl` 保存请求首次原生 GPU 服务时
的精确输入，以及原生请求完成时保留的精确输出，关联原请求、workflow、
invocation、context/epoch、session/generation、缓存命名空间和原输出预算。
记录的是诊断输入，GPU 回放及任务正确性并未因此获得资格。

录制模式在上述两个边界同步取得独立 token 快照，编码、哈希及写盘复用
已有异步 telemetry 线程。没有增加后台线程或周期扫描，也不把快照复制
描述成零成本。默认关闭时不为本功能复制、编码或哈希输入输出。

输入引用同 scope 中已完成请求的精确公共前缀，只写 uint32 little-endian
base64 后缀，并记录完整序列 SHA-256。session、代次、命名空间变化或原
历史过期时重新写完整输入。解码时验证基准身份、范围、长度及完整哈希，
不通过的输入拒绝恢复。相同物理 context/session 跨 invocation 的续接
仍可引用前缀，每条请求自己的 invocation 身份另与原生事件核对。
输出不引用前缀，全部记录。这里的服务与完成是原生 CPU 回调边界，
不声称新增了精确 CUDA 执行时钟。

离线检查器同时核对原生 submit/result 的完整请求总体、因果身份、
输入输出用量及原输出预算；缺失、重复、跨 scope 基准、坏编码、
篡改内容或不完整输出均不能通过。录制错误不能静默降级为合格 token
证据。正式内部性能比较监控拒绝启用录制的组，旧版缺少该新字段的
冻结结果仍可按原有检查观察，不修改它们的原始结论。

交替执行顺序、101 个采样轮次。原有被比较的记录及索引状态一致。

不能据此声称默认路径严格零成本，也没有 GPU、GIL 竞争或 JCT 结论。

V2909 使用真实 NativeReactiveTelemetry 写入线程和 CPU callback 夹具，
执行 50 个 100K 到 149K、每轮增加 1K 的输入，原输入共 6225000 token，
输出共 100 token；全部编码解码、原生用量及请求身份核对通过。

约 97.61%；文件实际为 854766 字节。这是诊断日志的去重，
不是模型输入、KV 迁移或推理工作量减少，更不是性能提升。
该夹具没有真实模型 forward 或 GPU。V2913 用最终代码重新核对同一
录制文件，完整身份、用量及 token 解码仍通过。
