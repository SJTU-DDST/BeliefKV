完整归档、Git 历史对象及暂存对象核验均通过，并完成原路径恢复实测。

最终磁盘观测为北京时间 2026-11-21 13:59。目录及磁盘前后差值包含
并行实验等写入；净回收估算按选择清单的原始分配空间减归档分配空间计算。
GB 使用十进制单位，可用空间采用 `df` 的 available，排除文件系统保留块。

本轮补查了 BeliefKV 与 SGLang 两个独立 Git 仓库登记的历史 worktree。
此前清理主要覆盖 BeliefKV 副本，独立登记的引擎副本尚有大量残留；
另有一些副本仅因历史研究文档提到过路径而被保留。

本轮按实际依赖筛选：检查当前源码、脚本、配置、环境安装信息、近期输入
元数据、运行进程、容器挂载及指向引擎的软链接。历史叙述中的引用本身
不再要求永久保留整个展开目录。创建时间以 worktree 的 `.git` 文件为
依据，筛选早于北京时间 2026-11-01 的副本。

## 保留与恢复

239 个选中的引擎副本含有未提交的冻结修改。这些修改连同未跟踪文件、
忽略文件、符号链接、原始 Git index 和管理信息一起完整压缩归档。
未把冻结修改当作可丢弃内容，也未使用 Git 强制删除或重置。

原 HEAD、HEAD reflog 提交及原始 index 所需对象均通过归档引用固定，
避免后续 Git 垃圾回收破坏恢复条件。原分支保持不变。

每份源码归档和 Git 管理目录归档均先与原目录完整比较。对不同仓库和
工作区状态共执行 **9 次还原演练**，比较完整文件内容、原始暂存状态与工作区状态。
随后重复依赖及内容检查，移除已归档的展开副本，并仅注销其对应登记。

逐项恢复命令见
[归档恢复索引](../../experiments/archive/20261121_historical_worktrees/README.md)。
恢复时必须确认原工作目录及原 Git 管理目录均不存在，不能覆盖新建副本。

另按清单在原路径实际恢复了一份已移除的冻结引擎，重新登记原 Git 管理
目录，核对源码、原始 index、暂存及未暂存状态均一致。验证副本随后移除，
没有留下额外展开目录。

## 执行与证据

维护采用 nice 19、idle I/O，每份归档使用一个 zstd 线程。后续以三个
互不重叠的批次续跑；已完成部分不重复处理。两个维护中断检查点完整保留。
路径解析缓存仅替换重复的祖先查找，保护集合及扫描文件数经过一致性核验；
新增登记会使解析缓存失效。

当前 GPU 实验、排队计划、输入、输出、模型和环境均在本轮移除范围之外。
主工作区现有图表修改保持原状。
