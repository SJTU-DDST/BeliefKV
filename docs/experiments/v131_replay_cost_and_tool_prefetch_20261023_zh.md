# V131 真实轨迹重放成本与工具预取开关

日期：北京时间 2026-10-23。

## 实际重放内容

Full 和 native_matched 均重放 V129 的原生动态运行：
`qwen35_locobench_long_36root_running8_exact_native_source_20261023_v129/native_capture`。
不是 V108，也不是分别选取两条输出数量相近的轨迹。
共同工作为 36 workflow、8165 个服务端模型请求、602782233 输入 token、
2352172 输出 token、73 次 JOIN、123 个动态 subagent、9846 对工具事件。
客户端任务摘要的 8163 次请求不包含两个上下文压缩请求；
相同工作量校验以全部 8165 个服务端回执为准。

后继依赖本轮真实前驱完成解锁，保留源工具及外部处理延迟。
每次请求实际执行原生模型 forward，强制原始输出 token，并检查
输入、输出、停止条件和会话身份。调度策略看不到未来轨迹。
源采集和当前重放的原生引擎树均为
`cc9772c6c5c4dcd3678a03b67fa9afc190aec4f8`。
两个收集提交之间的 `beliefkv/runtime`、原生补丁和服务启动脚本
也没有源码差异；这仍不等于已经控制 GPU 时钟等全部外部条件。

## 绝对速度受重放服务方式影响

| 完整指标 | V129 源 native | V131b native 重放 | V131b Full 重放 |
| --- | ---: | ---: | ---: |
| 平均 JCT | 2458.708s | 2802.152s | 2928.221s |
| JCT 中位数 | 2546.991s | 2889.844s | 3072.826s |
| 全程时长 | 4950.706s | 5785.155s | 5965.544s |
| 全程输出 token/s | 475.119 | 406.588 | 394.293 |

native 重放比源平均 JCT 增加 13.968%，全程时长增加 16.855%，
全程输出速率降低约 14.43%。源已经是较长运行，但不能将重放变慢
全部解释为任务变长或正常尾部。上述速率包含 prefill、工具与尾部，
不是 decode kernel 或满批 decode 吞吐。

CPU 复核以源请求的原始客户端提交至服务端完成间隔代入依赖图，
重建平均 JCT 为 2456.615s，与客户端摘要平均绝对差约 2.093s。
该差包含工作流事件边界以外的包装时间。没有发现把原始 GPU 服务
耗时再次当作外部延迟重复等待的证据。这是依赖一致性检查，
不是 GPU 性能预测。

分别封存源与 native 重放的完整 service audit，排除健康检查：

| Worker 区间 | V129 源 native | V131b native 重放 |
| --- | ---: | ---: |
| prefill 批次 | 8838 | 8826 |
| prefill 区间累计 | 379.332s | 394.977s |
| decode 批次 | 499013 | 494936 |
| decode 区间累计 | 4482.606s | 5338.345s |
| decode 请求步数 | 2351949 | 2351962 |

decode worker 区间累计增加约 19.1%。按相同请求、上下文长度、
输出进度、graph 标志匹配到 127823 个单请求 decode 对，
源和重放均值分别约 4.683/6.314ms。该样本主要来自尾部，
没有匹配相邻批次、背景传输和所有并发状态，不能据此推断整场
纯 kernel 慢 34.8%，也不能把区间累计差直接从 JCT 扣除。

源 audit 封存前缀：1590628797 字节，SHA-256
`47b52a5edf2ececee1cc8b5b051a2ae7534066e88037b6247488ae59e558042e`。
native 重放前缀：1590648524 字节，SHA-256
`8000b5ae00e48d7a7fa4191acb6eafb3cf463a5dcfaab98554fca39962a765bd`。

原生 custom-logit 分发先执行 GPU `batch_mask.nonzero`，随后根据
GPU 索引选 Python 参数并对 logits 作布尔索引。这条入口存在同步
和索引成本，V2971 已测得 batch1/8 相对 greedy 组件增量约
0.167/0.245ms。重放还启用源未启用的 delayed sampling，
并改变 HTTP 输入和回执路径。这些差异的完整端到端贡献未被单独
隔离；微基准在 logits 已就绪时测量，不能覆盖 forward 尚未完成时
同步对流水线造成的影响。

因此这轮只能作为共同重放条件下的辅助对照。Full 平均 JCT 比
重放 native 慢 4.499% 的负结果保留；共同成本可能改变批次、
预取提前量和迁移与计算的重叠，不能假定一定被比值抵消。
正式端到端结论仍需低侵入的重放校准和真实动态运行支持。

## 轨迹适用范围

73 次 JOIN 以及 Full 约 10.06GB 的提前确认复用 JOIN FULL，
支持将其用于 JOIN 恢复与控制的消融；不能仅因 Full 负收益换轨迹。
但它只有一次嵌套委派，不能代表丰富的嵌套场景。
源中一个 guard workflow 有 686 个请求、332275 输出 token，
约占输出的 14.1%，且在两组重放中都是最后完成的 workflow。
完整结果保留它，并继续单列预先登记的相同 35 项无 guard 结果，
不事后删掉正常长尾。35 项 Full/native JCT 仍约为 2841/2717s，
性能差距不能全部归因于这个源 guard。

## 关闭工具等待期 H2D

现有 Full 中，工具预取事件最后 ACK 到首次服务 P50 约 12.47s。
根据用户允许的两种方向，当前选择关闭工具等待期推测 H2D，
保留工具时长预测的备份/卸载资格、spawn/后台增量 prepare、
借用容量管理、JOIN/EOS 预取、resident-first 与阶段优先。
不重新启用普通 execution-frontier restore、handoff 或短工具续接。

`run_causal_comparison.py` 增加独立 `no_tool_prefetch` 控制；
相比同一 Full 环境仅更改 `BELIEFKV_ENABLE_TOOL_PREFETCH=0`。
原生观察必须核对实际 `tool_prefetch=false`，其余 Full 控制照常验证。
可通过 `--arms no_tool_prefetch` 单独选择，避免重跑未更改的 native。
可用 `--after-registration` 在现有矩阵释放全部进程后接续，
并重新验证前序每一组的实际回执、工作量、停止条件和配置。
前序失败、进程残留或源轨迹与容量变化时不启动后继。
