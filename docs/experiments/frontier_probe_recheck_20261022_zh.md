# 执行前沿的临时负例复查与控制降本

日期：2026-10-22，北京时间。CPU 验证，GPU 性能尚未验收。

## 根因与影响范围

V118 等待启动期间检查新执行前沿路径，发现首次没有恢复需求会将
`_frontier_probe_after_ms[key]` 设为 infinity。请求仍在队列中时，
原生驱逐可能使其从 resident 变成 Host-only，checkpoint 也可能稍后才发布；
这些变化不要求 request/session/epoch key 改变，因此同一请求再无复查机会。
同时，旧路径仍定期调用完整准入规划，只在规划之后跳过这个 key。

V2683 的 CPU 复现中，时间 10.0 秒时 checkpoint 驻留，随后同一请求
已有可恢复的 Host-only 数据、空闲容量及正恢复计划。10.051、10.25、
11.0、12.0 秒的检查共造成 5 次准入规划，但只读过 1 次原生 reentry，
没有重新发行恢复。这是提交后执行前沿路径的缺陷；不能归因为历史 V109
落后的已验证原因，因为该路径是后续才引入的。

## 修改

1. 临时没有 anchor、观测暂不可用或 checkpoint 已驻留时，复用既有
   200ms probe 退避。到期重新观察当前状态，不再永久记为无机会。
2. 同一有界 tagged 候选集合均处于退避期时，跳过完整准入规划；
   出现任何到期、新身份或未知身份即回到正常规划。检查与原规划同样
   最多覆盖 512 个 tagged 请求，不会越过这个边界自行挑选其他目标。
3. 有运行槽位是上游条件。running 已满时，在扫描队列之前返回；
   防止为了优化负例，反而在满载 decode 时遍历整条队列。
4. 周期复查先复用原生 session anchors 做现有的缺失 Host 副本检查。
   只有整条已观察路径明确无可恢复缺失副本时才跳过长输入验证；
   任意未知 metadata 都走原有验证。这里不按输入长度猜测 checkpoint，
   也不把该粗检查作为 H2D 的发行权限。
5. 成功提交仍记录本请求已经发行，不引入重复恢复、完整 ACK 等待、
   新排序、驻留租约或额外 donor 搜索。EOS/关键 parent 的接管优先级不变。

周期元数据复查仍有成本；它不是原生逐层 H2D/GPU 吞吐收益的证明。
底层引擎、模型、batch、任务、seed 和实验主排序都没有修改。

## CPU 证据

V2689 使用 pinned `67d904b` 的实际 `dispatch_frontier_restore` 方法体，
其他 helper 共用。保持正常 GC、101 个交替样本及全部原始计时。
比较图、visible/session 状态、在途命令和等待 ticket；诊断计数有意不同。

| 队列 | 全部处于退避期，旧/新 P50 | 首个到期候选，旧/新 P50 | 无运行槽位，旧/新 P50 |
|---|---:|---:|---:|
| 8 | 53.13 / 23.83us | 62.11 / 64.21us | 10.16 / 10.22us |
| 48 | 152.65 / 84.39us | 161.63 / 161.36us | 12.22 / 12.50us |
| 128 | 271.31 / 159.68us | 278.49 / 279.63us | 10.28 / 10.33us |

退避场景每样本 10 次调用的完整规划从 10 次降为 0 次；首个到期
场景两侧均规划 10 次、读取 anchor 10 次。该候选采用尚未发布 anchor
的标量入口，不代表正 H2D、分配器或实际长输入匹配。
8 请求新候选约增加 2.1us，其他小幅负向差异仍保留，不将其宣称为零。

另用冻结引擎原始 `RadixKey` 与 `inspect_beliefkv_reentry` 方法，
在 131072 token、一个 session leaf 的合成树上测得单次检查：

| 路径节点数 | 缺失副本 metadata P50 | 原生输入/reentry 验证 P50 |
|---|---:|---:|
| 16 | 11.00us | 89.97us |
| 64 | 33.88us | 193.81us |
| 1024 | 461.84us | 1499.18us |

使用标量 index metadata，未分配真实 KV pool，不涉及 DMA、GPU 或模型
推理。这里仅比较一次验证的成本；新版本会定期重新检查状态，不能用单次
比例宣称全程 CPU 降低同样比例，也不能与另一个表相加换算 JCT。
有 Host-only 数据时仍执行完整输入验证；这类正 H2D 路径的总成本没有
被此处 metadata 表完整覆盖。

此前 V2684/V2688 是同一轮修订的中间计时，继续保留；最终绑定使用
V2689。期间 CPU 测试也复现并修复了“无运行槽位时仍扫描退避队列”
的问题。没有据单独更好的样本删除早期结果。

最终应用资格 V2685 共 3779 项通过，保留上一轮全部 3770 项并增加 9 项，
无 skip、2 个 subtest 通过；此前相同的一个 Docker 沙箱测试仍明确
deselect，不计通过。新增项覆盖临时负例变正、未知观测、身份改变、
真实驻留 metadata 和满 running 队列边界。源码绑定 V2686，总资格
V2687。原生引擎未改动，沿用 V2664 的 467 项资格。
新的 V119 冻结登记保持 Full、JOIN-only、工程对齐 native 的顺序，
最早北京时间 2026-10-22 06:00、资源空闲后执行。
