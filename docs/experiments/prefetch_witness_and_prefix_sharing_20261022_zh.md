## 负身份见证不等于实际未使用

v2首次服务复用检查要求缓存节点仍持有发出传输时的同一Python Tensor
对象，并处于服务前缀中。原生FullComponent.redistribute_on_node_split
会克隆索引Tensor，原有KV槽索引仍可保持；这是索引元数据重排，不是
复制或释放所指向的完整KV池。

V2852及新增CPU回归复现：

| 情况 | 服务前缀中的原索引数 | v2 full_node_reused |
| --- | ---: | --- |
| 未改变 | 10/10 | true |
| 原生分裂后完整消费 | 10/10 | false |
| 原生分裂后部分消费 | 4/10 | false |
| 换成另一组索引 | 0/10 | false |

复现使用CPU索引Tensor和实际原生分裂方法，不执行GPU模型。初次复现
引用的本地原生副本与冻结引擎文件整体不同，但该分裂方法的AST完全
一致；新增回归显式读取SGLANG_SOURCE_CHECKOUT所指冻结引擎。
这些案例证明v2可漏记，不证明历史某条命令确实发生过分裂或实际节省了
等待。

V127原有138条工具FULL命令及1.978GB传输保留：30条、0.327GB有
首次服务正见证；108条、1.652GB是负身份见证。其中40条、0.715GB
存在同节点FULL reload关联，68条、0.937GB无该关联；本组reload关联
均为legacy_batch_pool_presence，不是逐页分配/重复传输的严格证明。
不能将108条全称为无效传输，也不能将68条直接补算成复用。

离线报告保留legacy full_not_reused_commands及全部旧数值，增加
full_identity_not_verified_commands、对应已知字节、reload关联分组及
原始full_use_witness字段，显式说明其证据限制。
V2853的116项聚焦测试通过；V2855逐项核对295823个既有字段不变，
仅扩展source_summary_semantics。原始报告未改写。
未来若要测清漏记量，需要分裂/分配来源证据；不能直接提高保护期、
扩大预取量或伪造更高复用率。

## 当前负载的原始前缀共享

V2857使用显式root invocation元数据定位36个root首请求，核对summary、
原生请求事件及仓库上下文哈希：

- 36 roots来自9个项目，每项目4项任务使用同一仓库文本哈希。
- 每个项目恰有3个root首请求命中超过100000个HBM输入token，共27/36。
- 首请求输入P50为133342 token，HBM命中P50为122627.5 token；
  逐请求命中比例P50约97.94%。
- 36份仓库文本的逻辑FULL量约97.55GB；按9个不同文本哈希去重后的
  容量代理约24.39GB，设备FULL池物理容量约36.82GB。

去重字节仅为逻辑容量估算，不是全程独立HBM分配清单，未包含私有历史
增长、工作状态、prompt包装及分裂/回收。它不能证明全程容量足够或
每个JOIN小恢复的成因。但它说明，36份100K上下文不是36份独立长前缀，
不能由agent总上下文大小推定每次JOIN都需要恢复GiB级FULL。

当前消融继续保持同一任务集。后续若研究更大恢复压力，应单独控制
独立项目/前缀的数量并测量真实缺失量，同时保留共享负载；不禁用原生
前缀共享、不填充无用文本，也不把改任务后的结果与当前native直接比较。
