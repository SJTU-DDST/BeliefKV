# V108 到 V123 的吞吐与短 Prefill 回撤核查

日期：2026-10-22，北京时间。本文区分已修改的主线默认值、冻结实验、
描述性几何对照和仍未达到的性能验收。所有历史失败与排除保留。

## 已执行的修改

按用户要求，runtime、内部对照环境、直接 launcher 和 fresh campaign
均将普通 `execution-frontier restore` 默认设为关闭。显式 `1` 仅保留
用于受控消融；关闭后不回退到工具预测预取。确定性 JOIN/EOS、增量备份、
工具等待卸载和原生准入后的按层需求恢复继续保留。

JCT 改为完整 workflow 的全程完成时间，保留普通工作长尾。
fresh/internal/frontier 三个后续入口取消默认 active-workflow 截尾。
比较器将全程 JCT 标为 primary；显式请求的旧截尾报告仅为 diagnostic，
其 `primary=false`。极少数异常工具长尾如需排除，必须提供任务身份、
实际工具耗时证据及相同任务集合的双口径，本轮没有据此排除任务。
guard、未完成和质量资格仍单列，不通过删掉困难样本声称获益。

## V108 的 600 token/s 确实存在，但不是固定工作量回放

V108 的应用提交为 `aefa20340b13`，使用 V103 冻结引擎；
V122 应用为 `35aa180e0dab`，V123 为 `a75d22db26df`。
V122/V123 仍使用同一已资格引擎树。

重要变化包括：

- `ed06f53` 前后固定服务端 seed；实际 V108 `server_info.json` 为
  `488387661`，V122/V123 为 `21`。客户端 seed21 不代表服务端 seed 相同。
- `4d30941`、`5666b52` 等将 Full 的排序与简单 JOIN 骨架对齐，改变
  resident-first、恢复保护和不同 continuation 的先后。
- `07bffff` 引入普通执行前沿恢复、execution 工具恢复模式和依赖传输档位；
  后续 `7e8a315`、`200728f` 又调整普通前沿的检查与重试。
  V123 删除的是普通前沿额外规划和提交，保留必要状态先行与 EOS。

不能将这些变化整体视为严格的单提交回归实验，也不能仅凭输出 token/s
认定模型 kernel 变慢。V2752、V2753 使用同一 600--1200s 窗口核对：
在 36 个相同上下文、连续 batch8、明确 graph 标志的共同桶中，
同权重 worker 均值为 V108 11.857ms、V122 Full 11.788ms。
V108 对 V123 的另一组 36 个共同桶为 11.666/11.654ms。
这些是 worker 区间，不是纯 kernel，但没有发现稳定满批 decode 的回撤。

V2760/V2763 将同一固定诊断窗口扩展为 600--1800s：

| 指标 | V108 | V122 Full | V122 JOIN-only | V123 无普通前沿 |
|---|---:|---:|---:|---:|
| decode token/s | 607.83 | 496.52 | 539.55 | 543.83 |
| decode 请求平均已缓存上下文 | 83130 | 125398 | 109193 | 115927 |
| decode 时间加权 batch | 7.876 | 7.859 | 7.860 | 7.902 |

关闭普通前沿后，忙时 decode 比 V122 Full 高约 9.53%。

都可能改变这一分布，尚未用固定输入/输出重放区分各自贡献，不将其
全部归到某个排序提交。保留固定 seed21，不通过改回随机 seed 追旧数字。

## 短 Prefill 的新增控制工作与删除效果

原来的 1.31--1.84 倍使用 512-token 输入桶及 2048-token 前缀桶。
这条观测不能直接当 kernel 加速比，也不能因为统计较粗就忽略实际开销。

新增离线细分支持 16-token 输入桶、相同前缀桶及明确 graph 标志；
同时分别输出全部 prefill 与单请求、实际新增输入 <512 的短 prefill。
每个共同桶对两侧用相同的 `min(left_count,right_count)` 权重；
支持度 1/2/4/8/16/32 全部保留，未知 graph 不计入平衡比较。

V2763 的 600--1800s 短单请求人口如下：

| 配对 | 共同桶 / 权重 | 左 / 右 worker 均值 | 左/右 |
|---|---:|---:|---:|
| V122 Full / JOIN-only | 289 / 372 | 15.563 / 10.585ms | 1.470 |
| V122 Full / V123 | 259 / 368 | 14.863 / 10.039ms | 1.481 |
| JOIN-only / V123 | 286 / 433 | 11.236 / 11.591ms | 0.969 |
| V108 / V123 | 300 / 450 | 10.265 / 10.088ms | 1.018 |

单桶仍稀疏，不能将这些比值当严格因果估计；最少 2/4 个 batch 的
子集也保留，最少 16/32 的共同短桶为空。V123 对 JOIN-only 的剩余
差异没有稳定单向退化。混合 prefill 的原始均值仍更高，继续保留，
不能用平衡后的较好子集宣称整个 prefill 路径已相同。

V2762 对原 600--1200s 封存窗口的短 prefill 阶段样本核对：

| CPU 阶段均值 | V108，47 个 | V122 Full，36 个 | JOIN-only，47 个 | V123，34 个 |
|---|---:|---:|---:|---:|
| selection | 10.308ms | 15.364ms | 14.635ms | 10.499ms |
| run_batch | 39.579ms | 52.542ms | 45.310ms | 35.323ms |
| post-launch physical | 0.828ms | 4.473ms | 0.008ms | 0.571ms |
| result processing | 6.421ms | 9.191ms | 8.444ms | 11.763ms |

post-launch physical 的已测 CPU 工作下降约 87%，与删除普通前沿相符。
样本几何并非完全相同，不能把各阶段均值差或 GPU span 相加后从 JCT
扣除，也不能用这张表声称每个阶段都改善。

具体被删除的工作是：在 PrefillAdder 最终容量、输入和 chunk 承诺之前，
额外进行队列前沿规划、长状态恢复检查、页分配与物理提交。该计划可能
随后失效，V122 已有 27.34GB 普通前沿 FULL 在首次服务前失去观察驻留。
V123 普通请求交由原生准入后的需求恢复，避免这条额外路径。
这是目前有源码、CPU 阶段和 GPU 消融证据共同支持的主要回撤来源；
其余排序/轨迹与混合输入分布仍未完成单独因果分解。
