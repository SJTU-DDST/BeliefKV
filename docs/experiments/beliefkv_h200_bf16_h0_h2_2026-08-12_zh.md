# BeliefKV H200 BF16 H0-H2 实施报告

日期：2026-08-12

状态：H0-H2 已完成；按当前任务边界停止，不启动 H3 workflow pilot。

## 1. 冻结环境

- GPU：NVIDIA H200 NVL，141 GiB，UUID GPU-a50d9b5b-d146-f031-d960-9a309904714e。
- 模型：Qwen3-Coder-30B-A3B-Instruct，BF16 权重，BF16 KV，TP=1。
- 模型目录：/srv/ai/models/Qwen/Qwen3-Coder-30B-A3B-Instruct。
- 上下文上限：262,144 token；本轮已完成 192K 请求 smoke。
- SGLang：0.5.2rc1，源码 commit 18f91eb639084825717c0e3c3c7273492812ab71。
- attention backend：decode 使用 FlashInfer，prefill 使用 FA3。
- HiCache：96 GiB pinned Host、kernel backend、layer-first、write-back。
- 完整环境和模型文件摘要见 configs/p6/h200_bf16_v1/environment_manifest.json。

代码已增加服务端身份和容量契约。校准入口会在提交 workload 前检查 model path、served name、权重 dtype、实际 KV dtype、context、KV pool 和 Host pool，防止旧 FP8/RTX artifact 混入 H200 数据。

## 2. KV Pool 决策

最终冻结：

| 参数 | 值 |
|---|---:|
| max_total_tokens | 871,700 |
| KV bytes/token | 98,304 |
| GPU KV pool | 85,691,596,800 bytes（79.81 GiB） |
| Host KV pool | 96 GiB |
| page_size | 1 |
| chunked_prefill_size | 4,096 |
| max_running_requests | 16 |
| cuda_graph_max_bs | 16 |
| 初始化后稳定空闲 HBM | 1,142 MiB |
| HBM safety margin | 1 GiB |

决策过程：

1. SGLang 自动定容得到 885,492 token，但初始化后只剩约 0.17 GiB，不满足安全边界。
2. 874,569 token 时外部空闲 HBM 仍只有约 758 MiB。
3. 871,700 token 时初始化后稳定空闲 1,142 MiB，通过 1 GiB safety gate。
4. 192K smoke 的 prompt 为 196,035 token，额外生成 256 token，39.49 秒完成且无 OOM。
5. 64 GiB Host pool 被当前 SGLang HiCache 协议拒绝，因为 Host tier 必须严格大于 device KV pool；因此冻结为 96 GiB。

该 pool 是硬件配置，不再为制造 pressure 或改善 A/B 结果调整。后续只调整 workflow 到达率和并发度。

产物：

- artifacts/p6/h200_bf16_v1/gpu_service_evaluation.json

校准结论：

- holdout 相对误差 P50：10.88%；

因此 artifact 已完成重采并可用于开发诊断，但 online_eligible=false。当前不能将其接入预测性 JointPlan。主要残余问题是 prefill 条件分布发生漂移，不能通过放宽门槛掩盖。

## 4. D2H/H2D Transfer Artifact

矩阵覆盖 64K、128K、192K context，每个 size 重复 3 次。9/9 restore gate 均通过以下 14 项检查，包括命令/ACK 守恒、durable obligation、非零 D2H/H2D、restore 后真实 decode service 和 shutdown 前无遗留事务。

有效训练样本为 18 条 completed transfer。另有 9 条第一次 H2D restore 被物理层标记为 rejected，随后同一轮第二次 H2D 成功；这些记录保留为 restore/admission 诊断，但不进入链路服务曲线。

| 方向 | 实际 bytes | extents | P50 | P95 | P10 有效带宽 |
|---|---:|---:|---:|---:|---:|
| D2H | 6.44 GB | 16 | 337.81 ms | 343.98 ms | 18.75 GB/s |
| D2H | 12.88 GB | 32 | 707.40 ms | 739.92 ms | 17.50 GB/s |
| D2H | 19.32 GB | 48 | 1,049.59 ms | 1,093.45 ms | 17.76 GB/s |
| H2D | 6.44 GB | 16 | 298.33 ms | 300.17 ms | 21.46 GB/s |
| H2D | 12.88 GB | 32 | 615.90 ms | 622.87 ms | 20.70 GB/s |
| H2D | 19.32 GB | 48 | 965.25 ms | 990.50 ms | 19.57 GB/s |

采样条件经 runtime audit 交叉验证：

- 每条 D2H 均与真实 decode service 重叠；
- 每条 H2D 均与 replacement prefill 重叠；
- 目标迁移期间没有其他 D2H/H2D 污染；
- Host copy 均为 pinned；
- 实际 extent 为约 384 MiB 的 16/32/48 个正常 HiCache bundle，不人为制造极端碎片。

产物：

- artifacts/p6/h200_bf16_v1/transfer_service_qwen3coder30b_bf16_h200_v1.json
- experiments/calibration/h200_bf16_v1/h2_transfer/transfer_calibration_summary.json
- experiments/calibration/h200_bf16_v1/h2_transfer/transfer_telemetry.completed.jsonl

artifact schema-v2 绑定 GPU UUID、driver、模型/dtype、SGLang commit、pool、page size、pinned Host 和 NUMA。18 条样本可在 runtime min_samples=8 下 warm-start，6/6 calibrated bucket 均为 shape_supported=true。

当前明确支持“PCIe link 无其他传输 + D2H/decode contention”和“PCIe link 无其他传输 + H2D/prefill contention”。纯 GPU compute-idle 和并发 PCIe transfer 未采集，必须走 OOD/static fallback。现有 runtime 没有在无请求运行时主动迁移已缓存 context 的外部 calibration hook，本轮没有为补标签临时引入新的调度接口。

## 5. 代码修改

- 新增统一 server identity/capacity contract。
- Qwen/SGLang launcher 默认切换到 30B BF16，并显式配置 dtype、KV dtype 和 page size。
- queue service、restore micro-gate 和 P6 collector 在提交请求前执行硬身份校验。
- 新增 H200 环境冻结脚本和可重复的 9-run transfer matrix。
- 新增 transfer 汇总器，校验 correctness、phase overlap、污染、样本数和物理 shape。
- transfer exporter 支持 schema-v2 外部环境元数据。
- 冻结入口为 configs/p6/h200_bf16_v1/frozen_runtime_profile.json。

## 6. 停止边界

本轮没有启动 12-16 workflow pilot，也没有训练或接入预测模型。当前 beliefkv 环境缺少 Deep Agents runtime；按照任务要求，不安装替代 runtime，不以简化 workload 继续实验。后续迁移并验证 runtime 后，从 H3 pilot 开始。
