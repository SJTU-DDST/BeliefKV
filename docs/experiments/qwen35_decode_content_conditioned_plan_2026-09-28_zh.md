# Child RETURN 的流式内容与长度联合预测：开发结论和下一阶段门禁

## 当前模型实际做了什么

这不是语义大模型、hidden-state probe，也不读取尚未生成的 token。
`scripts/pilot_child_stream_content.py` 对每个 child 的实际流式回调，
在首个正文 chunk、累计正文跨越 32、64、128 字符后按 128 字符
里程碑取最新 128 字符（大 chunk 可以越过多个里程碑）；转小写后
抽取词、符号和相邻词对，统计词频并归一化。词表必须在至少两个
**不同训练 workflow** 中出现该词；训练只用训练项目。这个
bag-of-words 代理只能识别类似“仍需检查”与“答案收束”的词形，
不理解因果、整个上下文、代码围栏闭合或跨语言同义表达。

长度特征是截至快照累计正文字符数的 `log(1+chars)`，**不是**
事后已知的最终长度，也不是输出 token 数。训练目标分别是
“这轮自然无工具 RETURN，而非继续工具调用”和“在 2 秒内自然
RETURN”；后一目标把最终报告的过早片段也标为负例。模型对
正负类按 workflow 均衡求平均向量，差向量与当下快照做内积，
用训练项目的请求级错误候选最大分数 P95 选触发阈值。
每个请求只计首次触发。此前直接拼接词形与长度会由长度主导。

新增的**长度条件化内容**消融用训练集拟合每个词形维度关于
常数项和长度的加权线性投影，减去该投影后得到内容残差；
将长度分数和残差分数分别除以训练集各自的标准差，再按
`长度分数 + 0.5 × 内容残差分数` 相加。`0.5` 是固定的
开发试验权重，不是由独立测试选择的最优超参数；投影、均值、
方差和阈值均不得用留出项目拟合。这让“长度之外有没有内容
信息”成为可检验的增量问题，仍不构成高级语义理解。

## 当天只读开发消融

保留原来的两份 `content_holdout_*.json`，新结果另存为
`content_workflow_balanced_holdout_{astropy,sphinx_dev}.json`。
下表是 child 自然 RETURN 的**首次触发**处于其前 0.5–2 秒的
个数，未做新 GPU 运行或物理动作：

| 项目 | 长度 | 直接拼接内容+长度 | 长度条件化内容 |
| --- | ---: | ---: | ---: |
| Astropy | 3/17 | 2/17 | 1/17 |
| Sphinx | 0/14 | 0/14 | 4/14 |

条件化模型在 Astropy 的 22 个有正文工具轮次误报 1 次，
Sphinx 的 52 个误报 0 次；在全部工具轮次口径分别为

因此目前不能宣称该联合模型有跨项目独立增益，更不能将它
用于 H2D 控制。两项目和全部本次 trace 已多次用于开发判断，
此后的消融结果均属于开发集，不是新的密封测试。

## 分阶段目标和停止条件

1. **可识别性与数据契约**：仅使用在线已送达的正文及其变化，
   以 `request_id`、child/context epoch 绑定自然 RETURN，
   区分同轮 tool_calls、纯文本后继续工具、异常和删失。
   扩大项目来源并预先冻结训练/校准/未见项目清单；至少收集
   100 个自然 RETURN、30 个 JOIN-last 和 100 个有足够
   正文的工具负例，分布在多个 workflow、至少 4 个项目。
   同时报告全部工具轮次及可评分轮次；若正文可见率仍很低，
   在**训练侧预注册**更早的 32/64 字符快照，同时评估由此
   引入的误报。不能拿 1318 个未达 128 字符门槛的旧负例
   给内容模型虚增精度。
2. **无工具终态 + 临近窗口**：把
   `P(本轮无工具地 RETURN | 已见正文、进度、上下文)`
   与 `P(将在可传输窗口内 RETURN | 本轮会 RETURN)`
   分开拟合与报告。只用训练项目选内容表示、融合权重和
   请求级首次触发门槛，再用独立项目校准。留出项目必须
   分别报告 0.5–2 秒窗口召回、工具误报、最终报告过早
   触发、JOIN-last 覆盖，按 workflow 聚类报告不确定区间。
   **候选晋级条件**：独立项目上较长度基线的窗口召回
   至少提高 10 个百分点且各项目不退化；有正文工具轮次
   误报率不超过 5%，最终报告过早触发率不超过 10%，
   workflow 聚类差值区间支持正增益。任一条件不满足则
   保持只读，不能由当前 Sphinx 单侧增益晋级。
3. **时钟和物理条件**：训练的目标是 child 自然 RETURN，
   不是受 HBM 调度影响的 parent 首次服务。将剩余生成
   服务量/可观测 decode 速率与无服务等待、工具等待分解；
   线上只用截至快照已知的服务进度，不用未来等待标签
   作为特征。只有当预期可用窗口覆盖实测 control +
   H2D 完成 P95 且目标 Host 副本、HBM 空间、身份及消费
   机会均成立时，调度器才决定是否预取。允许放弃动作；
   成功必须以物理 ACK、首次 GPU 服务复用、节省阻塞和
   其他 workflow 干扰的配对结果判断。
4. **信号升级**：先比较当前词形、结构状态/局部语义、
   长度和阶段变化，不因单侧 pilot 结果直接接入 runtime。
   再对同一请求的 EOS 候选概率/熵随时间变化做有条件、
   只读对照；它预测本轮生成结束，不能单独推出 child
   自然 RETURN。若内容和分布仍不足，并能证明额外
   服务开销低且不会改变解码行为，才评估轻量 hidden-state
   probe。每一步都要相对固定长度基线证明独立增益，
   否则停止增加在线复杂度。

这些门槛是下一批实验的**预定目标**，不是已取得的指标。
工具返回时间另由工具运行进度与等待时钟预测；child 解码
内容不应被拿来假装能预测任意外部工具完成。

## 冻结数据边界与下一次执行

本次内容路线已在 Astropy/Sphinx 上反复观察和调整；这两个项目
从此只作为开发诊断，**不再作为独立留出项目**。使用现有冻结
128-root 工作负载清单
`experiments/raw/qwen35_native_reactive_overlapped_128root_70_30_20260924_v3/qwen35-native-reactive-overlapped-128root-train-r0/runtime_workload_manifest.json`
（SHA256 `77e5ef62c09cccbc3f4d1d2d6cfd00967ad37f46477266dec308bf2379bf35d8`）
时，在读取新内容结果之前冻结项目划分：

| 用途 | 项目（任务数） | 使用边界 |
| --- | --- | --- |
| 开发/拟合 | django (67)、pytest-dev (19) | 允许选表示、融合系数和窗口 |
| 独立校准 | pydata (21) | 只拟合首次触发门槛，不反向调表示 |
| 密封评价 | pylint-dev (10)、psf (8) | 只读一次最终性能，不调阈值 |
| 暂不计入 | mwaskom (2)、pallets (1) | 数量不足，不拿来充足项目基数 |

同项目的全部 workflow 只属于一个划分，清单本身保留原始顺序和
image/repo 身份；以前在其他任务用过这些项目，不意味着内容路线
在未见项目测试中得到完全独立的论文证据。诊断采集先只选开发项目
`WORKLOAD_ALLOWED_PROJECTS=django,pytest-dev`；程序不再因
`STREAM_CONTENT_SHADOW=1` 隐式换成 Astropy/Sphinx。
初次运行仍是**开发可行性批次**，程序自动输出的双向
`content_*_dev_*.json` 仅供开发，不能叫作正式留出指标。
校准/密封项目也必须使用事先冻结的清单和特征及权重版本；
当前评分脚本可指定 `--train-projects django,pytest-dev
--calibration-projects pydata --heldout-project pylint-dev`（也可单独
将 psf 作为 heldout），只用训练项目构造词表/表示/方向和标准化，
校准项目决定请求级首次错误最大分数的 P95 阈值，密封项目
只评分。未指定校准项目仍是训练内选阈值的开发诊断；
当前冻结清单不足以自动满足样本量和 project-disjoint 置信区间
门槛，不能只凭 CLI 标记就宣称通过。

新增 `--min-snapshot-chars=32|64|128`：每档独立统计自然
RETURN、JOIN-last、有可观测正文的工具负例与全部工具轮次；
确认 32/64 是否实际提高覆盖而不使纯文本随后调用工具的误报飙升。
采集包含原文尾部，仅用于本机只读研究。扩大快照密度仍由有界
异步队列保证不阻塞解码；任何 writer 丢失、身份不匹配或删失
不能默默改算负例。

**目标不等同于结论**：先满足上节的 100 个自然 RETURN、
30 个 JOIN-last 和 100 个有正文工具负例，再在密封项目上
用请求级**首次**触发和按 workflow 聚类的区间检验相对长度
基线的独立增益。若仅凭当前清单无法达到 JOIN-last 或工具
负例数量，应在未看密封结果前追加来自其他项目的冻结任务，
不得靠重复快照膨胀样本数。0.5–2 秒只是一个诊断窗，最终
可行动提前量必须按实际目标 KV 字节、PCIe 并发和
control + H2D 完成分布设置；结束太早会占用 HBM，太晚会
退化为响应式 H2D。即便离线指标达标，仍需物理容量/ACK/
首次复用和配对吞吐证据，才能接入 predictive 行动。

冻结清单中的 Django/Pytest 开发项目各有 3/9 个任务被本批选中；
输出保留在
`experiments/raw/qwen35_child_stream_content_dev_12root_20260928_v3/`。

7/12 workflow completed，余下 5 个因缺少要求的终态标记为

实验仍在后台运行。可匹配的自然 child RETURN 为 31 个，
JOIN-last 仅 3 个，工具继续轮次 1543 个（其中 9 个先有正文
再调用工具）。**不能**用这个开发批次推断独立项目泛化。

| 最短正文 | 有正文可评分工具轮次 / 全部 | 长度 0.5–2 s 命中（Django/Pytest） | 条件化内容+长度命中 | 联合模型工具误触发（两项目合计） | JOIN-last 窗命中 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 32 字符 | 263 / 1543 | 1/10；0/21 | 0/10；3/21 | 1 | 0/3 |
| 64 字符 | 238 / 1543 | 1/10；0/21 | 0/10；3/21 | 0 | 0/3 |
| 128 字符 | 67 / 1543 | 2/10；0/21 | 3/10；0/21 | 0 | 0/3 |

缩短到 32 字符提高了工具负例的**可见覆盖**，但多数工具
轮次仍没有 32 字符正文；不可用 `1/1543` 掩饰真实
的 `1/263` 有内容误触发口径。不同里程碑仅在相同
开发项目上做诊断，不能因某一侧 3 次命中选择档位并
把另一侧当作独立验证。当前词形代理加长度尚无稳定正增益，
先保持 shadow-only。下一阶段只在训练项目预注册局部
进展/终态结构特征（如仍在列待查步骤、答案收束、围栏
闭合）与短窗解码速率，维持相同长度基线和项目隔离；
若独立校准/留出仍不能跨项目达到窗口与误触发门槛，
停止为这一路线增加线上负担，改以真正的 child 完成
通知或确定性 JOIN 阶段为触发信号。切勿对本批 5 个
incomplete 工作流作端到端成功宣称。
