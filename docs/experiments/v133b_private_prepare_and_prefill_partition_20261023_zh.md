## Prefill 差额的口径

V3101 的累计 prefill worker 区间为 native 374.797s、Full 391.492s，
相差 16.694s，即 4.454%。重新读取该报告封存且 hash 一致的
runtime audit，实际 prefill 增量为 9459122 与 9476744 token，
相差 0.1863%。

这两个差额本身不能证明 prefill 内核或完整执行路径慢了 4.454%。
原生 telemetry 的 `on_completed` 使用：

```text
service_start = max(this_forward_entry, previous_observed_completion)
worker_interval = this_observed_completion - service_start
```

因此，相邻批次重叠改变时，计入 prefill 的 worker 区间也会改变。
V3110 在相同封存前缀上逐行校验边界，再按同请求、输入前缀、
输出进度、实际 extend、batch 和 graph 配对，并排除重复几何。

| 长单请求样本 | 对数 | worker 差额累计 | forward 入口至完成差额累计 | 被裁剪时间差额累计 |
| --- | ---: | ---: | ---: | ---: |
| 全部配对 | 3480 | +13.162s | +1.315s | -11.847s |
| 附加邻批次类型匹配 | 2943 | +10.475s | +0.552s | -9.923s |
| 两侧均未被阶段探针采样 | 3047 | +11.668s | +0.872s | -10.797s |
| 未采样，附加邻批次类型匹配 | 2578 | +9.092s | +0.104s | -8.989s |

每行都满足：

```text
worker 差额 = forward 入口至完成差额 - 被裁剪时间差额
```

最后一组的 native/Full 均值分别为：

- worker：87.384/90.911ms，Full 高 4.04%。
- forward 入口至观察完成：150.591/150.631ms，仅差约 0.040ms。
- 入口至计入 worker 的起点：63.207/59.720ms，相差约 -3.487ms。

V3102 的 27 对同时具有完整阶段探针和邻批次匹配的长 prefill，
CUDA-stream span 均值为 147.005/146.678ms。该组数量小、实际输入
偏向较长 chunk，不能外推到全部 prefill；Full post-launch 控制
线程 CPU 均值仍有约 1.345ms，可继续优化。

这些结果修正了“累计增加 16.69 秒即可视为实际额外 prefill 成本”
的判断。配对子集的大部分差额来自区间归属变化，但这也不证明所有
prefill 内核都没有回退。未裁剪区间彼此重叠，包含 CPU dispatch、
依赖和结果处理；邻批次匹配没有固定其全部上下文与 kernel 历史。
两种区间都不能相加为纯 GPU 时间，或直接从 JCT 扣除。

V3109 保留第一次按探针覆盖和实际工作量分组的结果；
V3110 增加区间分解。主 JCT 始终保留全部正常长尾。

## 空备份路径

原先 main 的快路径只在整个原生未备份 FULL 索引为空时启用。
其他 agent 产生脏页，即使目标 parent 本轮没有可以备份的私有页，
仍会触发详细 `UnifiedNodeSummary` 闭包与规划。

本次使用既有 resident-parent 策略的实际动作范围：

1. 目标 FULL 叶在原生脏索引中时直接保留普通规划。脏索引只用于
   放弃可选快路径，不能授权传输、释放或推断副本已经就绪。
2. 其他情况重新核对当前 anchors、祖先关系、Host 副本和在途传输，
   判断已经证明可回收的私有 device 叶是否仍需备份。
3. 这些私有叶已经备份时，跳过本轮不可能产生动作的详细规划。
   未备份祖先仍保留；已经备份的祖先和必要 Mamba 节点继续按原顺序
   登记为压力候选，原生消费者实时核对锁、引用、身份和 DMA。
4. 私有叶缺副本、anchor 被替换、在途传输、独立 Mamba 分支、
   旧引擎或无法确定的路径继续使用原有检查。

没有新增周期扫描、长期证明缓存、容量预留或不可撤销保护。
没有改变备份对象、调度优先级、H2D 档位及正确性依赖。

第一版仅解除全局空索引限制，导致缺失副本时重复遍历：
V3103 记录了 11%--23% 的部分场景回退，没有采用该实现作为最终
候选。V3105 保留后续中间版本；V3107 绑定最终实现。
