## 为什么继续检查空计划

V3085 的较早前缀包含 56 个短 prefill 阶段样本，post-launch 线程 CPU
均值约 0.490ms。V3087 使用相同的封存字节前缀关联实际控制事件，
时钟对应的不确定范围约 0.00493ms：

- 4 个样本包含已记录的后台备份动作，线程 CPU 均值约 0.787ms。
- 52 个样本没有记录到迁移动作，均值仍约 0.467ms。

没有动作记录不代表没有工作；原生队列检查、失败探测和候选维护可能
没有独立记录。这些分组不能用于直接归因，更不能从 JCT 扣除。

同一前缀中，1899 批后台 FULL 备份累计约 92.93GB，每批均值约
48.94MB，中位数为 25MiB，最大为 375MiB。没有触及 512MiB 批次上限，
因此不能把该阶段的问题解释为批次上限太小。

CPU 复现进一步确认，完全备份的等待 parent 仍会构造整条
`UnifiedNodeSummary` 闭包，再得到没有 FULL 需要备份的结果。

## 实现与边界

只在已支持 resident-parent prepare、且原生增量脏节点索引为空时，
对备份选择启用轻量的完整副本检查。脏索引只是探测提示，检查仍逐段
读取实际 FULL 副本，并核对 session anchor、节点代际、祖先关系、
在途传输以及 Mamba anchor 是否包含在 FULL 路径中。

确认整条路径的 FULL 都已备份后，不再构造详细闭包，也不再生成
空备份计划。轻量检查保留与原路径相同的回收候选及顺序；生成尾部
仍须通过原有的私有叶节点证明。原生回收继续实时验证锁、引用、
Host 副本和 DMA 状态。

缺少、部分或不匹配的 Host 副本、在途传输、独立 Mamba 分支，
以及任何无法确认的情况均保留原有完整检查。没有增加跨轮的闭包
缓存、定时器或长期驻留保护。
