# 短工具续接与 V124 Full 验证

日期：2026-10-22，北京时间。

本轮按用户要求修复短工具返回后反复丢失队列地位的问题，随后仅重跑
Full。沿用普通 execution-frontier restore 关闭、36 roots、batch/running8、
seed21、256K 上下文、180s 工具上限及原任务集。完整 workflow JCT 为主，
保留普通工作长尾，guard 和生成工作量另列。

## 机制与已有调度的关系

借鉴 InferCept 的原始到达时间继承与 AgentInfer 的有界执行连续性，
实现的是本系统底座上的适配，不将这两点单独声称为新颖贡献。
既有研究核查与原始来源见
[短工具与 JOIN 研究记录](../research/tool_continuity_and_join_budget_20261022_zh.md)。

每段从一次实际普通准入开始，记录该请求真实进入服务端队列的时间。
同一 invocation 的原生请求确认完成后，整轮工具均结束、工具整轮不超过
1s，且 GPU 完成到后继实际排队的总往返不超过 1s 时，后继可以继承
本段初始到达时间。必须匹配 context、下一 epoch、session/generation，
不跨 sibling、重试、压缩或委派屏障继承。

每段最多四个模型请求。一次真实普通准入为 root workflow 提供至多三个
续接优待额度；child 共用同一账户，创建 child 本身不增加额度。
发生实际排序提升且成功准入才扣额度。Chunked prefill、NO_TOKEN、
重复完成回调和原生回退重排不重复领取。该计量是请求准入额度，
不是 GPU 服务时间，也不声称实现了请求内部的抢占式时间片。

真实 `_visible_since` 不修改，用于等待时延和 10s 老化。续接只在普通
候选中按继承年龄前移，不越过比继承年龄更早到达的普通请求，
或本轮已选中的 JOIN parent/最后 child。越过真实老化请求额外要求
初始可使用一次有界让步；实际续接提升后归零，再次越过老化请求前
需有四次真实普通准入。反复chunk或NO_TOKEN
不增加该全局额度，避免高负载老化队列彻底禁用续接，也避免持续插队。
JOIN 仍使用独立的既有四次普通准入
之间的有界优先策略。批次候选完整保留，原生 allocator/PrefillAdder
继续决定能否准入。容量不足不为续接等待，其他可执行请求继续填充。

`BELIEFKV_ENABLE_TOOL_CONTINUITY=0|1` 为独立消融开关。
仅在 `join_priority` 调度下生效；native/kv-only 与其他排序 profile
不接入这条排序偏好。未来 Full、JOIN-only、scheduler-only 可以在相同
调度开关上对比 KV 机制，历史 JOIN-only 不追写成已启用该策略。

## 控制工作与验证

状态只在原有工具事件、原生请求完成与实际准入边界更新。
排序复用本轮已经解析的候选 key 和可执行性检查；没有前缀重匹配、
容量规划、新 DMA、KV 锁、GPU 槽预留或逐 token 观测。取消、终态、
上下文压缩、JOIN/委派屏障及因果镜像丢弃会清除相关地位。

新增 CPU 用例覆盖并行工具整轮结束、长工具/客户端延迟回退、未知工具
身份/时钟、跨 session/epoch 拒绝、额度耗尽、同 root sibling 共享、
chunk/retraction 去重、真实原生完成接线、JOIN/老化优先与关闭消融。
完整保留上一轮 CPU 资格人口，失败的中间报告保留。

`benchmark_tool_continuity_cpu.py` 对 8/36/128 队列测量完整队列检查、
规划和最终 live selector；交替201次、正常GC、保留全部样本。
空机会必须保持相同顺序，正机会必须改变目标位置并保留全部候选。
该 CPU fixture 不包含真实 allocator、DMA 或模型执行，不外推 JCT 收益。

最终 CPU 资格为 V2780/V2781：3984项通过、2个subtest通过，保留此前
全部3928项及中间3982项；无skip，同一个既有Docker沙箱用例显式deselect。
V2775/V2776为3977项的首轮资格，V2778为3982项的历史默认核验资格。
V2770/V2771/V2773 的中间失败报告继续保留，分别涉及新fixture配置、
启动JSON字段预期及新开关在不同profile下的派生字段预期。

V2782 的完整规划/选择 P50：无机会时8/36/128队列差值为
-0.58/-2.00/-6.38us；正机会时为+15.64/+30.57/+75.59us。
这些小差值包含CPU噪声，保留原始201个样本、P99和最大值，
不据空路径的负差值宣称优化收益。V2774/V2777为较早源码的先行测量，
不替代V2782的最终源码绑定。

## 实验与验收

新 Full 使用新冻结 main、现有已资格引擎以及显式续接开关。
启动登记与运行时状态均记录实际开关和界限。新增启动模式
`run_frontier_ablation_after_campaign.py --tool-continuity` 只启动一组 Full，
不追加用户未要求的三组重跑。

首次 V124 登记在任何GPU启动前被历史输入校验拦住：V122当时默认
frontier=1，但旧launch JSON没有显式字段，主线新默认为0。
现已为历史参考单独传入其受核验的旧默认；显式launch字段总是优先，
新候选仍必须观测到frontier=0。原失败登记与冻结checkout保留，
重试使用新的V124b登记，不重写失败状态或历史trace。

复用 V122 Full/JOIN-only/native 为历史描述性参考，不能据不同轨迹直接
宣称 KV 独立收益。V123 无普通前沿结果另外保留，其35/36自然资格和
原始退出码不修改。V124 是否改善工具后继排队、完整平均JCT及吞吐，
以真实新 trace 验收；提前排序不自动证明净收益或公平性改进。
