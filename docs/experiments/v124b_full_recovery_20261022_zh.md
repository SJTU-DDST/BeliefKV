最新用户指示采用 V108 策略、JOIN只用EOS，见

V125继续完成冻结消融，收齐后按工作量再决定重跑对象。下面的接续工具

## 已有证据

| 指标 | V108 | V123 | V124b | V122 native |
| --- | ---: | ---: | ---: | ---: |
| 完整 36 项平均 JCT，秒 | 2105.47 | 1788.69 | 2262.19 | 2223.38 |
| 输出 token | 2128479 | 1566286 | 1820060 | 1836441 |
| LLM 请求 | 8459 | 6353 | 8163 | 8005 |
| 600--1800 秒 decode token/s | 607.83 | 543.83 | 579.95 | 516.94 |
| 同窗口 decode 请求平均上下文 | 83130 | 115927 | 92672 | 125770 |

V108 的对应历史 native 为 V103，完整平均 JCT 2370.07 秒，输出 2024180
token。V108 平均 JCT 低约 11.16%，但服务端实际 seed 为 488387661，
不等同于后来两端固定的 21。这不是与 V124b 同配置、同轨迹的回放。

V124b 相对 V122 native 的完整平均 JCT 高 1.75%，全程输出吞吐为
521.63/512.29 token/s。Full 有 21 项更快、15 项更慢，仍不能说明平均获益。
共同 35 项无 guard 的平均 JCT 为 2240.55/2202.12 秒；普通长尾全部保留。
V124b 没有再次出现旧 Full/JOIN-only 1.31--1.84 倍的短 prefill 回撤。
同上下文、同 graph、满 decode batch 的历史分桶没有一致的 worker 退化，
所以不能将约 608 到 580 token/s 的变化直接解释为 kernel 或控制降速。

V123 到 V124b 的主要新增策略是短工具排队连续性。V124b 累计 5691 次继承
段内队列年龄，2520 次实际优先准入，1704 次达到四请求段预算后让步。
该规则按工具/客户端间隔和请求次数限制，却没有按实际模型服务量、恢复
成本或 workflow 剩余依赖限制。普通工具后继可继承很早的到达时间，
实际可能是一轮较长的生成，而不是一次廉价续接。这是一项有机制依据的
回撤嫌疑，不是已经完成因果验证的根因。

同期 V124b 比 V123 输出多约 16.2%、请求多约 28.5%、平均 JCT 多约 26.5%。
动态生成工作量是重要混杂因素，不能把全部差值都归给连续性，也不能用
JCT/token 直接证明策略好坏。原始 trace、guard 和负结果继续保留。

## 当前修复

runtime、内部对照环境和 shell launcher 统一默认关闭短工具连续性，
通过 `TOOL_CONTINUITY=1` 或原生环境开关仍可显式做消融。默认关闭后不
建立/维护该策略的段、工具事件和队列优先记录。简单 JOIN 优先、
JOIN/EOS 恢复、后台增量备份和原生 HiCache 依赖保持可用；普通 execution
frontier 继续关闭。排队 owner 后台备份和其他已验证的控制优化保留。

复用 subagent 的新 profile 不加入这轮回撤实验，旧 prompt、36 个任务、
256K、running/decode8、200GB Host 池、两端 seed21 保持一致。未来复用
profile 中，模型自主选择新建或回访已有 handle；新 invocation 只表示一次
真实唤醒，不触发自动回访。

## 实验接续

`run_full_regression_recovery.py` 在当前 V125 KV-only 完整收集、后处理结束后，
以稳定 PID/start_ticks 验证旧 supervisor，暂停并复核没有活动 driver/子进程，
只退休尚未开始的后续矩阵。原始退出码、已完成 arm 和文件保留。
冻结应用与引擎不热改。随后先运行修复版 Full。

完整 JCT 同时对照 V122 native/JOIN-only，完整输出吞吐和 600--1800 秒
decode 对照 native。共同自然完成集合另列，不能用排除 guard 制造获益；
不新增普通长尾删减。任一开发门槛未通过则自动验证 V108 策略配置：

| 配置 | 修复版 Full | V108 策略回退 |
| --- | --- | --- |
| 排序 | 简单 JOIN 优先 | workflow，含驻留/阶段信息 |
| 普通 frontier | 关闭 | 关闭 |
| 短工具连续性 | 关闭 | 关闭 |
| 工具恢复 | 原生需求恢复 | 工具期推测恢复 |
| JOIN 提前依据 | EOS | EOS，按最新指示不恢复 child 工作量预测 |
| 后台备份对象 | cold，含安全排队 owner | 所有安全缺失 FULL |
| 恢复范围 | dependency 档位 | complete |
| 额外驻留保护 | 关闭 | 开启，保留当前安全撤销实现 |

回退只改变策略/实验设置，不回滚代码库；固定 seed21、最新正确性修复、
CPU 降本和公共前端优化保留。因此它是 V108 策略配置验证，不是旧二进制
与随机轨迹的完全复现。开发门槛用于决定是否回退；任务正确性尚未独立
评分、动态工作量不同，门槛通过也不自动构成论文性能验收。
