## V133b 的 JCT 时间分解

`scripts/audit_causal_jct_paths.py` 使用已核验的同一源 DAG，
重放事件的 monotonic 时间、原生完成 receipt 和每次 `run_batch` 的
launch 记录。每个汇合点选择实际最晚完成的前驱，回溯到该 workflow
到达；并行 sibling 的时间不相加。各组全部 36 个 JCT 都重建为原始
测量值，保留所有正常长尾，不剔除慢 workflow。

审计要求原生 sample_id 连续、记录数与最终 writer 状态一致、全部
6907 请求有匹配身份和同 clock domain 的首次 launch。三组分别检查
351911、357292、347139 个服务记录。请求输入、输出和停止工作量相同；
原始文件的完整前缀摘要保存在报告中。

单位为每个 workflow 的平均秒数：

| 实际阻塞链组成 | native | Full，工具预取关闭 | JOIN-only |
| --- | ---: | ---: | ---: |
| 完整 JCT | 2339.66 | 2289.13 | 2340.24 |
| HTTP 提交至首次 `run_batch` | 1661.46 | 1621.26 | 1659.27 |
| 首次 `run_batch` 至原生完成 | 606.98 | 595.95 | 609.29 |
| 工具结束事件的等待 | 29.02 | 29.22 | 28.99 |
| LLM 提交事件前的客户端时间 | 35.38 | 35.60 | 35.60 |

约 71% 的 JCT 在提交至首次调度之间。这包括 HTTP、前端、排队、
恢复和准入，**不是 GPU 空闲时间，也不是 CPU 调度成本**。GPU 可以
在服务其他 workflow，不能把该值当成可消除的等待上界。
后续服务区间也包含 prefill、decode、交错执行与各种等待，不能称为
纯 GPU 计算时间。

三组实际路径分别包含 5565/5563/5561 个请求，其中工具后继
5286/5284/5282 个，JOIN 后继都为 75 个。这里只计各组实现出的
阻塞链；不同组可以选择不同的最晚 sibling，分量差异是描述性证据，
不能替代模块消融。

下一步据此聚焦：

- JOIN-only 已复现绝大部分 JOIN 后的排队改善；不能把同样的改善
  再归给 JOIN KV 预取。
- Full 相对 JOIN-only 的额外改善主要出现在普通工具后继。该 Full
  关闭了工具预取，所以这些差异不能归因于工具提前 H2D。
- 继续区分驻留、回收/备份减少的代价与调度次序变化；有界工具
  预取优先期需要同轨迹开启/关闭验证。短工具续接保持关闭。
- 长 prefill 的 worker 区间略长，但 V3110 的 launch-to-complete
  大样本总体接近，不能只凭 worker 区间把吞吐差距归给计算 kernel。

完整报告为 `v3143_v133b_causal_jct_paths_20261023.json`。

## V134c 部分源与中断

V134c 的模型和 graph 初始化成功，实际 FULL、Mamba、Host 容量与
参考 native census 完全一致。容量固定修复因此取得了 GPU 证据。

预约守护在 19:59 发出停止请求，采集器于 19:59:17 退出并释放已验证
的本项目进程；20:00 后守护未发现遗留本项目 GPU 进程。
旧采集器将该 HoldChanged 记录为 capture_failed，原始记录不改写。
独立报告明确标记行政中断；新采集器区分 capture_interrupted 和
真正运行失败，并将同样标志传入 cutoff 记录。

中断时的完整事件前缀包含 36 个到达、1908 次 LLM 提交、10 次 spawn、
8 次 JOIN_WAIT、5 次 JOIN_SATISFIED。只有 5 个 workflow 自然结束；
一个 parent 有多轮 JOIN，无嵌套 spawn，真实 resume 为 0。
这不能作为完整源、JCT 对照或选择性保留的收益证据。
未完成 workflow 的复用 episode 删失，不记为“不复用”负例。
详见 `v3144_v134c_reservation_cutoff_partial_20261023.json`。

调用入口审计发现：ReusableSubAgentMiddleware 在重建 task 工具时，
丢弃了调用方显式传入的 DYNAMIC_TASK_DESCRIPTION。可用类型列表和
agent_id 接口存在，但原本关于实质独立工作、并行、后续新证据、
写入范围和嵌套委派的详细工具说明丢失。

新实现保留框架已经格式化的自定义描述，再补充复用接口；缺省描述
继续使用适合持久会话的文本，不带框架默认的“每次无状态”声明。
私有状态配置重建工具时也保留同样说明。未改变 tool_choice、强制
轮数、固定 DAG 或强制复用；模型仍决定实际轨迹。
修复是否足以增加自然委派和真实复用，需要新源验证，不能预先断言。
