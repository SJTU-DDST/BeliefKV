# 事件与正文驱动的 child 报告阶段和剩余工作实验

日期：2026-09-30。

## 目标与边界

将长程 child RETURN 墙钟回归拆成最终报告阶段判别、条件剩余生成工作
和独立服务/等待分账。模型只读输出正文和通知，不控制 child 终态，不
添加 guard，不要求自然语言报告变为结构化结果。H2D 许可及净收益保持
在 runtime 的物理状态和容量决策侧。

本轮目标是实现低开销非侵入式 token 序列基线并快速验证，不是宣称
已经实现完整预测式调度或亚秒级 RETURN ETA。不会以手工修改 eligibility
标志替代证据，亦不会因模型分数低而取消 child。

## 实现

- `beliefkv/predictor/child_report_phase.py`：按训练词表编码末尾 64 个
  已送达文本 token，24 维 embedding 和 2/3/5-token 卷积，输出最终
  报告原始分数、准备发通知的分数与有序名义剩余 token P10/P50/P90。
  三类标签明确区分继续工作、调用完成通知、当前报告轮次自然 RETURN；
  标签读取未来结果仅用于训练，模型观察不含这些结果。
- 事件输入包含有效 `announce_completion_intent` 的长度提示。继续
  执行工具、context 变化和终态使旧提示失效；future notice 不可见。
- 样本保留 request、child、context、epoch 和观测时间，接口不输出
  RETURN 秒数或物理传输许可，checkpoint 元数据仍为离线实验。
- 现有 trace 每个正文快照只保存末尾 128 个字符。第二个对照由过去的
  已送达快照因果重建最多 1024 字符的历史，文本缺口明确标记；不
  推断缺失正文，不读取未来最终报告。
- 剩余工作标签为同请求服务端最终 output-token 计数减去当前保守
  时钟界内已观测的 output-token 计数。未来服务/无服务区间是离线
  分账，不进入工作量模型。

## 快速验证口径

评估本轮 36-root trace；两批旧 32-root trace 只作训练。每个留出
项目的当前及旧数据均从训练侧排除，训练词表和归一化也只读取训练侧。
固定 20 epochs、seed 21 和 0.5 的只读阶段统计阈值，不在留出项目上
搜索阈值。分数是未经校准的比较信号，不是 runtime 门禁。

同时报告每个字符检查点的分母、自然 RETURN、工具轮次、精确率和召回；
另按请求统计第一次信号，避免把重复快照当作多个成功预测。仅有正文、
且有验证过的正在进行的服务的请求可参与此次比较；没有合格正文
或服务的工具轮次保留在 coverage 中，不伪装为全量工具误报率。

## 执行状态

1. 完成只读预测接口和 token 序列 CNN。
2. 完成通知失效、精确 token 标签、服务/等待分账和项目隔离导出。
3. 完成 128 字符 tail、有界正文历史、三类头及类别平衡四组快速对照。
4. 完成未来信息隔离、工具失效、类别权重和模型保存/加载测试。

原始结果保存于本轮 raw 目录下的 `report_phase_work_project_loo_v1/`，
最终三类对照位于 `report_phase_work_three_stage_v1/` 和
`report_phase_work_three_stage_balanced_v1/`。

## 结果

有服务与已送达正文的 243 个请求包含 43 个自然 RETURN 和 200 个工具
轮次。工具总数为 3018，其中 2814 个无合格正文、另有四个无可验证
服务，不能把下面的误报率当作全量工具误报率。四个检查点合并去重后
共有 484 个快照，其中 18 个的重建历史含明确的文本缺口。

按请求统计首次分数达到 0.5 的观测：

| 信号 | 命中自然 RETURN | 工具误报 | 精确率 | RETURN 召回 |
|---|---:|---:|---:|---:|
| 有效通知 | 28 | 2 | 93.3% | 65.1% |
| 三类正文+进度头 | 43 | 20 | 68.3% | 100% |
| 三类正文+事件头 | 43 | 21 | 67.2% | 100% |
| 类别平衡正文+事件头 | 43 | 23 | 65.2% | 100% |

平衡模型在固定 0.95 分数档仍有八个工具误报，精确率 84.3%，并非
95% 的实际置信度。普通三类模型的 21 个误报中，六个随后调用
`announce_completion_intent`，另 15 个继续调用真实任务工具；
“即将报告/通知”与“当前轮无工具、直接 RETURN”不能混为一类。
三类头在 25 个通知类快照上均未命中，类别平衡也未解决这点。

条件剩余 token 误差（类别平衡正文+事件模型，对自然 RETURN 轮次）：

| 检查点 | RETURN | 训练检查点先验 MAE | 序列模型 MAE | 名义 P10--P90 覆盖率 |
|---|---:|---:|---:|---:|
| 首快照 | 43 | 253 | 256 | 48.8% |
| 128 字符 | 43 | 256 | 242 | 39.5% |
| 512 字符 | 42 | 242 | 246 | 33.3% |
| 1024 字符 | 41 | 223 | 214 | 26.8% |

序列头没有取得稳定的明显工作量精度增益，名义区间严重欠覆盖。
从当前保守已观测服务点到请求结束，未建模的无服务区间中位数随
检查点为约 2.87/2.43/1.96/0.90 秒；这是离线分账，不是可预先输入的
等待量。不能直接将 token 区间除以速率后称为校准的 RETURN 区间。

模型约 4--4.8 万参数。在单 CPU 线程的独立基准中，包含分词、张量
构造和前向的单观测推理 P50 约 0.18--0.20 ms，P95 约 0.23--0.25 ms。
未测在线 scheduler/agent callback 高压下的干扰，不能从该数声称
端到端没有开销。实验未启动新 GPU 服务，未进行物理 H2D。

## 结论与下一目标

已实现并快速验证事件/正文阶段头、条件 token 工作头和独立等待分账。
这证明只读推理接口的低成本实现可行，不证明当前正文模型能够准确
触发预测传输；checkpoint 均是未经校准的离线原型，未接入 runtime。

下一步优先增加阶段语义的可辨识性：以当前通知信号为主证据，验证
更有语义能力的文本表示是否能补齐未通知 child，分开通知协议和
真实任务工具；不能用强制终止或新增 guard 人为制造高精度标签。
随后在独立项目上校准剩余 token 区间并报告精确率、召回与覆盖，
确认它能在传输所需提前量内滚动收敛后，再接在线进度并做 GPU
物理实验。精确 RETURN 时刻、完整 JOIN 和吞吐收益仍是未完成目标。
