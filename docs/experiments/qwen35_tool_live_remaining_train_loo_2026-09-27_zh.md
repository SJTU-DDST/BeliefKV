# Qwen3.5 工具存活后的剩余时间头：训练项目留一（2026-09-27）

## 问题与方法

工具调用开始时给定的持续时间估计，在其尚未结束时能否用新获知的
“已存活到当前时点”更新剩余时间？新增只读
`scripts/evaluate_tool_live_remaining_loo.py`，只用已有 128-root
高压与 20-root 低压**训练项目**的首个冷输入工具调用；
包括自然成功及有返回的非异常错误，未完成、异常和干预调用不作为
短调用负样本。148 次 workflow 运行涵盖 128 个不同 task，
其中 20 个 task 跨批次重复。以完整项目为单位逐个留出，
相同 task 的重复运行按一个 bootstrap cluster 处理。

在工具调用分别存活 100、250、500、1000、1500、2000 ms 时，
只对当时仍活跃的调用预测剩余时间。模型以剩余毫秒 L1 拟合，
只使用 TOOL_START 时已知的命令形态、输入长度及因果历史/peer
字段；观察到的存活时间只用于选该时点的模型和支持集，不读取
未来的进度或标签作为特征。比较另两个训练项目留一的头：
存活调用的形态中位数先验，以及现有仅用持续至少 600 ms 的
调用拟合的 `calls` 冻结时钟。后者在“全部存活调用”上只是
参照，还要单列事后已知的真实长调用支持集；该子集**不能**
用于在线决定是否行动。

## 结果与否决

| 存活点 | 全部存活调用 | 全部调用：形态 / 冻结 calls / 剩余模型 P50 误差 | 真实长调用：冻结 calls / 剩余模型 P50 误差 |
| --- | ---: | ---: | ---: |
| 100 ms | 6,920 | 239 / 586 / 140 ms | 348 / 543 ms（2,206 条） |
| 250 ms | 4,774 | 367 / 480 / 161 ms | 348 / 407 ms（2,206 条） |
| 500 ms | 2,615 | 1,007 / 364 / 293 ms | 348 / 417 ms（2,206 条） |
| 1000 ms | 1,129 | 576 / 1,086 / 761 ms | 1,086 / 761 ms |
| 1500 ms | 897 | 472 / 767 / 379 ms | 767 / 379 ms |
| 2000 ms | 610 | 25,428 / 440 / 1,278 ms | 440 / 1,278 ms |

上述是合并的调用中位数，**不是**按项目独立重复得到的显著性
证据。100 ms 存活点，真实长调用在 Pydata 上冻结 calls
约 1,081 ms、新模型约 1,375 ms；Pytest 为约 137→526 ms。
两项目按 task 聚类的配对改善区间上界仍为负值。
500 ms 存活点的 1,129 个真实剩余至少 500 ms 的窗口中，
新模型只选中 243 个，同时把 225 个不足 500 ms 的窗口
误判为可行动，漏掉 886 个。2000 ms 存活点相较冻结时钟
也明显恶化。减小所有存活调用的 P50 误差主要帮助了短
剩余调用，不能替代长窗口的时间精度或预取门禁。

**决定：不将此头上线，不因合并全体调用误差变小而调整
PREFETCH/JOIN 门禁。** 已有的 100/250 ms 时间头试验
和本次消融都缺乏稳定的跨项目长窗口 ETA 增益；下一步需要
真正发生在命令执行期间、比最终回调更早且可跨项目泛化的
在线进度信号，或从时间点预测转向有界动作收益决策。
JOIN 的完整 blocker 集合、队列影响和物理 H2D 消费仍须
独立评价，不能从这些工具调用误差推断。
