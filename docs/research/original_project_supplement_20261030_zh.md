2026-10-30 最新执行顺序已调整为“先验收负载/到达/完整 JCT，再验证 oracle，
收益建立后才做预测”。下文此前 Full 后直接运行 ThunderAgent 的计划已被
取代；现有冻结控制和完整历史证据保留。验收条件与 R5 边界见
[当前目标](../design/oracle_first_validation_goal_20261030_zh.md)。

正式工作负载不能只在六个项目上选择。复用已经完成的22个不同项目，
一次补齐另外26个项目，以48个完整原题候选构建预热、测量和背景人口。
新增候选来自固定LoCoBench-Agent原始归档，不改变题目目标，不给测试
造替代实现，也不为制造模型工作量添加调用。

`scripts/prepare_original_project_supplement.py` 保留完整公开题目、场景
哈希、原项目源码和测试、完整冻结仓库上下文。26个候选包含17个代码理解、
2个架构理解与7个功能实现任务；新增上下文以当前模型tokenizer重算为
19,068--178,191 token。选择依据是未覆盖的原项目和原题类别，未使用
predictive收益、native重算或同题最短重复轨迹。

采集配置独立记录三个值：26个待采root、最多12个同时运行的root、
24个原生running/decode请求上限。采集不设正式泊松到达表；它只提供
可复用的完整工作量、依赖、工具时长及token。`CLIENT_ROOT_CONCURRENCY`
保持旧入口的默认行为，只有显式配置才降低采集窗口；外部固定到达表
禁止较小客户端窗口，以免引入未声明的准入排队。

实际工具检查已覆盖26项目的root和child、共享工作区、失败退出码传递、
容器清理。项目测试和任务正确性仍由模型负责。当前聚焦CPU校验通过
185项与6个子测试；完整源码绑定校验随后通过5,672项与12个子测试，
保留全部5,644项旧测试身份，无失败、错误或跳过，2,131项绑定输入及
原生引擎在运行中未变化。冻结入口和GPU运行证据另行记录。

后续按完整候选池统计P80/P20，最低3、同时报告是否达到4；工作量分层
独立计入模型服务代理和工具因果关键路径，并行工具按最大路径计算。
多成员JOIN、child长度、重复并行轮次、root实际工作和上下文大小交叉
覆盖分别报告。不能只通过工作量倍率就宣布满足所有机制条件。

正式重放须先支持完整workflow多来源组合，独立编译每个来源的时钟域；
保留精确prompt/output、停止参数、原工具时长和全部依赖。统一的冻结
到达表提供预热、按到达序号固定的测量组和背景任务。每个测量成员的JCT
从预定到达到自然完成；吞吐按共同墙钟窗口统计全部工作。检查背景覆盖、
积压增长、实际跨workflow容量竞争、容量释放后的服务补位、物理KV与
有效前缀损失，之后先运行predictive，再运行匹配的ThunderAgent工具
衰减版本。保留JOIN/EOS预取；工具预取和逐层handoff保持关闭。

## 冻结的持续到达校准

`sustained46_r1` 使用6个初始预热、18个固定到达序号测量对象、22个
后续背景对象。独立泊松到达率为0.0125 workflow/s，即平均80秒一个；
到达种子与任务排列种子均改为31，模型种子仍为21。固定提交截止时刻
为3,353.249秒。不能按某一方法测量组的完成时刻停止背景提交。

速率选择只作粗标定：26项源的完成速率按46项更大的平均固有模型工作量
修正后约为0.01330 workflow/s，当前到达率约为该量级的94%。这不是
新Full的实测承载能力；上下文长度、工具等待、KV迁移和batch效率都
可能改变它，必须进一步检查真实积压、ready-paused竞争与物理容量。

继续使用已声明的TraceLab可观察网络类别合成场景，固定替换1,937次
`execute`时长，WebFetch/WebSearch类别在工具开始时可见，具体采样时长
保持私有，其他工具保留原始时长。当前样本P50/P90=5.733/16.339秒，
最大61.752秒，未截尾或缩放。离线222条训练调用和91条评估调用按公开
session分离，在线历史预测仍保留。这是明确声明的合成工具场景，不是
LoCoBench原生工具耗时。

首个Full保留现有策略作为匹配控制，尚不启用工作量排序。后续oracle或
可部署排序须使用同一组任务、工具和到达表；不能将oracle当作部署结果。
首个Full校准之后再匹配ThunderAgent acting-decay，比较固定组完整JCT、
同一墙钟窗口内包括背景的吞吐、服务间隔和KV成本。旧源采集JCT不能
充当新组合/到达/工具场景的native对照。

测量组身份仅保存在`analysis_cohort.json`，不进入调度器配置。统计代码
要求预热、测量和背景全部保留完成边界；按native批次完成时刻计输出，
包括prefill首token，另外报告decode吞吐和分箱趋势。若最后固定背景
到达早于某个测量对象的完成，记录未覆盖排空区间，不能把该结果标作
持续背景覆盖合格或稳态服务。

## 最新目标下的验收与统计修复

最新用户顺序已改为：负载/到达/评价验收 → oracle 收益 → 预测器。
ThunderAgent 与其他 baseline 暂缓，本文早期“控制之后直接运行
ThunderAgent”的计划不再执行。当前 Full 保持冻结，不热改服务代码。

发现新固定组统计错误：`workflow_cohort` 把 prefill 的 `token_delta`
当作输出，但真实日志该字段为 extend 输入量；实际所有 forward 模式的
输出量在 `output_token_delta`。分析代码已修正，并要求全程按 workflow
聚合的服务输出与完整精确请求回执一致。该问题不改变调度或 JCT 边界，
但修复前的共同窗口输出吞吐不能作为有效结果。原冻结 CPU reviewer
仍保留；其旧口径 cohort 文件须由修复后分析重新生成并明确替代，不能
因原 reviewer 正常退出就接受其吞吐。已有仅 decode 图表按 decode
批次统计，不能据此推断其同样混入 prefill 输入。

新增 `audit_sustained_supply.py` 按独立完整 JSONL 前缀审计在途人口、
已提交且未被工具/JOIN 阻塞的请求、paused 身份及未折扣逻辑预算。
固有工作按完整因果顺序重建，不比较不同采集来源的原始时钟；剩余量为
源总量减已完成请求，明确不扣在途部分输出。该审计不等于 exact tick
决策或 native 物理反事实。

`workload_validation_r1/live_supply.json` 的运行前缀包含38个已到达、
25个已完成 workflow，测量组完成13/18。共同窗口2,230份快照中，
360份有 ready-paused，3份存在跨 workflow 的两名候选：各自最低逻辑
预算可容纳、二者合计超预算，其中2份剩余工作倍率至少2。两份属于同一
候选对的相邻快照，不能说成三次独立实际恢复决策；三名及以上集合、
原 decay 预算、native 缺页和旁路准入另需核验。各300秒区间的在途人口
多为10--16，ready-paused中位数均为0。

同一观察的最新 HBM allocator 驻留约99.96%，可回收152,308 token；
这不是独占有用活跃 KV。Host约199.93GB，旧同 session 公共前缀损失
代理仍为0；Host驱逐块再访问的另一口径记录4,485个FULL单位重算，
不能将两者混为“所有重算都为0”，也不能把Host占满直接判为负载不合格。
原生计数较各日志前缀更新，完整结果仍待最终核对。

针对统计、独立时钟工作守恒、固定到达、阻塞排除与源组合的84项检查
已通过。审计初次入口错误把注册中的内嵌到达表当成配置的 path 对象，
在写结果前退出；已修正为 `workflow_arrivals_path` 并核对内嵌计划，
新增真实注册结构回归。保留该失败说明，不把它计为一次 GPU 尝试。
当前不宣称负载已完全合格、稳态成立或 oracle 已有收益。

完整共享 CPU 首轮保留为 `workload_validation_r1/bound_cpu_r1`：
5,720通过、3失败、12子测试通过。失败均为真实并行嵌套 harness 中的
回调事件时间倒序，最大观察倒退约0.625ms，不是项目测试或数据集任务失败。
修复在 adapter 的原发布锁内维护因果发布水位；发生并发交错时保留
`callback_observed_ts_ms`、公开调整量，原工具 `duration_ms` 不变，trace
与 control 收到相同事件。不重写旧来源、不热改当前重放。两个确定性交错
回归与完整 adapter/嵌套/本轮审计的133项聚焦检查通过；完整重验另列。

默认关闭的组合选择器也存在待解决的证据边界：资源摘要当前仅计原生
空闲页，没有纳入满足原生安全条件的可回收容量；在缓存占满时可能提前
回退，但不能直接把所有 evictable 页当作免费容量。缓存元数据微检查
每档200轮，6候选P50/P99约244/276微秒，8候选全部触发0.5ms软预算
回退，P50/P99约507/519微秒。该合成输入不含候选发现、物理路径、
日志或模型开销，不能宣称为完整控制成本。正式 oracle 之前需核查这些
回退和实际选择覆盖，不因理想评分已写入文档就假定其已落实。

修复后 `workload_validation_r1/bound_cpu_r2` 完整通过5,725项与12个
子测试，保留原5,701项身份，无失败、错误或跳过，2,158项绑定输入及
原生引擎在测试期间未变化。首轮失败保留。当前提交仅补充采集侧修复和
