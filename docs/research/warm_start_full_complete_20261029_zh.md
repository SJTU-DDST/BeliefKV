### KV 池已经接近满载

共同高负载窗口为计划首到达后的 300--1800 秒，按原生 allocator 采样
间隔加权；每个样本最多保留 2 秒，不跨长采样缺口补值。FULL 覆盖
100%，ThunderAgent 覆盖 99.9724%。两侧同为 805198-token FULL-only
池，有效容量 79.154184192GB；不把预分配池容量当成实际有效 agent 占用。

| 方法 | 驻留均值 | 可驱逐均值 | 不可驱逐均值 | 空闲均值 |
| --- | ---: | ---: | ---: | ---: |
| ThunderAgent decay | 99.5654% | 31.9636% | 67.6018% | 0.4346% |
| FULL | 99.3463% | 31.0787% | 68.2676% | 0.6537% |

FULL 平均约 78.637GB 驻留、24.600GB 可驱逐、54.037GB 不可驱逐，
只有 0.517GB 空闲；98.821% 的观测时间驻留不低于 95%。
因此不能从 handoff 次数少推断 HBM 大量闲置。可驱逐缓存不一定冷、

### 腾出空间与新增 D2H 是不同事件

| FULL 路径 | 节点释放事件 | 累计释放 FULL |
| --- | ---: | ---: |
| 真实分配缺口下回收 JOIN 等待页 | 747 | 173.816020992GB |
| 真实分配缺口下回收工具等待页 | 912 | 51.149635584GB |
| 需求感知预测工具回收 | 253 | 27.223523328GB |

前两类合计 1659 次、224.965656576GB，均有原生真实分配缺口和已完成
Host 副本证据。第三类关联 144 个消费者。它们是节点级累计事件，不是
不同 agent/B 请求的数量、唯一 KV 体积或可以直接扣减的 JCT。
已备份 A 可直接释放 Device 副本，不需新增 D2H。

需求感知工具路径另发起 76 个新备份命令，关联 70 个消费者，全部实际
ACK，累计 0.977534976GB；76 个 ACK 都早于对应 B 的首次原生服务。
这只证明存在针对缺口消费者的新备份，不证明全部备份都实际释放并被
同一个 B 使用。严格要求同 owner、同 node、同 beneficiary，且依次
满足“新备份 ACK → 实际释放 → 该 B 的已记录原生恢复 → 首次服务”，
可关联 7 条链。其余未关联不等于浪费；普通压力释放没有完整的 B 身份，
日志也没有物理页到消费者分配的完整谱系。

上述路径不穷尽 native LRU 的 writeback。因此，现有证据能确认“需要
腾空间”并不少，但仍不能精确报告所有“必须新增 D2H 后才能加载 B”的
独立次数，不能用 1 次 handoff 或 7 条关联链替代该分母。

### 五秒周期有可测的候选优化空间

使用已提交请求、全部首次原生服务记录及约一秒的逻辑状态快照，限制为
尚未首次服务、paused 且未 marked-for-pause 的调用。按该快照记录的
原始 active 总预算，检查候选完整输入加原有 100-token buffer 是否
放得下；状态最多保留 2 秒，不用最后一次五秒控制快照代替当前记录值。

完整收集窗口内有 130 个请求出现过这样的可容纳采样：40 个 invocation
首次调用，90 个后续调用。逐请求累计采样等待的 P50 为 2.031622 秒、
P90 为 4.086426 秒、最大 5.637244 秒；累计 292.714977 请求·秒。
至少存在一个此类候选的观测时间并集为 209.014771 秒；额外要求再有
4096 个逻辑 token 余量时仍有 179.757911 秒。这些不是可直接消除的
workflow JCT，累计请求时间可能重叠。

在共同 300--1800 秒内，相应观测时间并集为 183.188111 秒，占 12.213%；
额外 4096-token 余量时为 154.935780 秒。采样并非精确状态转换，active
token 账本也按原有刷新节奏更新；逻辑可容纳尚不证明物理页、native
槽位及依赖可执行，更不证明全由 tick 延迟造成。ThunderAgent 没有相同
逐 program 预算快照，该统计为 unknown，不能将缺记录读作零等待。

当前 FULL 的
[事件准入](../../beliefkv/runtime/reference_free_continuation.py)
已响应请求注册、完成、工具返回、JOIN 和终态事件，但只接 continuation，
每事件最多一名；普通候选窗口从 live requests 前部取八项，active
请求也可能占掉检查窗口。单纯缩短 tick 不能消除这些覆盖限制。

### 下一候选的改进顺序

先使用独立的 ready-paused 索引，容量/资格变化事件标记受影响候选，
在同一轮原预算内有界补位，覆盖首次调用和 continuation；复用现有
sibling 偏好，不新增抢占 active、全图物理扫描或逐 decode 步模型推断。
随后可单独声明 FULL 的 1 秒兜底周期，保留 ACTING decay 公式、
1800 秒超时和原压力处理；纸基线和当前冻结队列仍维持其原配置。
1 秒是待测候选，不是已部署或已验证的最优周期。

验收应同时检查可容纳 paused 等待、实际首次服务、有效运行宽度、控制
CPU、额外 H2D/D2H、重算和完整 JCT。KV 池已经接近满载，目标应为提高
有用工作集的及时消费，而不是增加无效缓存、强制迁移或 handoff 数量。
需要新增 D2H 的大缺口若仍有足够频率，再评价多 donor、donor 尾部与
输入增长预留的安全衔接，以及真实关键路径 overlap；不能因平均驻留率
高就假设这些具体条件自动成立。
