# 连续真值之后的短 workflow 准入检查

## 固定问题和边界

2026-11-09 Asia/Shanghai，连续模型工作真值 Oracle 已完整完成，固定 18 个测量
成员的平均 JCT 为 1041.991464 秒，相对重复轮非排序 Full 改善 1.018541%。
仍使用用户最终选择的 83 项目、400GB Host、20 初始、平均 70 秒固定到达；
不恢复旧 goal 文字中的 73 项目，不改变任务、token、依赖或工具时长。

继续推进的目标是可重复的约 1% 或更高完整平均 JCT 收益，再推进可部署的
学习预测。上一轮属于进展：完整运行、工作守恒、实际服务和吞吐核验均已完成；
它尚不能证明重复性，也不能给未通过校准的连续学习产物授予部署资格。

本项先检查现有 CPU 候选 `choose_shortest_frontier`：保留必需 JOIN 后，
优先为最短且单独规划可行的普通 workflow 保留一个成员；同组 ready sibling
整体放得下时共同保留，否则允许部分推进；再用原组合搜索填充剩余资源。
候选继续使用相同六/八成员窗口和 0.5ms 软预算，无物理释放、加载或准入权限。

## 后续决策

当前证据确认了组合目标的具体选择机会，也确认 6 次存在减少并行推进对象的
代价。尚未接入服务或登记 GPU。先核对这些被排后请求的精确 attempt/session
实际服务时刻，区分短暂选择差异与持续服务等待，再决定是否值得完整 GPU
验证。局部等待不能直接累加为可消除的平均 JCT，改变未来调度也可能影响其他
workflow；本项没有反事实执行或性能收益估计。

## 实际等待核对与本轮决定

新增可选 `--observe-native-service`，从相同选择边界取新进入替代集合的完整
request/attempt/context/session 身份，再在原生记录中寻找后续服务。有效工作
还要求 batch 在选择边界之后启动，排除先前服务、错误 attempt/session、
未知身份、零进展和已经启动的 batch。重复请求及并行分支在 workflow 内合并
等待区间，没有给反事实候选伪造实际授予。

最终 90 项相关 CPU 检查通过，无失败或跳过。补充检查覆盖重复等待去重、早期
服务排除、原生时钟异常、跨时钟域及未知身份；不修改任何服务或原始日志。

此前“10 次改选涉及测量成员”包括把测量成员移出集合；不等于 10 次直接提前
测量成员。这里只按预先固定的测量标签解释证据，不能把该标签用于在线选择、
重新挑选任务或修改主要统计人口。

这些局部等待不是可消除 JCT 或整体加速上界，后续状态也可能改变。它们没有
显示大量持续被排后的短测量 workflow，而 6 次改选会减少准入成员数，存在
并行度代价。因此本轮不新增“强制最短优先”GPU 实验，不将该候选接入默认
服务。现有 1.018541% 单次真值结果及所有完成比较保留，整体目标保持 active。

另一次 CPU 只读计数发现，当前连续真值运行有 134 次压力暂停记录：
124 次立即暂停阻塞对象、10 次仅标记后续边界暂停，工作量预测参与次数为 0。
源码与声明相符：R5 条件分布及同选择器真值模式的
`WorkflowSizeAdmission._pressure_preference` 明确返回 `None`；工具保留权重
仍然生效。这是当前组合调度的实现边界，不据此直接认定为 bug 或 134 次
可改进机会。后续先核对同工具保留档内是否有多个实际安全候选，再考虑把工作量
用于压力选择；不能抛弃工具权重、保护对象和请求边界来人为增加改选次数。

现已实现显式的同工具保留档压力工作量 Oracle，并完成准备及相关 CPU 检查；
未接入默认 R5、未登记 GPU。具体实现、失败修正、输入保持和剩余检查见
