## 恢复请求 TTFT 辅助优势

2026-10-29 补充离线分析：将工具后继和 JOIN 后继的恢复 TTFT 改善，
暂记为本轮相对 V345 工具衰减 ThunderAgent 的有限辅助优势。
Resume TTFT / resumed-turn TTFT 在此统一定义为：
恢复请求的客户端提交开始，到客户端收到首个流式输出的时间。
首次 native 调度不是首 token；工具结束或 JOIN 满足到请求提交的客户端
间隔另计为 ready-to-submit，不混入这个 TTFT。

比较保留同一完整 V230/V311 的 18 个 workflow、全部 3674 个请求、
精确输入输出、工具计时及正常尾部；其中工具后继 3474 个、JOIN 后继
72 个。下表按请求统计，单位为秒，P95 使用 nearest-rank：

| 恢复场景 | 请求数 | V345 平均 TTFT | 本次 FULL 平均 TTFT | 平均降低 | P95：V345 → FULL |
| --- | ---: | ---: | ---: | ---: | ---: |
| 工具后继 | 3474 | 1.474214 | 1.301541 | 11.71% | 5.299231 → 4.352187 |
| JOIN 后继 | 72 | 10.492605 | 1.500730 | 85.70% | 47.450159 → 4.155385 |

JOIN 的 72 个配对请求中，64 个恢复 TTFT 改善。按每 workflow 内的
请求均值再等权平均，工具后继为 1.685066 → 1.508686 秒，JOIN 后继为
12.199949 → 1.649458 秒；它们与上表的请求加权口径分别保留。
完整响应同样改善：工具后继的客户端提交到响应接收完成均值为
5.816683 → 5.547937 秒，JOIN 后继为 18.956499 → 10.146294 秒。
因此本轮不只是首 token 提前，但仍不将这些请求差值直接加成 JCT 收益。

这个辅助优势的边界如下：

- 该恢复 TTFT 复核来自本次 FULL 与单次 V345 的配对；前述 R1/R2 的
  JCT 重复结果不等于恢复 TTFT 已完成重复验证。两侧 native tree 分别为
  `729aa0caa7a1` / `11b84f7c3198`，不作单模块因果归因或统计显著声明。
- 本轮工具预取仍关闭，不能将工具后继改善称为工具预测 H2D 的收益；
  JOIN 后继改善也属于整套系统的观测，不能全部归因于 JOIN 预取。
- 工具后继 P50 基本不变，V345/FULL 为 0.124774/0.125676 秒；
  FULL 的最大恢复 TTFT 仍达 326.883748 秒。相对准入前卸载 FULL，
  工具后继平均 TTFT 反而从 0.989708 增至 1.301541 秒，保留该回退。
- 内部 agent 的首 token 不一定是用户可见结果或可执行工具调用。
  此项只作为恢复及时性的辅助证据，完整 workflow JCT、全程吞吐、
  完整响应及 ready-output gap 继续共同评价，不宣称用户体验全面改善。

## 原始24.98秒问题

固定原来的2973个历史工具后继、467561输出token，相对准入前卸载：
prefill成员区间-2.853132秒、decode+13.425704秒、成员之外-20.425701秒，
首次服务到完成合计-9.853128秒。首次服务前等待仍多59.143803秒。
这些固定历史请求与每轮实际关键路径分别报告，不能加到完整JCT上。

按本轮实际关键路径，首次服务前等待+1.350547秒、服务到完成
-15.237101秒，其余事件净约+0.588699秒，总JCT-13.297855秒。
worker区间包含运行时和传输依赖，历史新增独占控制CPU仍未知。
不能将上述分解或不同运行之间的差值当作纯kernel、DMA或控制CPU。

workflow TTFT均值132.160374秒，对照139.028403秒；每workflow最大
post-first ready-output gap均值83.807889秒，对照73.449107秒。
后者明显回退，故没有声称workflow交互性或公平性全面改善，也没有删尾。
