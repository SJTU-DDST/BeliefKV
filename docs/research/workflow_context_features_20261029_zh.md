# Workflow 剩余工作预测的上下文特征

## 数据范围

开发阶段沿用 34 条训练、22 条校准、18 条开发评估完整执行。训练包含
历史 V174 的 24 条，加上已完成的 8 任务采集中 4 条及匹配当前任务的
6 条；校准包含历史 V171 的 18 条及 8 任务采集中的另 4 条。
允许同项目、同任务的独立执行，不将一次执行的快照拆到不同集合。
这些评估已参与开发，不能称为盲测或未见项目泛化。

现有数据足以先检验输入和选择机会，不因项目隔离而继续采集 native。
原始 trace、失败结果及正常长尾全部保留。

## 输入缺口与实现

已有 17 个数值特征包含完成请求的必要输入、已观察输出及图进展。
训练、校准和开发集合的首请求提交处，分别有 34、22、18 个样本，
每个集合的数值向量都只有一种取值，累计完成输入 token 均为零。
任务文本仍然不同；这不代表整个模型输入完全相同，也不证明性能根因。

新增可选 `workflow_remaining_model_work_context_v2`，追加三个数值：

| 特征 | 来源与时机 |
| --- | --- |
| `initial_prompt_tokens` | root 第一次实际提交的完整输入长度，提交前未知，之后固定 |
| `active_prompt_tokens` | 当前已提交、尚未完成逻辑模型调用的完整输入长度之和 |
| `max_prompt_tokens` | 当前 workflow 截至此时已提交输入长度的最大值 |

这些是逻辑输入长度，不是物理 KV 占用、独占页数或真实 GPU 时间。
并发调用各计其可见输入，不给共享前缀虚构物理空间信用。未提交的未来
请求、最终生成长度及最终工作量均不作为特征。重复提交和已完成调用
不会再次计入活跃输入；部分 decode 输出沿用原有真实输出计数。

旧 v1 模型继续读取原 17 个特征，权重、默认导出和默认训练模式保持兼容。
新模型声明完整 schema 与维度，导出、训练、后台 Worker、输入一致性
检查和 paused 竞争审计都按该声明取数。调度热路径仍只查询已有缓存，
没有新增物理路径遍历或 GPU 查询。

## 验证与下一步

两个旧实现反例先实际失败，保存在
`experiments/reports/workflow_work_training_20261029/context_features_r1/initial_red_cpu.xml`。
第一组 93 项测试通过；随后全部 workflow 预测、准入、选择与训练相关的
167 项 CPU 测试通过，无失败、错误或跳过。原生复制和物理调度没有改动。

在相同 34/22/18 执行上重新导出 v2，已完成。逐快照保留旧 17 维、
事件顺序、执行指纹、任务、已完成工作和最终标签，不能借特征修改工作量。
固定 compact16、词表 512、dropout 0.25、weight decay 0.1、300 epochs、
seed 21，只拟合一次，并已完成实际 root 输入/完整进度一致性和同一批
paused 竞争诊断。源代码为冻结的 `d6001b9c`，运行显式隐藏 CUDA、nice19。

这些 CPU 检查不构成源绑定的完整运行时资格，也不证明 JCT、吞吐、
后台 200ms 缓存时序或实际 GPU 准入改善。

## 固定数据的结果

| 指标 | 原 17 维模型 | 新 20 维模型 |
| --- | ---: | ---: |
| 校准集 macro F1 | 0.533339 | 0.578583 |
| 开发集 macro F1 | 0.450162 | 0.531463 |
| 开发集长任务判短比例 | 19.1823% | 20.1723% |
| 首次真实提交时的分类正确率 | 9/18 | 9/18 |
| 连续剩余工作量的 paused 比较正确数 | 1332/1803 | 1252/1803 |
| 每对请求仅取首次比较的正确数 | 273/440 | 272/440 |

第一行校准门槛通过；它只说明原有 calibration 检查允许产生预测，不代表
模型已获得性能实验或推广资格。分类分数提高，但长任务误判略增，
实际 paused 排序没有改善，所以不为这个模型注册 GPU 性能实验。
原有 mixed-off、2 秒 Full 继续作为保留配置，workflow 分档保持关闭。

1,803 项是同一原生运行的重复观测，不能称为独立任务；440 项按请求对
去重，仍然来自同一批 18 个 workflow，也不是 440 个独立 workflow。
去重时按时间逐次观察，在同一原恢复类别中每 workflow 只取最小上下文
代表，对每个请求对只保留首次可比较的连续工作量。原上下文顺序在这
440 对中正确 232 次，两种模型在同一候选、同一标签和同一时间上比较。
没有重建实际物理容量、完整 selected set 或 JCT 反事实。

新输入将 18 个首提交数值向量从原来 1 种变为 18 种，仍未提高首提交
正确率。不要把 WORKFLOW_START 处尚无首请求输入时的 `initial_accuracy`
和真实首提交准确率混淆。

实际后台 Worker 的 CPU 回放核对了全部 18 个 root、17,128 个快照及
17,110 次预测，包括 2,670 次原生部分输出观察；文本、特征、投影和概率
全部相同。全程运行时的 200ms 异步投递和 GPU 服务时序未被模拟。

机器可读证据：

- `context_features_r1/fit_run/state.json`：固定数据导出和单次拟合完成。
- `context_features_r1/fit_run/input_binding/parity.json`：完整输入一致性。
- `context_features_r1/paused_native_r1.json`：原生运行的完整 paused 观测。
- `context_features_r1/review.json` 与 `review_context_features.py`：旧 17 维、
  执行、训练设置和候选/标签一致性核对，明确未推广及未注册 GPU。

以上文件均位于 `experiments/reports/workflow_work_training_20261029/`。
没有额外重采 native，也没有启动或排队下一轮 GPU。保留可选 v2 支持、
旧模型兼容和本次负面的排序结果，后续不能仅凭 macro F1 继续性能实验。
