## 下一候选：一次提交真实并发任务组

在同一 `native_in_graph_parallel_workstreams` 实验 profile 中增加
`parallel_tasks(assignments=[...])`，每组显式提交 2--4 个结构化 checkpoint。
模型仍选择问题、角色、时机和后续组；`task` 继续处理真正不可分的单项
问题。初始工具选择仍为自动，不增加固定 DAG、多轮配额或输出硬上限。

该工具用原生 task 执行路径并发运行成员，再等待全部结果并返回一个
parent 工具消息。成员分别保留真实模型调用、回调、私有状态隔离、
session 和因果身份。runtime 将一个外部调用展开为它实际启动的成员，
记录外部调用 ID 和成员序号，不改写生成 token，也不虚构请求。
原生文件更新及删除标记保留；成员异常显式进入报告。

仅对未满足并行最低要求的最终返回，现有最多两次补充尝试改为要求
`parallel_tasks`，不再要求生成多个外部 task 调用。实际模型服务及
完成 JOIN 的校验仍保留。此干预需要继续在源报告中披露。

新的 `parallel_checkpoint_pilot6_20261030` 单独声明，保留上一批全部
六个原项目、任务文本、访问类型、上下文、工具环境及 4/8 child、
8/16 root 软预算。单项 checkpoint 格式仍为协议 3，并行 API 单独
记录为版本 1；整体契约指纹改变，旧采集不会因此重新解释。
这是 workload/runtime 接口准备，不是 KV 调度创新或性能收益。

## 无效角色导致的错误 child 记录

两个模型输出使用了 `=bounded-editor` 和 `<bounded-editor` 角色名。
原生 task 实际返回“不存在该角色”，没有执行 child 模型；适配器
却只检查结构化字段，没有检查当前 caller 图中真实可用角色，先记录
了 child 和 singleton JOIN，再把该工具返回记为完成。这是适配器
校验缺口，不能将其归为成功执行的 child，也不能修写旧 trace 消除。

主分支现在在 checkpoint 图构建时登记实际可用角色，以 caller 角色
和已观察到的委派深度查表，拒绝不存在的角色及没有 task 工具的 leaf
委派。root 和 direct child 的不同角色集合不会互相放宽。并行工具
在启动任何成员前检查整个组的角色，避免有效成员已执行、无效成员
却被提前忽略的不一致。正常模型输出、历史源和 paper 策略不改写。
