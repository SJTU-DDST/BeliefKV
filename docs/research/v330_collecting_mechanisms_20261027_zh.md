负 ACK-to-service 差值不能被解释为负等待或额外加速。

## 工具预取的收益判断边界

用户进一步明确：工具预取不是必须产生流量的设计点。零实际预取
不能单独判为实现缺陷，也不能证明关闭开关等价于当前执行；开启后
仍有预测和控制开销。保留、关闭或修复均以完整 JCT 和全程吞吐为准。

需要区分：

- KV 本来驻留，或者后继近期没有正常 agent 准入机会：不提前恢复。
- 恢复会挤掉 ready/排队 agent，或消耗当前计算增长所需空间：保留
  原生需求恢复，不能以提高工具预取覆盖率为理由强制搬运。
- 确有缺失且可安全恢复的 KV，存在空闲或真正阻塞、已备份的冷容量，
  且近期正常准入可消费它：才检查保守的身份、预测或资格检查是否
  错过一个值得验证的机会。

目前 retained eligibility 的检查发生在详细恢复规划之前。
`tool_prefetch_outside_retained_eligibility` 因而只证明跳过检查，不能
证明当时有 Host 缺失前缀、物理容量、可隐藏的实际 GPU 等待或净收益。
有恢复机会也只是候选证据，不是修复后必然改善的因果证明。

若完整证据支持修复，应单独声明候选并保持 JOIN 优先、原生容量权威、
ready peer 保护及低控制开销。评价同时计入提前占用时间、被影响请求
的恢复、重复 H2D 和重算；不能只比较 GPU 依赖等待而忽略总排队。
若大部分机会需要替换可执行的热工作，或匹配验证显示净负收益，
可以关闭工具预取并保留长工具卸载与 JOIN/EOS 预取。继续使用原本
可获得的在线信息，不把事后工具结束时间交给调度器，也不据此筛选
获胜调用或 workflow。V330 的冻结配置不因该判断规则而改变。
