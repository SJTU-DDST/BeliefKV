## 两个机制的实际证据

53 次阻塞额度交接全部绑定到同一 parent 的后续 native 服务。
其中 25 次在授权之后发生了有 allocation 首次服务证据的恢复，
合计 128240713728 字节；另外 28 次不能直接认定为无需恢复，
因为授权前恢复和 native demand 等路径要分别计量。
53 次授权至后续 native 服务 P50 为 242.42ms、P90 为 499.27ms。
交出的逻辑额度始终不被提前计入物理空闲页，ready/pending agent 不是 donor。

实际 23 次逐层交接均为 D2H8/H2D4，配对真实 ACK 与同 session 服务，
恢复 4384555008 字节，占全部 H2D 的约 0.1573%。
提交后至 journal 发布的区间 P50 为 0.9253ms，旧 1/1 为 4.8201ms；
总和分别为 22.95ms/23 次和 62.43ms/13 次。
这些是不同交易样本的 wall 区间，不能当作独占 CPU 或固定大小微基准。
23 次 native run_batch 进入均早于最终 donor ACK，但这不直接证明
每个真实 GPU kernel 都早于 ACK。组件验证中的实际提前读取证据单列保留。

## 局部改善为何未变成明显 JCT 收益

相对上一轮，H2D 增加 111.801GB，D2H 增加 23.907GB，
prefill worker 区间增加 3.618s。分组减少的几十毫秒提交区间，
不能单独抵消这些系统变化，也不能据此独立归因 JCT。

工具预取实际命令数为 0。63 个已观察 JOIN 预取 episode 中，
24 个在完成前启动并确认复用约 98.563GB；包含完成后恢复，
tagged H2D 约 190.789GB 均有复用证据。不能将新增迁移全部归为
“预取没有用上”；有效复用仍不等于全局净收益，调度和驻留变化可能
改变其他对象的换入换出，具体归因还需物理回收及服务链路证据。

旧输入代理统计没有发现首次服务缺失的先前同 session 公共前缀；
Host 驱逐再访问仍有 7780 token 单位重算归因，不能扩大为零重算。
恢复依赖采样本轮 35 个、旧 FULL 34 个、ThunderAgent 18 个；
不能直接用采样总等待比较全部恢复时延或按比例扩展为可消除 JCT。

后续优先统一实际消费者与增长预留的容量口径，再协调逻辑 donor、
可回收独占页、Host 目的空间和 parent 准入。当前 native 物理检查仍是
最终权限，逻辑额度 donor 与最终回收对象并未形成统一物理计划。
继续保留实验性 8/4 overlap，暂不推广，不启动消融或其他 baseline。
