# 连续工作量权重与初始语义预测

2026-11-02，America/Los_Angeles。针对三档内差异被压缩、`1/.5/.25`
缺少工作量依据，以及初始语义表示是否有效的问题，完成连续权重和
Qwen3-Embedding-0.6B 的 CPU 验证。新代码均为离线诊断；没有修改已冻结
GPU 实验、接入新服务模型或证明新的 JCT 收益。

## 问题与修正边界

当前组合准入对模型预测调用
`probability_weight = p_short + .5*p_mid + .25*p_long`。
冻结分界为 `[13062.96, 22971.15]`；剩余 24000 和 230000
均属 long，高置信度时权重都趋近 .25。三分位的样本数关系不能推出
工作量之比，概率校准也不能修复这种档内信息丢失。

最新保留模型的静态输入实际是 8192 项字符 n-gram 及 MLP，
进度分支另有连续剩余工作量条件树。它没有启用 `task_encoder`。
此前单独试过 MiniLM 句向量先验，不能将旧候选写成当前采用的编码器，
也不能以语义相似度模型的名称代替工作量预测准确率证据。

条件树本来已输出 `log1p(remaining_model_work)`，随后才转成三档概率。
因此进度阶段可以直接使用连续输出；初始阶段则需要任务相关的连续先验。
仅将 long 换成另一个固定系数，仍不能区分 long 档内任务。

另一项必须控制的差异是旧 oracle 使用模型/工具关键路径秒数，
学习模型使用逻辑模型工作量。旧二者的差值同时含目标、单位及映射差异，
不能全部归因为学习模型误差。

## 连续权重

离线比较采用共同的工作单位：

```text
R = 尚需必要新增输入 × 0.01 + 尚需输出
```

包含完整 workflow 的 root 和 descendants，各项只计一次；
工具等待、排队、迁移和丢失缓存导致的额外重算不属于该标签。
未来真实工作量仅为离线监督或 oracle 标签。

连续效用定义为：

```text
q(O) = E[M0 / (M0 + R) | 已观察状态 O]
```

`M0=19144.06` 为 77 条训练执行、59 个项目按项目/任务等权得到的中位数。
所有比较共享这个冻结参考量。点预测为 24000 和 230000 时，效用分别为
0.443724 和 0.076839，不再因同属 long 而相同。

这是一项有工作量尺度、数值有界的启发式，不是最优平均 JCT 的推导，
也没有证明中位数或此函数形状最优。预测为 log-work 时，
`expm1(E[log1p(R)])` 不是 `E[R]`，不能将其标成算术平均剩余量。
分布版本使用既有校准残差尺度及固定 12 点 Gauss–Hermite 积分；
初始无语义版本使用训练档内的经验效用
`[0.655105, 0.524308, 0.358716]`，没有新拟合调度系数。

## 语义预测实验

固定公开 Qwen3-Embedding-0.6B，revision
`97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`。
输入只含已声明任务说明，最多 4096 字符，没有完整 prompt、源码、
工具输出、项目 ID 或未来工作。冻结编码得到 1024 维向量，再拼接
16 项任务结构特征。只训练小型监督头，没有微调 0.6B 主干。

比较 59 条旧训练执行与扩展 77 条训练执行。岭回归正则和误差尺度使用
训练项目分组交叉验证；固定 12 条校准任务选择候选，只有选中者读取
18 条开发任务结果。开发组已在历次探索中重复使用，不是新的盲测。

### 档内条件语义预测

保留原模型三档概率作为门控，每档单独拟合语义连续工作量：

```text
q(O) = sum_b p(b | O) × E[M0 / (M0 + R) | b, 任务语义]
```

训练时真实档位只是监督标签；查询只使用原模型已经预测的概率。
条件分布限制在各档固定区间内。因此相同 `p_long=1` 的两条任务仍可
有不同的连续工作量，同时避免用较弱的新回归器推翻全部粗分类。
剩余限制是高置信度粗分类错误仍可能限制语义头的取值区间。

校准选中 59 训练版本，三档分别有 21/18/20 条完整训练执行；
77 版本的校准排序为 81.8182%，未选中。

| 指标 | 原分类＋训练档内效用 | 选中的档内 Qwen |
| --- | ---: | ---: |
| 校准初始排序，66 对 | 83.3333% | 86.3636% |
| 校准连续效用 MSE | 0.00645106 | 0.00604624 |
| 开发初始排序，153 对 | 62.7451% | 64.7059% |
| 开发连续效用 MSE | 0.01655394 | 0.01617965 |
| 开发 log-work RMSE | 0.553185 | 0.548196 |

开发排序增加 3 对正确判断，效用 MSE 下降 2.2610%。这是小幅改善，
不能称为语义模型已经能准确估计任务长度。这里的原权重已经换成训练
经验效用，与旧 `1/.5/.25` 下的 66.6667% 初始排序不是同一个指标。

真实 CPU 编码使用 BF16、SDPA、单线程、CUDA hidden。
首次编码 89 条训练/校准文本的 P50/P99 为 0.7184/1.5529 秒；
后续复用这 89 份向量，只编码 18 条开发文本，
P50/P99 为 0.8256/1.5664 秒；两次模型启动均约 2.15 秒。
尚未量化它对真实服务进程的 CPU/GIL 干扰。若后续接入，只能后台一次
编码并缓存；恢复入口不应同步等待这个模型。

## 真实调度现场的匹配审计

使用已经完成的 Host400、20 初始＋mean70、73 原项目实验记录，
固定 18 测量成员与完整尾部。先精确重放实际完整选择，
再替换工作量权重；候选、容量、成本、required JOIN 均相同。
完整池几何规划可行不等于现在就能物理分配。

同配置确认轮有 7425 个入口：6876 个没有可比搜索元数据，
41 个未完成搜索予以排除；剩余 508 个完整搜索中有 130 次跨 workflow
规划容量竞争。1891 个候选观测中，376 个使用初始先验，
1515 个使用进度条件树；其中 18 个不受支持的观测保持中性权重。

| 权重版本 | 相对树三档改变集合 | 按共同真实连续效用评价，改善/退化 | 130 次竞争包含真实最短者 |
| --- | ---: | ---: | ---: |
| 树三档 | 0 | 不适用 | 93 |
| 连续点预测 | 8 | 6/2 | 90 |
| 连续分布＋训练档内先验 | 10 | 7/3 | 90 |
| 连续分布＋档内 Qwen | 9 | 7/2 | 91 |
| 真实三档 oracle | 22 | 8/14 | 92 |
| 真实连续 oracle，共同工作单位 | 15 | 15/0 | 98 |

Qwen 相对无语义连续分布仅改变一处选择：将真实剩余 59596.65
的 background workflow 换成 32516.94 的另一个 background workflow。
它修复一个不利局部选择，但两者都不属于固定测量组。
仅看两侧均属于开发组的竞争，覆盖 17 个边界、24 个不同 workflow 对、
28 个配对观测：树三档与两种连续分布的边界等权排序均为 79.4118%，
尚未观察到这一人群上的排序提升。

同样的代码还对首轮完成记录做了交叉检查，没有重新训练或改变候选选择。
8368 个入口中，7796 个元数据不可比、42 个搜索未完成；
530 个完整搜索包含 145 次规划竞争。结果为：

| 首轮权重版本 | 相对树三档改变集合 | 按共同真实连续效用评价，改善/退化 | 145 次竞争包含真实最短者 |
| --- | ---: | ---: | ---: |
| 树三档 | 0 | 不适用 | 105 |
| 连续分布＋训练档内先验 | 18 | 12/6 | 104 |
| 连续分布＋档内 Qwen | 17 | 12/5 | 105 |
| 真实连续 oracle，共同工作单位 | 22 | 20/2 | 111 |

Qwen 相对无语义分布同样只修复一处，而且是相同两个 background
workflow 的替换，不是另一对独立任务上的改善。两侧均属于开发组的
22 个竞争边界、22 个不同 workflow 对、33 个观测，边界等权排序在
树三档和两种连续分布下均为 74.2424%。

以上“改善”仅指共同冻结代理目标在同一现场的值更高，不是新策略的
真实准入、后续服务或 JCT。全部 130 次竞争还包含训练任务；
不能将全人群排序准确率当作未见任务泛化。不能将多个边界累计成独立
样本，也不能把真实连续 oracle 的 15/0 写成理论 JCT 上界。

当前结果支持保留连续分布与档内语义候选，尚不足以推广为新的默认
GPU 配置。预测表示和组合目标需分别检查：即使权重更合理，原成本比值
仍可能优先选择便宜的长 workflow；不能承诺更换编码器就获得 JCT 改善。
