# 2048-token prefill 与持续到达的配对验证

日期：2026-10-29。状态：配置、队列及 CPU 回归已完成，新 serving profile
的 common GPU 资格通过，正式对照启动中，FULL 资格及完整性能尚待完成。
本文件不修改历史实验或用户维护的
`docs/design/native_demand_prefill_pipeline_20261028_zh.md`。

## 为什么先试分块

完整 mean120 FULL 的中段物理 KV 驻留率已达 99.48%，约 67.01% 不可
驱逐。500ms 免费逻辑准入补位把有完整逻辑 fit 的 inactive 请求从
133 降到 56，平均 JCT 下降 0.75%，但全程吞吐下降 0.59%，decode
worker 加权宽度从 8.108 变成 8.057。因此不推广这个参数，使用原
FULL 的 dispatch interval 0，保留已验证的安全修复。

物理占用高不等于有用活跃工作集达到上界，也不能证明 GPU SM 利用率高。
HBM 平均上下文及原生输入/增长预留限制了可持续 decode 宽度，不能仅
把 running24 当作能实际同时运行 24 个长上下文的承诺。下一步先检查
长 prefill 与 decode 的交错，避免用主动增加迁移来制造 handoff。

## 单一候选与配对边界

只更改共享 serving 参数 `chunked_prefill_size=2048`，mixed 保持关闭。
不同时扫描 1024、mixed、到达率或新调度策略。

## 实施与验收

配置及操作入口位于
`experiments/reports/prefill2048_mean120_20261029/`：

- `prepare.py` 只生成一对配置，逐字段核对原工作、工具计时、到达和方法
  参数，检查 dispatch0、工具/frontier 预取关闭。
- `run_cpu.py` 保留此前 4,760 个测试身份，加入准入审计、free extent
  字节记账和队列资格检查，绑定本次真实源码与原生树。
- `queue_pair.py` 先在 common native 上进行 24 个真实
  token/session/native-stop 检查和 sampler1/8/24 标定，再运行完整
  ThunderAgent。完整请求、两份新鲜空闲 telemetry 与实际 owned
  进程退出通过后，才在 FULL native 上执行同一资格及完整 FULL。
- 单独队列负责改变 shared serving profile 的序列，不放松原
  `after-registration` 仅允许相同策略环境的约束。canonical patch
  路径只在补丁、原生树与其他元数据完全相等后重新绑定。
- 两臂完整结束后使用现有相同 contract 的 reader 生成 JCT、全程输出、
  decode 趋势和分布。原生引擎差异明确记录。

不重采 native，不强制减少工作量，不删除自然长尾。最终还需核对真实
prefill 分块、输出守恒、恢复后的实际服务、H2D/D2H 与重算；不能把
更短单批或新增传输本身计为成功。控制开销没有完整测量时保持未知，
不能从一个小性能差值倒推出 CPU 根因。

最初 preparation 的 CPU-only 失败保存在
`preparation_failure_r1.json`：validator 错用 internal factory 处理
paper arm；改为与正式 operator 相同的 `paper_environment` 后配置生成
成功。该次未创建配置或 GPU 子进程。针对性 87 项检查随后通过。

`cpu_r1/evidence.json` 的一次实际执行通过 4,810 个测试与 6 个子测试，
保留此前全部 4,760 个测试身份，无失败、错误或跳过；1,952 份绑定
输入及原生 checkout 在执行期间保持一致。独立 CPU 前置检查也已确认
原 mean120 两臂和 500ms 候选的 3,674 个完整请求、排空及实际 owned
进程退出，并核对了新冻结路径所需的原生 canonical patch 重绑定。
这些是 CPU/source/退出证据，尚不是 2048 profile 的真实 GPU 资格。
