# 完整原题轨迹复用

当前用户要求为：优先复用已有完整原题 trace，只补采缺失的任务档位或不同项目；
模型工作量 P90/P10 的最低门槛为 **5**。此前临时采用 3 的准备记录保留，
但其 3.081 结果不满足当前门槛，不进入正式比较。

## 复用与时间口径

复用单位为整个原始 workflow，冻结全部请求 token、停止条件、invocation、
JOIN 依赖和真实工具时长。每个原始项目只出现一次；相同原题有多个采集版本时，
保留预先声明的代表，不选择恰好执行更短的版本。

并发与到达表不作为固定 trace 的兼容条件，不需要因此整组自然重采。
实时自然执行仍可能受工具资源竞争或共享工作区先后顺序影响；固定轨迹评测
明确冻结这些已记录行为。旧采集 JCT 不冒充新到达设置下的性能结果。

模型工作量继续使用 `0.01 * necessary_new_input + generated_output`。
长短分档另外纳入依赖图上的模型加工具关键路径：模型节点使用统一时间系数，
工具节点使用真实执行时长，串行累积、并行分支取最长路径。排队、框架编译和
未标注的外部间隔不纳入该工作量代理。不能将并行工具直接相加，也不能将
独立的最长模型路径和最长工具路径直接相加。

新增 `critical_model_observed_tool_proxy_s` 记录上述路径；历史
`critical_model_tool_proxy_s` 的外部间隔口径不变。模型倍率和含工具的路径
倍率分别报告，工具时间不能用于绕过纯模型工作量的 5 倍门槛。

## 已有库存

四批既有兼容采集共有 40 道不同原题、18 个不同项目，原题文本已与冻结清单及
数据集 scenario 校验。旧 scope18 的模型工作量 P90/P10 为 2.955。

按旧 3 倍门槛，一次完整原题替换即可得到 3.081，模型加工具路径代理倍率
为 3.221。该证据留在 `review_r1`，已明确标记门槛被替代；没有启动 GPU 比较。
当前 `review_r2` 使用 5 倍门槛，继续保留未选中的全部原题和完整尾部。
选择不使用 JCT、native 重算或 predictive 收益。

`review_r2` 未找到达到5倍的替换，明确记录为未达标。这40道已核验同协议原题
的模型工作最大/最小值也只有4.466，因此该部分库存即使忽略项目去重也不能
提供5倍的P90/P10，不能通过换一种排序方式宣称达标。相关CPU检查通过
30项测试和6项subtests。

入口为 `scripts/prepare_reused_workflow_mix.py`。只做 CPU 度量刷新，事件和
token 哈希、原有模型工作量均须与旧库存一致。当前无新增 GPU 任务。

此前运行的六原题采集已经完整结束，970个请求、145,508个输出token均保留，

工作P90/P10为3.666，仍低于5。33个child调用P50/P90为14/36、最大105；

root并行轮次中位数为1。该结果仍需改进，不能直接扩大或进入正式比较。

这些新增完整原题用于增量补足库存。不能仅因异构倍率
