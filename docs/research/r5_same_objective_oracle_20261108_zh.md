## 要解决的问题

已有 GPU Oracle 按含工具的剩余关键路径进行全局恢复排序；R5 则使用剩余总模型
工作三档概率做组合准入。两轮平均 JCT 相差 13.11 / 19.42 秒，不能全部解释为
预测误差。重复轮同状态分析有 145 次普通规划容量竞争：换为真实三档工作量会
改变 39 次选集，换为连续工作量效用会改变 29 次。它们都不是全程 JCT 反事实。

本次先验证真实三档，以保持现有 R5 效用映射 `1、0.5、0.25`。连续读出与
预测器整项目隔离诊断另行保留，不在本次同时变更效用尺度或放宽校准门槛。
这个试验衡量对应调度规则的真值效果，不是平均 JCT 的最优上界。

## 实现边界

新增显式产物种类 `workflow_model_work_combination_oracle_v1`，旧冻结代码会
拒绝该种类。产物声明使用未来模型工作、不可部署；阈值和完整容量 v7 成本配置
从当前 R5 模型逐值复制。来源中的请求、token、依赖和工具时间保持原样。

真值只用于共享组合选择器的权重，保持以下行为与条件分布 R5 一致：

- 周期选择及首次、续接、sibling 准入共用原组合选择器。
- 候选参考顺序、默认 6 / 按需 8 候选、0.5ms 搜索预算、效用加和目标不变。
- 普通准入窗口 2 秒、完整控制 2 秒、兜底 500ms、工具卸载检查 400ms 不变。
- 工具替换沿用原顺序；工作量不改变压力暂停对象，工具保留权重继续生效。
- 保留 JOIN/EOS 优先、预测工具卸载、prepare_host、连续性及 sibling 支持。
- 工具预取和逐层 handoff 保持关闭，原生物理容量、锁、传输 ACK 和选批仍有最终权威。

总工作真值为 `0.01 × 必要新增输入 + 输出 token`。进度只通过已观察的请求完成
和每 128 token 的原生输出观测扣除；不会按私有未来完成时间唤醒工具或请求。
该模式不计算未来工具路径。记录器必须明确写出其未使用未来工具时长。

Oracle 的进度更新是同步的，原学习模型在异步 worker 中更新，因此不能声称两个
提供器的记账开销完全一致。实际控制 CPU 及观测节奏需要随完整结果检查。
