# Handoff 覆盖、泊松到达与 prefill 候选

2026-10-29。本次审计保留 V230/V311 的完整工作量、全部正常尾部及既有
冻结实验。工具预取和普通 frontier restore 继续关闭，工具预测卸载门槛
维持 0.75，逐层 handoff 维持 D2H8/H2D4。没有改动正在运行的 TokenCake

## 零 handoff 对应哪轮实验

“本轮没有实际发生逐层 handoff”指同源码 FULL R2，不是最新完整 FULL
都没有交接。直接读取三轮完整机会日志得到：

| 完整运行 | 成功提交 handoff | 消费者恢复 GB | 原生拒绝日志 | 其中空闲页低于输入与增长预留 |
| --- | ---: | ---: | ---: | ---: |
| FULL R1 | 2 | 1.797784 | 9 | 9 |
| FULL R2 | 0 | 0 | 5 | 5 |
| ACK 修复 FULL | 8 | 4.787700 | 3 | 3 |

GB 采用十进制。逐轮历史日志和末次观测计数保存在
`experiments/reports/prefill_arrival_20261029/handoff_historical_audit.json`。
它是完整运行的日志审计，不是新 GPU 实验或新的性能归因。

R2 的五次原生拒绝均支持所用 cache，单页起点没有 Device/Host 锁，
当时写入/加载队列和 ACK 队列均为空；但有以下必要条件失败：

| 消费者缺失前缀 token | 空闲 token | 输入与增长预留 token | 预留缺口 token |
| ---: | ---: | ---: | ---: |
| 95 | 1218 | 4146 | 2928 |
| 9845 | 517 | 920 | 403 |
| 145 | 30 | 57 | 27 |
| 70 | 302 | 522 | 220 |
| 73 | 878 | 1420 | 542 |

当前原生交接复用 donor 的物理 extent 容纳消费者缺失的 Host 前缀，
额外输入和 decode 增长仍需要交接 extent 之外的真实容量。donor 超出
消费者前缀的尾部在 D2H ACK 前仍受保护，不能立刻计作普通空闲页。
这五项证明预留条件不足；不能据此声称其它祖先路径条件一定全部满足，
更不能删除保护来增加触发次数。普通卸载与 handoff 已使用同一
`consumer_input_reserve` 口径，保留空 adder 替换批次输入预留的修复。

R2 另观测到 378 次已落 Host 的私有节点释放，累计约 45.734461GB，
465 次原生需求恢复批次。前者不需要重新 D2H 后才能交接，后者主要
由已有的 demand pipeline 覆盖。它们不是 378 次独立工具调用，也不能
据此计算 handoff 的漏触发率。

历史较早退出的分支没有穷尽原因日志。R2 已有计数包括 11 次几何拒绝、
3 次私有 decode 尾部不匹配和 48 次选定输入预留检查，但分母不同，
不能拼成完整的 handoff 决策树。本次在原有有界尝试中补充明确拒绝计数：
资格、消费者成本、锚点数量与身份、Host 目的空间、donor 大小、成本授权、
原生拒绝等；没有新增周期扫描或绕过原生所有权规则。

交接成立也不保证净正收益。它只覆盖需要新增备份且容量受限的恢复，
还可能受到复制提交、带宽竞争及后续层等待影响。ACK 修复 FULL 的交接
仅约占全部 H2D 的 0.176%，不能期待单靠它解释或大幅改变完整 JCT。
更广泛地让 donor 尾部同时支持新输入，或组合多个 donor，是新的原生
容量与逐层依赖协议，不属于本次已实现范围。

## 75% 与 90% 的含义

当前门槛是以下条件生存概率，而不是预测正确率或总工具时长 P90：

```text
P(T > t + C | T > t, 可观察类别和已完成历史) >= 0.75
```

`t` 是工具已等待时间，`C` 根据新增 D2H、消费者恢复、donor 后续恢复、
维护裕量和必要逻辑交接成本估计。冷启动估计仍有显式下界；无真实容量
受阻消费者、无可靠尾部支持、原生锁或空间不允许时均不会因门槛通过
而强行卸载。当前合成工具场景利用可观察类别、离线互斥 prior、
在线完成历史和 elapsed，不知道本次抽中的未来工具完成时间。

本次保留 75%。90% 更保守，可能减少过早卸载，也可能失去更多可用冷页。
历史 75% 同时引入 Host 管理和 layer engine，不能从组合运行单独证明
75% 优于 90%；此前 3.91%/3.44% 的 JCT 改善也不是门槛单变量对比。
后续若做门槛比较，使用相同到达表、工作量和引擎，同时记录提前返回、
实际受益消费者、重复迁移、重算及完整 JCT，而非仅比较卸载次数。

## 68.55% 不是 GPU 利用率

该数来自
`tool_offload_before_admission_complete_20261027_zh.md` 的 KV 表：
ACK 修复 FULL 在第 300--1800 秒区间，不可驱逐页占 KV 池的时间加权
均值为 68.55%；同表驻留为 99.44%，可驱逐为 30.89%。

不可驱逐包括锁、引用和在途传输，不能等同于执行中的热 KV；
可驱逐也不证明一定冷、已备份或能零代价释放。这批完整运行没有连续
NVML/SM 采样，不能以 100%-68.55% 推算计算空闲，更不能承诺对应的
JCT 提升。现有 prefill/decode worker 区间包含等待与运行时，也不是
独占 kernel 忙碌时间。

## 新到达与计时契约

已实现并生成独立 seed21 的 λ=0.2、0.35、0.5 workflow/s 到达表，
同一表供所有方法复用，随机序列不依赖模型或调度器随机状态。
相邻间隔为指数分布；不是每个 workflow 独立抽一个时间后排序。

| 到达率 | 第一个到达/s | 第 18 个到达/s |
| --- | ---: | ---: |
| 0.2 | 0.901315 | 58.689983 |
| 0.35 | 0.515037 | 33.537133 |
| 0.5 | 0.360526 | 23.475993 |

到达表位于同实验证据目录的 `poisson_*_seed21.json`，含全部 workflow
身份、offset 与 SHA256。只改变 root 外部释放，不改变请求、token、
workflow 内部工具时间、SPAWN/JOIN 依赖、停止方式或工作量。
未到达的事件不发送给在线调度器。

JCT 从计划到达时刻计至正常 WORKFLOW_END，保留计划释放后的 driver
迟到、局部准入和 KV 恢复等待。事件单列实际投递与迟到时间；结果审计
还逐项核对原始开始事件是否符合冻结表，不能仅填写一个相同摘要。
当前不允许将此模式与 AgentX idle timer 压缩同时使用。

完整输入轨迹仍可复用，无需重新自然采集。原 burst JCT 不是新泊松
到达的配对控制，因此新注册不再暴露它为可比 native baseline；
同 chunk/mixed 配置的 fresh model check 仍是必要条件。
当前工具衰减 ThunderAgent 等旧结果全部保留。

原 burst 对比在各方法到达相同时也是公平的；泊松扩展到达模型的覆盖。
18 个长 workflow 在本表下几十秒内全部到达，不能自动称为稳态负载，
也不能以这一个种子实现的到达跨度替代名义 λ。

## Prefill 已完成的代码与边界

以下是 CPU 实现，不是新完整 GPU 性能结果：

1. 共同服务入口接受 2048/1024/4096 分块及原生 mixed 开关。位置/采样
   资格与正式入口逐项验证实际服务参数，不能复用 4096/mixed-off 的
   GPU smoke 冒充其它配置。其它模型、容量和调度参数保持共同契约。
2. mixed extend 使用原生 `decoding_reqs` 标识 decode 成员；保留 prefill
   输入统计，另记实际输出增量。分析同时包含纯 decode 和 mixed 内的
   decode，并按请求连续输出 ordinal 与完整回执检查所有相位输出守恒。
   mixed 的完整 worker 区间只计一次共享时间，不能与 prefill 时间相加，
   也不用普通 decode CUDA Graph bucket 推算其 padding。
3. demand pipeline 现在可暂存第一次 chunk 的正常原生 Host 恢复，在
   ACK 后重新运行原生选批，再建立 chunk owner。保留全部选定成员、
   原生 lock receipt、session/attempt、共享前缀 fence 与取消路径。
   已持有 request row 的后续 chunk 仍走原生路径，不声称覆盖全部 chunk。
4. 已准备 `chunk2048.json`、`chunk1024.json`、`chunk2048_mixed.json`，
   默认配 λ=0.35 的同一到达表。它们未登记 GPU 实验；先验证
   2048/mixed-off，再依据结果选择 1024 或单独的 mixed，避免展开网格。

真实 native CPU 选批用例覆盖初始 chunk 暂存、ACK、重新准入和请求行
生命周期；复制/事件使用 stand-in。mixed CPU 证据覆盖未产出 token
的中间 chunk、首 token、mixed decode 和零输出终态步。
这些不能代替真实 DMA、模型数值和完整 GPU 实验。

实际源绑定 CPU 回归共 4189 项通过，保留此前全部 4102 个 literal case
身份，另有 6 个 subtest 通过，绑定 1828 份应用输入；初轮 600 项报告也
保留。原生测试执行于 prepared patch 工作树，后续独立核对其 canonical
tree 与干净 `729aa0caa7a1` 完全相同；该绑定不是重新执行 CPU 用例，
也不是 GPU 资格。证据位于同目录 `complete_cpu.*`。

已就绪短续接的新组选批规则和自适应 decode 宽度尚未增加。下一轮保持
running/decode24；先验证分块与 mixed，再决定是否需要新的组批机制。
上下文平均长度与容量使 24 只是上限，不能强迫 24 个独立长上下文同时
常驻来改善表面的 batch 指标。

验收继续使用全部 workflow 的平均/尾部 JCT、全程输出吞吐和服务间隔，
同时核对 CPU 成本、实际 mixed 服务、H2D 等待、重复复制与旧输入重算。
通用分块/mixed 优化不计作 agent 调度创新。整体优化目标仍未完成。
