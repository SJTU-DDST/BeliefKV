## 实际结果

最初一阶段保留 73 个不同原项目、43 条训练 workflow、12 条校准 workflow

再评价被选模型和原模型。由于这组开发评价结果已经在探索中多次使用，
它不是新的确认性测试或未见项目泛化证据。

## 设计与成本

先验仅编码显式任务说明，最多 4096 字符。使用固定版本
`sentence-transformers/all-MiniLM-L6-v2`，revision
`1110a243fdf4706b3f48f1d95db1a4f5529b4d41`；权重与 tokenizer 文件逐一
绑定 SHA256，使用本地 safetensors、CPU 和关闭远程代码的加载路径。
长说明分段编码，保留后面的段落，另加入 16 个由任务文字计算的结构特征。
没有输入完整 prompt、源码、工具输出、项目 ID 或未来执行信息。

总工作量的对数先验采用小型岭回归，正则强度由训练组整条 workflow
的 leave-one-out 误差选择；均值偏差与尺度只用校准组拟合。选中候选
在实际模型服务尚为零时，以 .5 权重结合原模型。必要新增输入或输出
一旦实际获得服务，立即完全使用原进度模型，不再持续混入初始先验。
预测仍只提供概率，不用 argmax 直接替换组合准入。

实际后台 worker 已对 18 条评价任务发布与离线相同的初始概率，无错误；
每条任务只编码一次。该次 CPU 观察中，模型预热一次约 4.30 秒，18 次
任务编码累计约 2.17 秒线程 CPU，平均约 120ms/任务；缓存推断和支持
检查 P50/P99 约 0.056/0.070ms。预热在后台线程完成，调度器不等待推断；
这是组件成本，不是完整控制平面或 GPU 干扰测量。证据为
`r5_initial_work_prior_r1/actual_worker_and_cost.json`。

同时修正缓存时间戳：有效期和下一次刷新从实际推断完成时起算，避免
较慢的首次编码使新预测发布时就已过期。结构版本、队列积压、任务结束
和失效回退规则继续生效。

## 委派输入的因果检查

旧 R5 只使用角色类别计数和委派文本长度，没有使用委派内容。新增的
独立输入模式只拼接已经观察到、尚未返回的至多 8 个 child 的角色与
委派说明，分别保留已有 128/512 字符上限。只在文本版本变化时重新编码；
不会因每个 decode token 重做任务编码。原模型读取单独的 `task_text`，
不因新导出多了委派列而获得额外输入。

新导出保留 53890 个原快照，其中 41500 个可以加入当时可见的委派。
全部原数值特征、工作量标签、原始任务、task template 和快照边界逐项
相等，所有旧来源哈希继续保留。新版额外绑定了原本已声明的 token 包与
tool overlay 哈希。失败的一致性检查源于 Python tuple/JSON list 比较
以及来源清单新增两项，不是实际原始特征变化；失败记录和未验证导出均
保留，修正证明见 `r5_observed_delegations_r1/export_validation_correction.json`。

SPAWN 前的快照没有该 child 的说明；RETURN 后将其移出未完成委派摘要。
离线训练和概率评价都按 `(workflow, 已观察文本版本)` 缓存投影，不能
把最后一次委派内容用作整条 workflow 的静态输入。源码已有针对这些
因果边界、对照输入隔离、缓存更新与父导出绑定的回归测试。

## 结果边界

53890 个快照只来自 73 条独立执行，本轮训练实际只有 43 条独立任务；
后段近完成快照使全进度准确率显著高于初始和前段准确率。增加模型容量、
更换表示或增加相关快照，都没有自动解决独立训练样本和任务信息不足。
上述尝试不证明该方向没有潜力，也不能把轻微排序改善包装为准确率问题
已经解决。

本轮标签仍为 `0.01 * 必要新增输入 + 实际输出` 的剩余逻辑模型工作量，
不是剩余墙钟时间或 GPU 秒数。并行工具的剩余时间仍由独立路径处理，
没有将未知的未来工具采样时长作为线上输入。与包含工具关键路径的
oracle 的差距还需要单独评价。

227 项相关 CPU 检查通过，包含原有模型、条件分布、实际准入接口、旧
输入兼容、源标签守恒、真实 worker 生命周期以及新增候选的检查；
未重复全量历史回归、Host 池资格或 GPU 性能对比。没有新的 JCT 结果。

## 实际竞争候选审计

新增只读审计 `scripts/audit_live_work_prediction.py`，用已完成非排序
Full 的客户端事件发布时间和原生 128-token 进度重建当时可见特征。
完整未来工作量与已记录 oracle 路径只作标签。1887 次控制中，193 次
存在应用 ready、窗口允许且逻辑容量不能全部容纳的跨 workflow 候选。
2026-11-02 后续审计发现，旧脚本错误地用原恢复类别零识别受保护 JOIN；
该类别实际也表示普通连续推理。修正版只在已声明 global-rank 契约下，
使用排序值零识别 JOIN 保护，普通排序值必须至少为一。调度实现没有
这项错误；它影响的是离线评价人群和旧报告的解释。

修正版 1572 对观测中，15 对涉及受保护 JOIN，15 对缺精确选择器元数据。

固定开发组的有效观测有 89 对，覆盖 48 个边界、42 个不同对。这些是
重复边界观测，不等于独立样本数。

不能严格称作“尚未发生首次 GPU 服务”。

## 增加独立训练项目与排序目标

随后复用先前已经自然采集、但没有进入当前 73 项目 workload 的 16 条
完整原始 workflow。选取规则是所有已声明且不属于现有数据集的原项目，
没有根据工作量、JCT 或预测结果筛选。新增 16 个项目和 10098 个快照，
使预测数据共覆盖 89 个项目，训练从 43 条增加到 59 条；固定 12 条校准
和 18 条开发 workflow 的全部快照保持不变。新增项目、任务模板和执行
指纹均与原数据集不重合。正式 GPU workload 仍是原来的 73 条，没有
改变任务、到达表、token、依赖、工具时长或测量成员。

扩展标签从已有源绑定 oracle 文件导出。未来请求只提供离线监督标签，
输入仍是显式任务与已观察进度。训练固定原有工作量门槛
`[13062.96, 22971.15]`，避免增加短任务后移动类别边界而产生表面提升。
数据与导出清单位于 `r5_training_extension16_cpu_r1/`。

以相同 128 宽度进度 MLP 为基础，训练阶段增加跨 workflow 的排序损失：
对不同 workflow 的初始状态和三个离线进度阶段分层取有界样本对，优化
`p_short + .5*p_mid + .25*p_long` 与剩余工作量的顺序。取样先均匀选择
workflow，避免长轨迹贡献更多配对权重。阶段、差值和方向都是离线标签，
不会成为线上输入。排序损失系数的固定候选为 `.1` 和 `.3`，校准组在
原有支持与误判门槛下选择 `.1`；没有增加推断网络大小、线上模型依赖、
新事件或周期控制。

### 实际竞争与后台成本

修正版的实际竞争结果见前表。59 训练＋排序在全部有效配对上，边界
等权模型排序为 83.5962%，原模型为 83.6358%；不同对等权为 84.1732%
和 84.7558%。模型加工具路径边界等权为 81.5881% 和 81.1813%。
开发组边界等权由 79.3056% 到 80.0000%，不同对等权由 80.9921% 到
79.5635%。因此不能声称排序目标改善了所有真实竞争指标。

候选目录下原 `actual_competition_quality.json` 使用错误 JOIN 排除
人群，保留为历史证据，以上结果以 `corrected_global_JOIN_rank.json`
为准。自然源初始 153 对的指标不受这项修正影响。

实际后台 worker 已对 18 条任务发布与离线一致的初始概率并正常退出。
本次 CPU 观察中，18 次任务编码累计约 49.56 ms 线程 CPU，缓存推断和
支持检查的 P50/P99 约 52.51/159.07 微秒；这是组件观测，包含同时进行
CPU 学习时的运行环境，不是完整控制平面、原生事件接收或 GPU 干扰证据。
该候选没有语义编码器，也不增加线上推断网络规模。

### 未保留的后续候选

浅层多分类树与对数剩余工作量回归，分别在 43 条和 59 条训练任务上
尝试 4/8 叶子、原模型混合及校准概率。全部未通过原有校准门槛，主要是
long→short 过高。训练库分数与可移植树计算逐项核对，说明不能简单归因
于导出错误；它们没有加入生产预测路径。代码和失败证据保留在
`r5_progress_tree_cpu_r1/`。

另外测试了在尚无已观察逻辑工作量、也没有已观察 child 时，统一使用
任务估计，避免仅请求注册导致概率变化。训练与推断使用同一变换，门槛
仍依据已观察粗粒度工作量，不能解释为首次 GPU 服务。该候选的开发
初始排序只有 62.0915%，全进度分类 74.9701%，低于保留的排序候选，
未采用；保留 `r5_expanded59_stable_initial_cpu_r1/` 和显式模型输入契约。

这些结果支持继续增加有效训练任务、针对实际排序目标学习，并按阶段
检查误差；不支持单纯增加模型容量就能解决当前信息与样本限制。

本阶段最终针对性 CPU 检查共 178 项通过，没有失败、错误或跳过，覆盖
旧模型兼容、输入与进度契约、训练划分、固定门槛、排序监督、实际 worker
及封闭竞争审计。报告为排序候选目录下的 `final_targeted_cpu.xml`。本轮
预测器工作没有新增 GPU 运行或修改正在执行的冻结 ThunderAgent 对照。
