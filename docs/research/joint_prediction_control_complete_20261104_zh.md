## 改动与归因

本轮同时采用：

- 最新条件树工作量预测，继承原初始语义和条件进展输入。
- 显式 v7 纯收益组合目标，容量、槽位、输入和增长保留为约束。
- 工具替换需求复用、普通 hint 刷新合并、donor 预筛、settled Host
  释放计划快路和同调用内计划复用。
- 工具后台重试间隔 400ms，真实资格与容量事件仍能立即重新检查。
- 盈利性控制余量固定 400ms，不随重试间隔一起放大。

JOIN/EOS 预取、工具预测卸载、prepare_host、agent 连续性与 sibling 支持保留；
工具预取和逐层 handoff 仍关闭，工具 survival 门槛 75%。
连续工作量权重、额外语义模型和新的 JOIN 余量准入没有上线。

**该结果不是只改变工作量排序的消融，也不是 JOIN 余量策略的收益。**
它说明联合候选在这一轮达到相对非排序 Full 约 1% 的描述性目标；
尚不能单独归因于预测、取消分母、重试间隔或同步控制削减。
全局 goal 的“可重复”和独立短 workflow/oracle 贡献仍未证明。

授予、资格保留和正进展，不用后来其他授予代替原选择。

完整运行的新 episodes 包括 41 个周期恢复、25 个直接事件补位。

这些是 episodes，不是 66 个互不重复的 agent 或独立 JCT 样本。

旧两轮分别为 117.907、131.920 秒；全程跨度和工作状态不同，不用全程差值
冒充相同窗口或独立重试间隔的收益。

旧两轮授予为 153、155 次。这些计数不能证明可继续无条件降低检查频率：
真实事件与例行重试、容量条件和队列状态仍需分别核对。

组合元数据加选择的线程 CPU 全程计数约 2.560 秒，
共同窗口约 1.336455–1.336504 秒；它不是全部同步控制成本。
CPU 区间可能与 GPU 重叠，不能将减少的线程秒数直接作为可消除 JCT。
