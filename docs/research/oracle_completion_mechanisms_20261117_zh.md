# Oracle 完成期机制与后续准备

2026-11-17 的同一次简化 Oracle 已完成 fixed18，自然 JCT、2991 个
测量请求、362157 个测量输出、实际池容量、fresh drain 和进程退出均已
验证。平均 JCT 1276.770573 秒，对照 Full 1274.833468 秒；
共同窗口输出吞吐下降 2.663618%，没有达到验收目标。
本记录补充完成期的机制证据，不注册新 GPU 实验。

## 竞争是否作用于测量组

原 `complete_diagnostics_r2/global_choices.json` 的全局选择与服务审计
保持原样。新的只读分析逐一核对全部 2906 个原始选择时钟、候选身份、
原预算和所选集合，再按原固定阶段统计；不重新定义测量成员或窗口。

| 周期决策指标 | 固定共同吞吐窗口 | 首条测量到达到最后测量完成 |
| --- | ---: | ---: |
| 完整周期控制数 | 655 | 2867 |
| 控制前 application-ready 快照中的逻辑竞争 | 88 | 489 |
| 实际选择器候选中的逻辑竞争 | 88 | 486 |
| 实际竞争中包含可独立放下的测量组候选 | 46 | 198 |

| Oracle 改变局部准入集合 | 46 | 258 |
| 集合改变且新选入测量组成员 | 13 | 38 |

| 改变后选择更少成员 | 14 | 57 |
| 改变后选择更多成员 | 1 | 13 |
| 剩余逻辑预算可再加入未选候选却未加入 | 0 | 0 |

完整跨度内，290 个新选请求只有 39 个属于测量组，覆盖 13 条测量
workflow；这 39 个中有 33 个在下一次控制或同 agent 干预前获得新的
有效服务。全负载的 258 次集合变化不能全部当成 fixed18 的直接改善机会。
共同窗口后的大量竞争涉及背景任务，不能把背景已经完成的条件样本
替换成新的主 JCT 分母。

选择器候选和控制前 application-ready 快照是不同口径：完整跨度内有
25 次控制的可独立放下候选数不同，逻辑竞争数相差 3。
原快照计数继续保留为 489，实际候选计数为 486；二者都不证明原生物理
容量可行。初版分析误要求两者相等并停止，原失败说明保留；
修订版分别校验实际选择人口和原控制快照人口，没有放宽原生权限。

这里的“更少成员”指局部恢复集合，不等于实际 decode 并发一定变少。
未发现可直接追加的逻辑可行候选，说明该贪心选择已经是当前顺序下的
极大集合。要进一步提高成员数通常需要替换已选成员，不能描述为免费
填空，也不能悄悄以最大基数或效用加总替代用户要求的短优先 Oracle。

## 服务宽度与执行成本

复用同一只读分析器，分别核验完成 Full 和完成 Oracle 的完整原生工作，
再读取同一个冻结墙钟窗口。decode 几何按 forward 开始时刻归属；
正式吞吐仍按输出完成时刻归属，两个分母不能混用。

| 共同窗口指标 | Full | Oracle |
| --- | ---: | ---: |
| decode 批次数 | 29911 | 30123 |
| 平均 decode batch | 15.513958 | 14.995651 |
| 每批平均 worker 区间，ms | 26.390271 | 26.295705 |
| 观测平均上下文 token | 36818.629339 | 37171.304748 |
| 需要 graph padding 的批次 | 0 | 0 |
| active-ready 时间加权均值 | 17.278170 | 16.265371 |
| ready-paused 时间加权均值 | 3.569061 | 3.942730 |
| continuation ready-paused 时间加权均值 | 1.877605 | 2.233818 |
| supply 采样有效覆盖 | 97.963995% | 97.190340% |

批次数增加约 0.709%，平均宽度下降约 3.341%。decode 输出的恒等分解为：
批次数比例 1.007087693 × 平均宽度比例 0.966590930 × 每 request-step
输出比例 0.999871232 = 输出数量比例 0.973316482。
这是已观测批次的代数关系，不是对规则的因果归因或可移除 JCT 上界。
供给均值按各自有覆盖的区间计算，超过 1.5 秒的缺口保持未知；
没有把不一致的缺测区间填零或插值成精确配对。

结合前述控制成本增加，后续应检查选择、恢复与迁移如何影响实际工作集
和 batch 宽度。不能把全部新增线程 CPU 都换算成暴露 GPU 等待；
worker 区间也不是 CUDA kernel 利用率。

同一完成期前缀检查中，Full 有 16157 次 probe，Oracle 有 16273 次，
该诊断的 missing previous-input-prefix token 均为 0，测量组支持的旧
前缀额外 prefill token 也均为 0。这不代表全部重算为零。
原生 Host-block 归因另有非零重算字段，且全运行背景执行量和观察时长
不同，不能直接把累计差值解释成 Oracle 对 fixed18 的重算代价。

ready/JOIN/tool-paused 完整曲线仍保留在原 Oracle 的
`complete_diagnostics_r2/paused_timeline/paused_agents_over_time.png`，
以及配套 PDF、两个逐点 CSV 和输入绑定。曲线已实际查看，未截去尾部。
