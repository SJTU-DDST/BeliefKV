# 完整控制成本诊断与准入前卸载对比

当前不能把服务到完成的回退主要归因为新增控制开销。历史比较没有
完整控制线程 CPU 计时；新诊断确认存在较贵的准入及 prepare 路径，
但没有提供历史增量、逐次 forward 推迟量或可直接从 JCT 扣除的成本。
服务交错、批次组成和额外迁移仍是需要优先核对的解释，尚非因果结论。

## 先区分原始问题与新诊断

用户提到的 24.981494 秒来自准入前卸载 `716ef9a3e4ad` 对旧分组
`913e3238b84b`：2973 个关键工具后继的首次服务至完成区间求和，
再按 18 条 workflow 等权平均。原始分解为 prefill -0.687349 秒、
decode +14.601518 秒、请求成员区间之外 +11.067325 秒。
不能把全部这些区间视为控制 CPU、纯 kernel 或独占传输时间。
旧两轮共享控制 profiling 均关闭。

原始完整 decode worker 区间总和反而减少 20.430434 秒；按实际 batch、
2048-token 上下文档和 CUDA Graph 状态匹配、每侧每档至少 32 批时，
worker 均值差约 +0.027233%。这不支持普遍 decode 明显变慢，
但没有排除批次之外的控制成本。旧 23 次 handoff 的原生 pair submit
到 journal wall 总和仅 22.954346ms，也不能单独解释 24.98 秒；
它没有计入候选规划、失败检查及后续异步成本。
完整旧证据见 [原始控制核对](control_cost_vs_preadmission_20261028_zh.md)。

两次新鲜 idle 快照、原始退出零和实际 owned 进程退出均通过。

以下为末次记录快照中实际测到的 inclusive 线程 CPU 样本，顶层每 64
次采样，后代继承该决定，嵌套 exclusive 数据另外保留：

| JOIN prefetch | 19 | 0.610352 | 7.513467 |

末次快照 `final=false`。维护入口共观察到约 214 万次调用，其中有空闲
轮询和退避快路径；不能称为 214 万次物理扫描，也不能以很小的最终
均值排除累积影响。相反，样本最大值和较贵 prepare 路径说明仍需优化。
这些样本没有倍乘外推，不能相加为整轮独占成本，更不直接等于 GPU
暴露空闲或历史新增控制成本。后续真正需要的是控制工作是否推迟下一次
有效 forward，以及服务交错与额外迁移分别发生在什么关键请求上。

## 物理计划与迁移的发现

89 次有界 JOIN 物理尝试逐项核对到同前缀计数：59 次无安全 donor、
18 次已无缺失、6 次消费者失效、3 次实际容量已足够、2 次发备份等 ACK、
1 次真实释放，共 174 token。73 次节点检查中 69 次停于非驻留节点；
55 次工具 donor 引用继续走预测路径。这些计数没有独立机会分母。

这里发现并在 main 修复了一个真实集成缺陷：Host-only 尾节点上方仍可能
存在原生允许释放的私有 Device 前缀；旧遍历提前停止，同时不接受内部
节点没有叶 session 标签的原生表示。详见
[祖先回收修复](../design/join_host_tail_ancestor_reclaim_20261028_zh.md)。
修复提交 `a3d38d23` 已通过 3705 项及六个子测试的完整 CPU 回归，
未进入本次冻结 GPU 实验；实际出现频率及性能影响仍未知。

本次 H2D/D2H 分别为 2868.361986/1277.110911GB，高于准入前卸载。
两个实际 8/4 handoff 恢复 3.272245GB，与上述 JOIN 计划真实释放分开核算。
1037 条 JOIN 命令均有 version2 复用证据，共 227.702637GB；
63 个已观察预取 JOIN 事件中，26 个有完成前启动并复用，共 126.322606GB。
复用量增加不等于净 JCT 收益。

全部 1045 条 sibling 服务记录、1058 个请求准入尝试有实际批次及完成
session 证明，包括 13 个多成员 prefill 批次。257 次逻辑 grant 对应
260 个 program 服务关联，其中 258 个验证、2 个仍未证明身份；
不能把共同服务记录或 grant 次数当作独立 JOIN 或收益分母。
36 个恢复等待采样累计 3055.029ms，V345 的 18 个样本为 2662.835ms；
cohort 不同，均不外推整轮等待或直接计算收益。
