# 在截取候选窗口之前比较工作量

缩短 workflow 到达间隔，是为了让多个真实 ready-paused workflow 在额度
不能容纳全部对象时形成选择，并使短优先改变准入、实际服务和完整平均
workflow JCT。paused 数量、重复控制次数和实验次数都不是验收结果。

## 已完成的同负载结果

本轮为 100 个不同原项目、20 个初始 workflow、平均 60 秒泊松到达、
400 GB Host、固定 18 个测量成员。复用已经完成的非排序 Full；不回到
70 秒，不截断任何测量成员的自然尾部，不向策略公开测量组身份。

| 完整测量结果 | 非排序 Full | 短优先 Oracle |
| --- | ---: | ---: |
| 平均 JCT，秒 | 1258.540519 | 1256.498150 |
| 共同窗口输出 token/s | 340.056146 | 337.647300 |

Oracle 平均 JCT 仅降低 0.162281%，11 个成员改善、7 个退步。共同窗口
输出吞吐下降 0.708367%。相同 2991 个测量请求、362157 个输出 token、
新鲜 idle drain 和实际进程退出均已独立验证。该结果没有达到约 1% 目标，
背景到达也没有覆盖整个测量尾部，不构成正式稳态结果。

完整测量跨度有 443 个跨 workflow 逻辑容量竞争边界，197 个涉及测量
成员。208 次局部集合变化产生的 212 个新增授予均有实际原生服务，
201 个在下一控制或干预前得到服务。不能再仅以低并发或选择未进入
服务解释低收益；逻辑竞争仍不等于所有替代集合通过物理检查。

## 候选截取的缺口

旧代码先保留 reference，再从按恢复类别、KV 大小等排序的既有队列前缀
补齐 6 个候选，随后才按 workflow 工作量选择。因此，较短 workflow
可能在工作量比较之前就被截掉。候选数量上限是开销约束，不应变成另一
套隐藏的工作量偏好。

在已完成 Oracle 日志的 103 个控制边界中，有 160 次单独满足逻辑容量的
窗口外观察。使用前后两个原生 Oracle 状态中完全相等的单调剩余工作计数，
可严格确定其中 155 次的工作量；另 5 次保持未知。36 个边界有窗口外
对象比至少一个已选成员更短，其中 5 个边界涉及 4 个测量 workflow。
这证明有候选覆盖缺口，不证明这些对象通过原生前缀、物理容量、锁、
DMA 或 required JOIN 组合检查，更不是 36 次可独立相加的 JCT 收益。

原始证据位于现有实验目录的
`short_first_execution_r1/admission_gap_audit/window_work.json`，没有新建
GPU 实验版本或改写原始数据。

## 修复边界

只在已经显式启用 `shortest_work_first_admission` 时，对本次已经收集的
逻辑候选先比较 protected JOIN 与缓存的工作量权重，再截取可选窗口。
单独逻辑额度不足的可选对象不占用前缀检查名额。reference 始终保留，
未知预测沿用原有中性权重和稳定顺序。

保持 6 个普通候选、8 个 sibling 候选、原有 0.5 ms 选择软预算、容量
与增长预留、短工具保护、JOIN/EOS 权利、active 连续性及原生物理检查。
模型参数、工具时长和到达表不变。只查询已缓存预测，不增加同步模型
推理；日志仍只序列化实际候选的预测，避免扩大每条选择记录。

CPU 集成检查使用同一运行时中的 11 个 ready workflow，在 shared
boundary 打开前收齐请求。两侧均使用短优先选择器，只切换候选截取
顺序；旧窗口遗漏较短对象，新窗口改变实际逻辑 active 集合以及原生
prefill 候选。该检查使用 CPU 原生容量替身，不是 GPU 服务或 JCT 结果。

最终相关 CPU 回归 210 项全部通过，3.27 秒，无失败、错误或跳过；
JUnit 为同一证据目录的 `candidate_cpu_focused_r4.xml`。既有窗口已被
reference 填满时直接返回，避免无用预测查询。该结果只覆盖相关 CPU
路径，不替代新 serving 源码的完整冻结资格或 GPU 性能验收。

下一次 GPU 验证复用同一 Full 和固定 18 人口，只验证这一批已合并修复。
若仍缺少完整 JCT 收益，再依据容量积累、服务成本和实际选批证据调整；
不以继续增加积压或更换测量成员来代替设计收益。
