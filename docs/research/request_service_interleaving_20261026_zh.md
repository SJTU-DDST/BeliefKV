# 服务开始后的完成时间与 agent 准入

本轮只读审计完整的 v232 ThunderAgent、v232/v233/v235 Full。
所有实验仍为同一 v230 源的 3674 个请求、549671 个输出 token，
逐请求核对 prompt/output 哈希和原生停止条件，保留全部正常长尾。
GPU 预约截至北京时间 2026-10-27 11:00，本轮未启动或登记 GPU。

## 请求生命周期分解

新增 `scripts/audit_request_service_interleaving.py` 使用同一单调时钟下的
实际提交、scheduler.run_batch 入口、记录的 worker 区间和 native 完成。
逐请求将成员区间裁切到真实生命周期并取并集，避免重叠重复计时。
重叠调度的 descriptor 可能继续包含已经完成的成员快照；这些样本全部
保留，并单列越过完成边界的数量和时长。没有把尾部快照当作额外输出。

本统计的精确关系是：

首次 launch 至完成 = 生命周期内成员 worker 区间并集 + 其余区间。

worker 区间沿用原遥测的 `max(launch, previous_complete)` 起点，
不把重叠提交区间当作 CUDA 执行时间。“其余区间”也包含遥测的重叠
记账间隔、结果处理及其他 runtime 等待，不能称为 GPU 空闲、抢占、
传输等待或可直接消除的 JCT。prefill/decode 的独立并集可能重叠，
因此通常不能直接相加；本次四组实际跨阶段交集均为零。

输出为 `v244b_request_service_interleaving_complete_cpu_20261026.json`。
它重新匹配 v243 完整 JCT 路径报告的全部输入前缀和每条路径时长。
较早的 v244 报告保留；最终版明确使用 `_s` 键表示秒，并增加尾部诊断。

| 实测末完成路径分量，workflow 等权均值，秒 | ThunderAgent | Full v232 | Full v233 | Full v235 |
| --- | ---: | ---: | ---: | ---: |
| 提交至首次 launch | 634.203 | 605.855 | 503.576 | 443.912 |
| 成员 worker 区间并集 | 526.042 | 524.175 | 603.718 | 666.885 |
| 首次 launch 后的其余区间 | 100.075 | 107.071 | 137.969 | 154.402 |
| 其中 prefill 成员区间 | 20.703 | 20.576 | 21.031 | 21.420 |
| 其中 decode 成员区间 | 505.339 | 503.598 | 582.686 | 645.465 |
| 完整 workflow JCT | 1339.764 | 1316.524 | 1324.729 | 1344.922 |

v235 相对 ThunderAgent，首次 launch 后多出的约 195.17 秒中，
约 140.84 秒属于成员 worker 区间，约 54.33 秒属于其余区间。
各 arm 的末完成依赖路径可以不同；该表不是单模块因果消融。

对固定的全部 3674 个请求比较，提交至首次 launch 均值由 3.131 秒降到
2.192 秒，首次 launch 至完成由 3.348 秒增到 4.341 秒。排队改善没有
转化为明显的请求平均完成时间改善。全程输出吞吐提高和平均 JCT 改善
必须继续分别验收，不能只根据更宽的 decode batch 选择配置。

## 相同 decode 形状的检查

复用已有 `audit_decode_transfer_envelopes.py` 完整比较 v235 和
ThunderAgent，结果为 `v244_v235_decode_geometry_transfers_cpu_20261026.json`。

按 batch size、上下文总量/最大值分桶及 CUDA Graph 状态匹配：

- 全体匹配样本加权 worker 均值为 11.410ms 和 11.392ms，差约 0.158%。
- 稳定同成员、位于记录的 H2D/D2H submit-to-ACK 包络之外的匹配样本，
  均值为 10.821ms 和 10.798ms，差约 0.210%。
- 相同请求、相同输出位置的 12910 个包络外 singleton 样本，均值为
  5.618ms 和 5.613ms，差约 0.073%。

包络覆盖只是对记录 Host 传输的保守排除；它不排除 D2D、CPU 开销或
未记录动作。上下文分桶不是精确相同张量，条件样本也不是全部 forward。
因此不能据此认定唯一根因或估算可节省的 JCT。不过，与现有 decode
均值从 4.932 扩大到 6.418、总 worker 区间从 1652.57 秒减少至
1518.03 秒的事实结合，证据更支持优先审查准入与完成次序造成的
服务分摊，而非把全部完成时间增加归于同形状执行变慢或 H2D。

## 委派阶段的组成

另对原自然源的全部请求核对客户端事件和 native 完成时钟，结果为
`v244_v230_delegation_phase_work_cpu_20261026.json`：

- root 生成全体输出的 34.384%，其余由 child 生成。
- 首次任意 JOIN_WAIT 前完成的输出占 7.652%。
- 首次至少两成员的 ALL-JOIN_WAIT 前完成的输出占 69.916%。
- 首次并行 JOIN_WAIT 前 root 提交模型请求的中位数为 36.5。
- 72 次 root JOIN 中，20 次至少有两个成员。

这说明单 child 委派较早，而并行汇合较晚；不能把该源描述为大部分
工作都发生在第一次委派之前。首次并行等待前的比例按各 root 的实际
时间边界分别计算，只是工作量组成，没有用于在线预测或筛选获胜轨迹。

## 接下来的选择

保留 v230 和所有正负结果。现阶段继续优先验证已经完成 CPU 检查的
共同 free-page fence 和 cold-fit 归还候选，不增加工具预取的 ready
驱逐权限，也不通过请求 running 上限制造冷页。若双主指标仍未过关，
下一步独立评估 agent 借用/新工作流准入节奏与真实 JOIN 关键路径，
同时观察首服务和服务间隔；不把仅提高 batch 或只提前开始当作收益。
若需要新自然源，必须先声明有业务意义的委派阶段/工作范围变化，
保持自动初始工具选择和模型决策，不强制空转、固定 DAG 或延长工具。

验证为 70 项 CPU 定向测试，其中 21 项新增，另外 49 项属于已有回归。
共同运行路径与原生源码均未修改，沿用 v243 的 2155 项及四个子测试
证据，并逐文件核对来源；没有再次执行整套共享回归。
源码和报告绑定于 `v244_request_service_interleaving_sources_cpu_20261026.json`。
实际 GPU 安全、模型数值及性能验证仍待预约结束后执行。
