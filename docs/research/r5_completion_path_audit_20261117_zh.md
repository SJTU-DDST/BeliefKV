# R5 短优先、sibling 与剩余关键路径审计

日期：2026-11-17，美国西部。当前 GPU 实验与本文 CPU 候选分别记录。

## 1. 结论与范围

旧 Full+R5 的主要已证实偏差是排序目标，而非已知容量内的贪心装入
没有遵守输入权重。总剩余模型工作量不能替代含工具等待、并行 child
和后续 parent 的剩余关键路径。

在旧 Full+R5 已完成运行的 3,134 个非空候选记录中，3,127 个有完整
选择与资源摘要。按相同候选窗口、原生规划容量及必要 JOIN 权利检查：

| 口径 | 全部完整运行 | 有测量 workflow 候选的边界 |
| --- | ---: | ---: |
| 候选非空边界 | 3,134 | 550 |
| 摘要完整 | 3,127 | 545 |
| 多 workflow 各自可容纳、合起来不能全部容纳 | 1,150 | 316 |
| 实际集合与真实模型＋工具关键路径短优先集合不同 | 347 | 96 |
| 新关键路径预测集合与同一真实集合不同 | 227 | 70 |
| 旧模型工作量权重按最新状态重新推断后，与真实集合不同 | 330 | 94 |

这里的一次是一次记录的逻辑选择边界，同一等待可能被多次观察。
它不是独立 workflow 数，也不是已经证明的原生执行错误次数。
容量来自既有规划摘要，仍不能替代实际 native KV、锁、DMA 和槽位检查。
七个不完整边界保留为未知。

共同吞吐窗口有 95 个竞争边界、58 个涉及测量 workflow；旧集合与真实
关键路径集合不同 21 次，新预测集合不同 20 次。不能用全程改善覆盖这个
窗口内收益较弱的事实。当前 CPU 重放没有重新计算未来队列、迁移、
实际服务或 JCT。

## 2. 两种审计问题应分开

第一层问“实现是否遵守了给定权重”。旧日志共有 38,414 个选择记录：

- 在可描述摘要中，未发现可容纳的更高权重候选被更低权重跨 workflow
  候选绕过的边界。
- 未发现有成员入选、同组可整体容纳而遗漏其他可见 ready sibling 的边界。
- 43 个边界、47 对候选出现连续工作量点值与期望效用权重反序。
  这包含可能全部放得下的状态，不能称为 43 次实际错误准入。
- 不限制 CPU 预算的同状态选择仅一次改变集合；它不是竞争收益证据。

第二层问“给定权重是否表达了期望目标”。使用固定模型服务率与完整
model/tool DAG 作为离线标签，保留原 required JOIN、真实候选及资源：

- 全程有 347 个边界存在“更短的真实剩余关键路径候选可容纳，却选择了
  更长 workflow”的规划层反序，共 659 对 agent 反序。
- 仅将真实模型关键路径改为真实模型＋工具关键路径，就会改变 121 次集合，
  其中 37 次所在窗口含测量 workflow；共同吞吐窗口为 5 次。
- 单独将旧期望效用改为模型工作量点值，真实关键路径集合偏差为
  351 次、测量参与边界 97 次，未改善原来的 347/96。因此没有将这个
  点值替换推广到未启用关键路径头的默认路径。

工具时间必须放在依赖路径上。并行的 8 秒和 2 秒工具不能累加成 10 秒；
工具已实际等待的部分也不能继续当成未来等待。模型工作量相同的
串行链和多个并行分支，其剩余完成路径可以不同。

## 3. CPU 候选实现

新模型工件可显式增加 `completion_path_readout`。目标为
`remaining_model_tool_critical_path_seconds`，输出整个 workflow 的剩余
关键路径秒数点值。在线只运行有界浅树，不读取未来图。

保持策略简单：

1. 真实 JOIN 权利先保留，普通 ready 候选按预测剩余关键路径从短到长装入。
   使用单调权重 `1 / (1 + predicted_path / reference_path)` 适配现有接口；
   不以权重之和或成本比压过更短的可容纳 workflow。
2. 同一真实阻塞 ALL-JOIN 的可见 ready sibling 跨恢复类别作为同组。
   整组能容纳时连续选入；不能整体容纳时允许可行子集推进，不等未 ready 成员。
3. 候选仍默认六名，完整可见 sibling 跨过窗口末端时可扩到八名。
   复用已收集的逻辑候选和 JOIN 索引，不额外扩大 native 前缀扫描。
4. 普通准入与已有工具替换入口使用同一个权重函数。已配置的压力排序也可
   使用该预测，仍处于原工具保留/保护规则内，不新增主动工具边界抢占。
5. 缺少受支持路径预测时，显式使用模型工作量乘冻结服务率得到的模型秒数
   后备；完全不受支持时弃权到中性先验。不同单位不直接比较。

`ObservedToolClock` 只使用已经收到的真实事件，统计在途工具数、
在途等待最小/最大/总时长，以及已完成工具数和平均时长。这里的总时长
仅是输入统计，不是并行工具标签的累加。

工具起止时间在调度线程提交观察时记录，不使用后台线程稍后处理的时刻。
启用路径头后 TOOL_START/END 立即使旧预测失效；工具仍在执行时，后台
按既有每 workflow 最多每秒一次的约束刷新。未结束工具的预测不能通过
“输入未变化”延长有效期。工作量分布与路径头复用同一次隐藏表示计算，
调度器不等待推断。

原 2 秒普通边界、ACTING decay、active 连续性、1800 秒独立服务兜底、
JOIN/EOS 预取、预测卸载和 prepare_host 保留。没有新增等待老化、
容量积攒或组合效用机制。工具预取、逐层 handoff 保持关闭。

新 sibling 选择日志记录组选择语义及实际 deadline 检查次数，重放器
继续支持旧的类别内逐个装入日志，避免用新检查次数解释旧 CPU 截止点。

## 4. 预测训练及负结果

复用旧 Full 已完成运行的 117,357 个因果进度快照。任务输入仅包含已有
任务委派元信息、已观察模型进展、角色和依赖统计，以及上述工具时钟；
不输入完整 prompt、工具正文或未来 DAG。

离线标签复用 source-bound `cache_remaining_paths`：串行依赖累加，
并行依赖取 max，扣除已经实际等待的外部时间，模型使用冻结服务成本。
标签不是包含调度排队的已测 JCT，冻结服务率也不是未来真实服务时间保证。

固定拟合一次：64 轮 LightGBM、最多八叶、深度四、单线程；训练按
workflow 归一化快照权重。训练 103 个 workflow，校准 12 个，固定测量
18 个完整 workflow 的路径标签不参加头部训练或校准。

| 分组 | 快照数 | 平均绝对 log1p 秒数误差 |
| --- | ---: | ---: |
| 训练 | 89,923 | 0.346541 |
| 校准 | 10,907 | 0.418515 |
| 固定 18 条评价 | 16,527 | 0.718376 |

原隐藏表示仍来自复用的开发预测器，且测量组长期用于开发；这些数字
不证明未见项目泛化，也不应解释成独立确认性测试。

新头在完整摘要上纠正 172 次旧集合偏差，同时引入 52 次新偏差，
另有 175 次两者均偏离真实集合。测量 workflow 参与时分别为
36 次纠正、10 次新偏差、60 次仍偏离。全程净偏差 347→227，
测量参与边界为 96→70。

这些是同状态、最新观察重推断结果，没有精确模拟原异步 worker 的缓存滞后。
重新推断旧模型的对照已另列为 330/94，不能把全部改善归因于工具特征。
共同吞吐窗口中，全部候选 workflow 对的排序正确数由 516/597
变为 502/597；旧模型另有一个平局，新模型没有平局。
因此新头没有全面占优，暂作为候选工件，不自动替换正在运行的模型。

局部 CPU 成本使用既有因果快照与缓存任务投影，CPU0/nice19、单线程：
后台连续工作量推断线程 CPU 中位数 192.9285µs，加入路径头后
301.4385µs；相应 P99 为 233.5623/341.5988µs。新六/八候选选批
墙钟 P99 为 245.8938/332.5061µs，本次样本没有触发软截止。
这些选批数字不含 native 前缀元数据、完整控制器、日志或异步队列，
不是在线 P99 上界，也不能折算成 GPU stall 或 JCT。
