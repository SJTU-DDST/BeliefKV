## Oracle 评分的 CPU 诊断

完整旧 resource oracle 的原集合缩减和实际服务审计保持不变。
新增两份只读诊断均不修改运行配置，也不推断反事实 JCT：

- `amortization_same_cutoff_diagnostic_r1.json` 对 6484 次入口保持实际候选、
  资源、JOIN 权利和截止位置。396 次搜索函数入口中，原成本下
  60 次严格缩减参考、5 个参考外成员；10 s 及更长成本分母基准下，
  分别为 39 次及 11 个，28 次集合比已执行集合更大。
  这是明确的目标函数改动诊断，不是简单数值稳定性修复或性能结果。
- `full_batch_cost_complete_search_diagnostic_r1.json` 仅比较 364 次完整枚举。
  将已有 active decode 的共同批次时间加回分母，不引入新时间参数，
  严格缩减从 59 次降到 41 次，参考外成员从 5 增至 11；
  28 次选择变化，其中 25 次集合更大，没有更小的变化。
  该初版报告把未纳入的 32 次统称为 deadline；准确口径是
  29 次枚举前返回及 3 次真正截止。不得将 32 当成超时数。

上述 CPU 结果支持后续检验“完整批次时间收益率”作为单独候选，
但它仍未实现为线上新 profile，也没有 GPU JCT 收益。
继续保留原生准入、必要 JOIN 成员、既有 active 连续性、
JOIN/EOS、prepare_host 和即时预测卸载，不强制增加迁移。
