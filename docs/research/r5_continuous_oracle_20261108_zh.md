# R5 连续真值效用诊断

## 目标与固定条件

上一项同目标三档真值实验完整完成，固定 18 个测量成员的平均 JCT 为
1045.760001 秒，相对非排序 Full 重复轮改善 0.660558%，相对 R5 重复轮
改善 1.009110%。这不足以证明继续提高三档预测准确率能取得明显收益。
本项进一步检验三档压缩与固定效用是否限制组合选择，而不是继续扩大模型。

使用用户最终保留的 83 个不同原始项目，400GB Host、20 个初始 workflow、
平均 70 秒的固定泊松到达及原固定 18 个测量成员。所有请求、token、依赖、
工具时长、2 秒控制及普通窗口、500ms 补位兜底、400ms 工具检查不变。
保留 JOIN/EOS、预测工具卸载、prepare_host、正在执行 agent 的连续性及
sibling 支持，继续关闭工具预取和逐层 handoff。

连续真值只用于现有 R5 组合选择器的 workflow 权重：

```text
R = 0.01 * 必要新增输入 token + 输出 token 的剩余总量
s = 19144.06
utility(R) = 1 / (1 + R / s)
```

`s` 直接复用既有连续读出合同：77 次训练执行、59 个训练项目的初始工作量
按项目等权得到的中位数。没有使用测量组标签选择标尺，也没有搜索不同标尺。
原始三档门槛仍保留作诊断，但不再决定效用。该有界启发式不是最优 JCT 上界。
工具未来时长不进入权重，工具卸载及压力暂停的选择规则不变。

## 实现与边界

新增独立的 `workflow_continuous_model_work_combination_oracle_v1` 产物类型，
强制声明连续读出、训练参考量、来源预测器和预测主干指纹。原三档类型继续
拒绝连续读出，旧关键路径 Oracle 也不能夹带连续参考合同。

剩余工作仍只根据已观察的请求完成与原生每 128 输出 token 观测更新；请求
提交或工具等待时间本身不扣除工作，不提前释放工具依赖。连续权重随真实进度
更新，但不会凭未来时间戳唤醒 paused agent。

准备器核对参考模型与保留 R5 的预测主干和来源文件指纹一致；只读取训练标尺，
不把该连续学习模型部署到服务中，也不撤销其 `decision_eligible=false`。
JOIN 保护、六/八候选、0.5ms 搜索、资源检查和原生物理权威均沿用现有代码。

CPU 收尾器已支持明确的 `Continuous-work Oracle` 名称，并可同时比较非排序
Full、学习 R5 和刚完成的三档真值。固定测量成员自然完成后停止背景，保留
精确请求回执、新鲜 drain 和实际退出，再计算 JCT、共同窗口吞吐与交互性。
