# 剩余工作量预测器的数据扩充与开发验证

用户允许在当前工程验证阶段放宽项目和任务的隔离，并补跑少量 SGLang native
任务收集训练轨迹。这里的结果用于已知项目上的调度开发验证，不声明跨项目泛化。

## 数据边界

- V174 的 24 条自然完成轨迹用于训练，共 9,380 个因果进度快照。
- V171 的 18 条自然完成轨迹用于独立校准，共 6,208 个快照；其余非自然完成
  workflow 保留在导出拒绝记录中。
- V230 的 18 条完整轨迹用于开发评测，共 14,458 个快照，不用评测标签训练模型、
  校准温度或选择训练轮数。
- 相同项目和原任务在不同真实执行中可以重复。所有快照按整次采集分组，
  不把同一次执行的早期和晚期快照拆入不同数据分组。
- 历史执行会复用逻辑 workflow ID，因此用完整事件文件的 SHA256 识别实际执行。
  同一次采集不能跨分组，同一事件轨迹复制到别的目录也不能绕过隔离。
- 原有项目/任务互斥模式继续保留为默认值；放宽规则必须显式选择 `--split-mode capture`。

## 首次扩充训练

使用既有固定训练轮数与种子，不根据开发评测结果选择 checkpoint。训练和校准
工作量标签仍是 `0.01 * 同上下文必要新输入 token + 实际输出 token`，不是实测 GPU 秒。

首次训练得到训练 macro-F1 0.9963、校准 macro-F1 0.5830、开发评测 macro-F1
0.4650。开发评测的长档误判为短档比例为 0.4892，初始档位准确率为 0.4444。
虽然独立校准通过原有数值门槛，这些结果仍不足以支持启用新的调度排序。
本次不注册预测器调度性能实验，先补充当前短 child 预算下的数据。

原始数据、模型和完整混淆矩阵保存在
`experiments/reports/workflow_work_training_20261029/`；不得把校准通过解释为 JCT 改善。

## 新增八任务采集

在已通过真实 root/child 工具执行检查的项目池中，按已有种子顺序取前八个不同项目，
将原始任务类别顺序轮换一次：功能实现到跨文件重构、跨文件重构到集成测试、
集成测试到功能实现。任务来自固定公开数据包，不按观察到的时长或结果筛选。

复用原项目 source commit、上下文快照、容器镜像和工具环境；不修项目代码和测试，
不向模型提供参考答案。每个项目的新任务不同于其已有评测任务。

采集使用 Qwen3-Coder-30B-A3B-Instruct、8 roots、running/decode 上限 24、
child 提醒/软目标 4/8、root 提醒/软目标 8/16、2048-token prefill、mixed off、
种子 21、真实工具时间。使用当前 canonical common native 引擎及其原生 KV 策略，
不启用 agent 准入、工作量排序、prepare_host、工具预取或逐层 handoff。
保留完整自然长尾及所有失败和干预记录。

配置为 `configs/migration/workflow_work_train8_native_20261029.json`，
任务清单为 `configs/workloads/locobench_workflow_work_train8_20261029.json`。
这次 GPU 工作是预测器训练数据采集，不是再次执行旧对比的 native baseline。
启动前须通过绑定当前源码的 CPU 检查和实际 CUDA sampler 检查。

补采结束后只把完整、可审计的执行加入后续明确声明的数据分组；非自然执行保留为诊断
数据。正式跨项目泛化评测留到工程机制有效后另行冻结，当前不能用开发集结果代替该结论。

## 源码验证

`cpu_r1/evidence.json` 实际通过 4,913 项测试及 6 个子测试，无失败、错误或跳过，
保留此前全部 4,903 个测试身份，绑定 1,987 个源输入；源输入和原生引擎在测试中均未变化。
新增检查覆盖独立重跑、快照泄漏、复制轨迹、显式开发验证模式、运行时识别及 native 配置。
保留最初单 workflow 训练 fixture 无法定义三档的失败记录；只补足 fixture 的三个 workflow。

采集复用已经验证的 common tree `11b84f7c31986782be3fbe699bae2574ef092389`，
其 726 项原生检查证据与实际引擎逐字段核对，只允许 canonical patch 路径及派生哈希重绑定。
历史 V230 的旧 patch 属于 rebase 前的引擎，不能直接套用当前 patch；该预检查失败未启动 GPU。

## 实际启动与后续处理

采集已从干净冻结的 `a719f972` 启动，注册为
`ops/workflow_work_train8_source_20261029_r1.registration.json`，服务端口 18891。
实际 sampler 的 batch 1/8/24 均通过。`live_start_r1.json` 独立核对冻结源码、
实际模型参数、原生采集模式、进程身份和唯一 GPU 所有者；watcher、driver、server、
scheduler 均为 nice 0。2026-10-29 11:12 America/Los_Angeles 的快照已有 8 个
workflow 和 379 个完整输出；这是运行中前缀，不是完整采集结果或性能结论。

`finish_training.py` 只执行 CPU 后处理。它等待成功完整采集、审计通过、两次新鲜
idle telemetry 及实际采集进程退出，再导出 24+8 共 32 条训练轨迹，沿用上述独立校准/
开发评测数据进行固定训练。失败采集或不完整自然执行不会进入自动重训；所有失败记录保留。
输出终态为 `training_complete_requires_review`，不会自动注册下一次 GPU 实验。

该后处理新增 7 项完成边界检查，与训练/划分检查合计实际通过 34 项测试，见
`completion_cpu_r1.xml`。它们不替代采集前 4,913 项绑定回归，也不改变正在运行的冻结代码。
