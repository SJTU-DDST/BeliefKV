## 当前执行设置

采用我们已有的多 agent harness，导入原始任务和完整源码；不调用官方
`agent_session`，因此不继承其 40% 压缩或 50 轮上限。root/child 保留
2048 图步骤硬预算和 32 步收尾预留，不提高到 8192；软模型/工具次数预算
不执行，没有单独的 child 对话轮数门禁。图步骤不等于模型对话轮次。
workflow 仍为 14400s、工具 180s，单次输出最多 16384。

总上下文 262144，完整渲染输入达到 249036 token（95% 向下取整）时压缩
动态历史。静态源码与工具 schema 纳入触发计数，但不作为可删除历史。
使用服务模型的本地 tokenizer/chat template；按消息边界缓存未变材料，
不在服务端逐 decode 重新分词。临近上限时，将单次输出预算缩至剩余空间
并留 256 token 余量，避免 95% 输入加 16K 输出超过模型上限。

新工具镜像使用 Python 3.10。V1890 的语法解析检查未覆盖
`dataclass(slots=True)` 的执行要求；V1897/1900 保留了 Python 3.9 运行失败。
原生成依赖存在不兼容或不存在的版本，镜像按实际导入选择兼容版本，
原项目源码不作语义修补。原测试自身的模块/断言缺陷与镜像故障分别保留；
自带 stub 的测试即使通过，也不是生产代码或任务质量通过。

工具预测使用本轮因果已完成调用的命令形态生存分布，单 workflow 至少
4 个完成样本、跨本轮至少 8 个；超时右删失，超出观测尾部时不给假精确值。
冷启动与支持样本数明确记录，不把旧 SWE 模型的覆盖率当新数据上的精度。
JOIN 保留真实 EOS，并允许最后一个未完成直接 child 的通知绑定到后继
最终请求，观察真实 decode 服务后估计剩余报告工作；用本轮已结束报告校正
长度，工具轮次即时失效。启动时机随当前整批恢复的实测成本增长，取消
长负载的一律 1 秒截断；没有足够大小/池类型的传输证据时仍记录无支持。

关键 parent 的容量为按需可借用空间，不永久空置物理分区。临近恢复时先

## 选择与边界

LoCoBench-Agent 提供交互式软件工程任务，官方实现支持模型根据当前状态选择
文件操作、搜索、编译及调试等工具，并使用多阶段会话。官方最多 50 轮是上限，
不能当作实际工具调用次数。任务和阶段的定义固定，执行时的工具及参数可动态变化。
论文报告不同模型平均约 10–22 轮对话；这不是逐任务工具次数，也不能外推为
我们适配后的交互密度。
任务本身不保证我们的多轮、嵌套 spawn/JOIN，也不保证每个 agent 长时间使用
100K 以上上下文。

官方当前代码默认 `initial_context_mode=minimal`，仅放入部分入口和说明文件；
因此“项目包含 100K 源码”不代表普通 agent 输入已经达到 100K。本候选明确
使用完整项目输入：root、child、嵌套 child 的 system context 都携带冻结源码。
这是完整材料输入方式，不能描述为工具历史自然增长到 100K。材料可见后可能
减少读取工具，所以实际交互密度仍是待验证项。

这些项目来自生成数据，不能描述为真实 GitHub issue 修复任务。原 SWE-bench
负载保留作普通长度对照。LongBench v2 的长文多选题虽方便可靠评分，但没有
自带的工具执行工作流，本次没有将其替换为工具密集主场景。
