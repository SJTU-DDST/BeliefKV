# 56原题的初始人口与持续到达校准

## 改动依据

此前8初始/平均90秒供给不足；8初始/平均60秒在后半程产生有用状态
超容、重算和背景耗尽；8初始/平均70秒的完整共同窗口GPU利用率已到
97.03%，但ready-paused只有81/1384份状态，实际窗口周期竞争为0。
后者仍未完成固定18项JCT，当前不能作为合格oracle控制。

静态原题输入合计，初始8项708,761 token、10项801,154、12项965,900，
Device池上限805,198。它们不是物理独占页或native准入证明，但表明
单纯用8项初始填充不必制造多候选容量竞争。背景组平均初始上下文和
模型工作又较测量组大，不能只继续提高持续到达率来补早期选择机会。

下一候选采用12初始/平均80秒，即增加初始在途人口，同时比70秒降低
持续到达强度。选择依据是原题静态输入、已观察供给和容量边界，没有
使用oracle收益或策略胜负。这是待验证的校准，不预先认定可持续供给、
有用状态容量和调度收益都成立。

## 冻结的条件

使用相同56个完整原项目，12预热/18固定测量/26背景成员与上一轮完全
一致，排列seed54、到达seed35不变。不修改原题、token、依赖、工具
overlay、root/child提示词或项目源码及测试。

新的12个预热成员在0秒到达，测量成员仍从到达序号12开始：

| 项目 | 新候选 |
| --- | ---: |
| 首个测量成员到达 | 63.648882秒 |
| 最后测量成员到达 | 1873.091257秒 |
| 末次背景计划到达 | 3725.552697秒 |
| 最大指数间隔 | 287.376796秒 |

同seed的指数间隔抽样使用相同公共前缀。初始数量改变后，工作流对应的
随机间隔槽位会平移，不能声称全部到达偏移仅按比例缩放。准备记录把
固定成员、公共抽样前缀及整表同比缩放分别标注。
仍保留自然指数空档，没有截断、重抽或伪装成低变异泊松。

所有非到达配置与原90秒Full逐字段相同，包括Device805198、Host200GB、
running/decode24、chunk2048、mixed关闭、2秒控制、500ms补位、acting
decay半衰期1秒、预测工具卸载门槛.75、JOIN/EOS和prepare_host保留，
工具预取及逐层handoff关闭，工作量排序关闭。

JCT保持从预定到达到自然结束，全部18个固定测量成员必须自然完成，
然后才取消非测量工作、核对回执、新鲜排空和实际owned退出。
共同吞吐窗口由新到达表预先确定，不按完成顺序选任务或选忙碌窗口。
预热成员数本身不证明稳态，首个测量到达较早的实际影响须核查。
