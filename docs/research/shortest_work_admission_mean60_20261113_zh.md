# 60 秒持续到达下的短 workflow 准入候选

## 完整对照与当前结论

本项沿用 100 个不同原项目的完整轨迹：原 83 项目加已授权的 17 个背景
项目，400GB Host、20 个初始 workflow、平均 60 秒泊松到达、固定 18 个
测量成员。任务、token、工具 overlay、依赖、到达表和测量成员不变。
测量成员全部自然完成后才结束剩余背景。

旧非排序 Full 与连续剩余模型工作量 Oracle 均已核对完整的 2991 个测量
请求和 362157 个输出 token、两次新鲜 idle 快照及实际服务进程退出。
证据在 `background100_mean60/continuous_campaign_20261113_r1/`。

| 完整固定测量组 | 非排序 Full | 原组合 Oracle |
| --- | ---: | ---: |
| 平均 JCT，秒 | 1258.540519 | 1274.093451 |
| 共同窗口输出 token/s | 340.056146 | 337.791728 |
| 共同窗口 decode token/s | 337.176437 | 334.926020 |

Oracle 的平均 JCT 回退 1.235791%，6 个测量成员改善、12 个变慢；输出吞吐
下降 0.665895%。其正式 1% 目标未通过，没有继续登记旧配置的 R5 和 baseline。
两臂背景表仍未覆盖全部测量尾部，缺口分别为 966.502070 和 1069.177056 秒；
没有将这份匹配诊断改称已接受的稳态负载。

候选供给已经不是最初的稀少状态。Full 完整测量跨度有 194 次涉及测量成员
的逻辑竞争，16/18 个测量成员参与。Oracle 的对应计数为 186，普通可规划
集合分析有 350 次跨 workflow 容量竞争。重复边界不是独立的 JCT 改善机会。

完整 Oracle 产生 151 次相对局部 S0 的集合变化，139 个新增周期成员和
2 个新增免费补位成员均有精确原生服务；其中 129/139 和 2/2 在下一控制
或同 agent 干预之前完成有效工作。选择已影响实际服务，不能将回退简单
归为准入后没有执行。

## 两个有证据的覆盖问题

原组合目标累计多个 workflow 的有界效用，不保证优先最短 workflow。
在同一候选、完整预算、槽位、输入与增长预留、extent 去重、FULL 规划几何
和 required JOIN 下，350 个竞争边界中原规则 307 次包含最短普通可行
workflow。按剩余工作量顺序装入会在全部 350 次包含它，改变 67 个集合，
其中 23 次集合差异涉及测量成员。

既有“保留最短成员后继续组合搜索”的 CPU 候选也在本轮重放：改变 46 个
集合、15 次涉及测量成员，其中 20 次减少准入 agent。其新增测量对象为
7 个 episode、6 个不同请求、3 个 workflow；原历史等待区间的 workflow
内并集总计 58.638836 秒。这不是可消除 JCT 或新策略的收益上界。

长工具 A→B 即时替换仍使用原候选顺序。在已封存前缀内，206 次实际替换
中有 55 次记录完整竞争候选，23 次涉及测量成员。复用原始客户端与粗粒度
原生输出观察，55 次都可取得剩余模型工作量标签，29 次实际选中者比另一个
逻辑可装入的候选更长。替代候选的 native/donor 可行性未知，不能当成
29 次已经能够改选的迁移机会。没有候选元数据的记录保留为未知。

## 默认关闭的实现

artifact 新增显式布尔字段 `shortest_work_first_admission`，默认关闭。
启用时仍要求既有 capacity-v7、benefit/full-batch 配置及启用的工作量排序，
不改变预测参数、训练标尺、资源预算或工具保留权重。

普通准入先保留 required JOIN，再按 workflow 的连续权重降序尝试装入；
同一 ready sibling 组相邻处理，能共同装入时共同准入，不能时允许部分推进。
不等待未就绪 sibling，容量有余量时继续填充其他候选。选择仍最多 6 个普通
候选、按既有规则扩展至 8 个，最多检查 8 个成员，共用 0.5ms 软预算。
元数据异常或预算超时保留 reference，实际 native 资格和容量仍需复核。

即时工具替换只对已有、有界的候选顺序应用相同偏好，保护 JOIN 在前，
不使用释放前的免费预算筛掉消费者，不等待普通 2 秒窗口。短者无法形成
安全 donor 配对时，继续尝试后续候选；没有新增 donor、备份或释放权限。
预测不支持或异常时保留原顺序，继续按原安全路径检查。

保留 active 连续性、工具预测卸载、prepare_host、JOIN/EOS 预取、sibling
支持、原生锁及 DMA 检查；工具预取和逐层 handoff 继续关闭。Host 与 NUMA
设置保持当前匹配资源，不新增分布门槛。

新事件记录明确选择器类型、实际成员检查数和原即时候选顺序。分析器校验
artifact 声明，并按实际超时位置重放选择，沿用精确请求、attempt/session、
授予及原生服务关联。工作量被用于即时替换的范围也在状态与配置中明确记录。
