# 设计点收益优先级：基于已完成实验的暂定判断

2026-10-28。以下是当前长上下文 agent 场景的工程优先级排序，不是模块收益的可加总消融。
早期 v108 与后来模型/工作量不同，不能用它们的吞吐差证明某一模块的净收益。
数值只引用同工作量、同工具时间的完整结果；所有正常长尾保留。

| 顺位 | 设计点 | 当前判断 | 证据边界 |
| --- | --- | --- | --- |
| 1 | agent 粒度准入与执行连续性 | 最重要的基础，预计收益最大 | 避免每次工具返回都丢失工作集地位；ThunderAgent 也具有这一能力，不能算我们相对它的新增贡献。缺少当前源的独立开关消融。 |
| 2 | 降低控制开销，保持有效 decode batch | 高优先级，可能超过单纯传输优化 | 多轮表现表明吞吐受执行形状影响明显。V235 对当时同轨迹 ThunderAgent 吞吐 +7.02%，但平均 JCT 反而 +0.385%，所以 batch 变宽不能单独作为验收。 |
| 3 | 真实阻塞 parent 释放、已结束 child 回收，与 JOIN/EOS 恢复 | 较可靠的容量/依赖收益，优先保留 | 当前 V311 上 reference Full 组合通常平均 JCT 优于 V345 约 2.6%--3.9%，全程输出率约 0%--2.5%；这是组合效果，不是 JOIN 单独收益。V364 的保留资格组合为 JCT -3.30%、输出 +3.63%。 |
| 4 | 有界短工具连续性、空余完整预算上的 continuation/sibling 准入 | 小到中等，依赖工作集 | free-continuation Full 为 1630.056s / 236.040 token/s；pre-admission Full 为 1631.195s / 238.499 token/s。不能无限优先，不能把 JOIN 成员之一的加速直接当作 JOIN 完成收益。 |
| 5 | prepare_host 增量备份及实际需求的 Host 容量保障 | 重要支撑，净收益受 Host 压力制约 | 可避免需求 D2H，但过量备份占空间、占传输资源。旧 Host mirror 回收候选相对前一 Full 的平均 JCT 恶化约 0.919%、输出率下降约 0.448%；不默认推广。新的需求优先 Host 管理尚待验证。 |
| 6 | 预测式长工具提前卸载 | 潜力较高，当前独立收益证据弱 | 之前存在离散 CDF 插值及 Full 提示过期不刷新两个实错。修复后动作可增加，但 CDF 修复 Full 仍相对前一 Full JCT +0.271%、输出率 -0.797%，不能由卸载字节数推断收益。75% 新门槛未验证。 |
| 7 | 工具预取 | 当前源近零可验证收益 | 多轮完整结果中实际工具预取复制为零。保留条件路径可以，但不该为提高覆盖驱逐 ready agent；不能声称它已贡献吞吐收益。 |
| 8 | 普通队列下一批请求预取 | 历史有明显反复换入风险，当前关闭 | agent 连续驻留后机会减少；必须绑定真实近期服务并有非竞争容量，不能替换同优先级 ready KV 来制造预取。 |
| 未定 | D2H/H2D 逐层容量交接 | 新机制，不能提前放进已证实收益排序 | 小池组件与模型 R5 正确性已通过，尚无完整性能结果。收益取决于真实需求等待、方向速率、batch 干扰和机会次数。联合首轮与门槛/Host 管理一起验证。 |

V345 ThunderAgent decay 的共同基准是平均 JCT 1697.583645s、
全程输出率 233.371801 token/s。固定输出量时全程输出率由 makespan 决定；
同时保留 decode 随时间曲线、worker 区间、batch 形状与 workflow 服务间隔，
避免把两个相关的端到端指标当作独立 GPU 计算加速。

最值得投入的新增研究点仍是：在有真实冷 KV 的需求切换中减少暴露的迁移等待，
同时控制占用与计算干扰。资格借出、归还和拟合选择属于工作集切换工程，
不应包装成多项独立创新。最终排序应在组合取得稳定优势后，再用同工作量消融校正。
