# 原始56项目的容量限制与本地Host扩容判断

2026-10-31 PDT，在70秒固定18测量成员完成后进行CPU/只读核对。
没有新GPU实验、Host分配、到达变更或工作负载推广。

## 当前证据支持什么

当前大上下文任务组合在提高供给时容易触碰总KV容量，但现有结果不能
证明在原硬件上找不到合适负载。Host容量、应用ready人口和准入选择机会
是不同约束。增加Host只能扩大可保留的存活状态，不自动扩大HBM、
ThunderAgent逻辑active容量，也不让仍在等工具的agent变成ready。

当前可用Device为805198个FULL token、Host为2034506个，总计2839704个。
每token为98304字节，合计约279.154262 GB。以下是离线去重的下一请求
可复用旧前缀并集，不是物理Host占用、完整在途/增长预算或可部署保留规则：

| 控制 | 观察范围 | 并集token | 合并容量比例 |
| --- | --- | ---: | ---: |
| 平均70秒到达 | 完整共同窗口内定期采样峰值，1320秒 | 1284182 | 45.2224% |
| 平均70秒到达 | 全程定期采样峰值，2520秒 | 2476930 | 87.2249% |
| 平均60秒到达 | 最后检查点，约3260.7秒 | 2997703 | 105.5639% |
| 平均60秒到达 | 更早的全程采样峰值，2580秒 | 3225390 | 113.5819% |

不能把60秒控制的最后检查点当作全程峰值。峰值时有26个存活workflow、
41个context，仅这份旧前缀估计就超出385686 token，约37.914477 GB；
完整保留还需要考虑在途副本、输入增长及运行时余量。因此仅增加16GB
不能覆盖该已观察峰值，增加40GB也不是全程无重算保证。60秒仍是14/18
测量完成时停止的失效校准，不能与完整70秒结果比较平均JCT。

70秒全程峰值对应19个存活workflow、38个context。它保留了约35.662135GB
的该口径余量，但实际物理分配仍可能受副本、锁和原生分配约束。
70秒共同窗口GPU利用率97.027573%，ready-paused快照比例仅5.85%；
更大Host并非解决这段低竞争的充分条件。背景到达另有754.083037秒
测量尾部缺口，扩容本身不会补充背景到达。

## 当前NUMA与软件限制

实际launcher选择NUMA node1和`preferred`策略，不能把它描述为严格
`membind`，也不能未经实际页驻留观察就声称全部Host页位于本地。
2026-10-31 01:15 PDT附近，node1 MemTotal约251.97GiB；现有只读
`preflight_qwen35_host_pool.py --node 1 --size-gb 200 --memory-policy bind`
估计本地可回收可用量199.80GiB，200GB池本身186.26GiB，另留8GiB。
这是当时可用量估计，不是未来分配或实际驻留证书。

240GB池加同样8GiB预留需约231.52GiB，超过上述当前本地可用量。
扩大本地预算需要新的资源余量，不能直接依据整机另一节点的空闲量
就宣称本地容量够用。现有`preferred`允许其他节点后备，实际驻留和
相应传输成本必须另行观察。

软件亦明确锁定200GB：

- `scripts/launch_qwen35_native_v0520.sh`拒绝大于200的`HICACHE_SIZE_GB`。
- `scripts/preflight_qwen35_host_pool.py`的`MAX_POOL_GB=200`。
- `scripts/run_causal_comparison.py`的共同资源校验要求200GB。

仅增加物理内存不会改变这些限制。扩大池应声明新资源配置，保留旧结果，
完成对应资格检查，所有对比臂使用相同容量、到达和工作量。不能把额外
内存带来的重算减少归为调度算法收益。

## 后续判断

先利用新增的只读准入观测区分：同边界候选提前消耗、没有其他ready工作、
逻辑额度不足及物理恢复失败。还可以在保留完整原题和长上下文任务的
前提下，检验更多短/中上下文原任务能否增加单位KV容量内的ready人口。
不能仅延长调度等待来制造paused积压，也不以策略获胜筛选任务。

若保持当前大KV任务组合并进一步提高存活人口，增加本地Host容量是
合理的容量敏感性方向；240--256GB池可作为待资源审查的一档，而非
已授权/已可行配置。需结合新增到达供给验证，不能从扩容推定oracle
一定获益。当前没有改变200GB配置或登记此实验。
