# 普通准入与工作集控制统一入口

2026-11-04。实现范围是 Full 的 learned/R5 和 global oracle 普通准入控制。
目标是统一触发与计时，保留已有选择策略和执行权限。GPU 继续暂停；
本次不注册实验，也不以 CPU 验证代替 JCT 或 GPU 性能证据。

## 控制顺序

`WorkflowSizeAdmission.tick()` 将有 deferred controller 的执行交给
`DeferredFreeAdmission.tick()`；R5 组合控制器继承同一个入口，
global oracle 不再另写一份窗口到期协调逻辑。

同一个 native 调度边界内按下列顺序处理：

1. 读取已有普通窗口截止时间、pending 索引和完整控制截止时间。
   普通窗口到期且存在 pending 候选时，必要时将完整控制提前到当前边界。
2. 按原完整控制更新 streaming 工作量、工具权重、恢复与容量压力。
   保留原排序、sibling 偏好和暂停规则。
3. 对剩余未获准入的请求执行原有有界补位。
   补位重新读取完整、未折扣容量；不能沿用控制前的额度。
4. 消费本轮普通事件并推进普通窗口。重复通知不重置尚未到期的窗口，
   同一时刻再次进入不会重复执行完整控制或普通补位。

注册、完成、TOOL_END 和 sibling 通知仍先更新有效 pending 索引，
在普通路径只设置通知状态；一个 native 边界前收到的通知合并处理。
配置了 1/2 秒窗口的路径不再运行独立的 500ms 免费补位唤醒计时。
没有配置时间窗口的历史路径保留原 fallback，外部 paper baseline 不受影响。
首个已挂接 native 边界仍吸收旧 fallback 的初始通知，保留空闲启动时的
窗口相位以及在首次边界前变为 ready 的 JOIN；之后不再单设半秒计时。

普通实验仍使用已有的 2000ms 配置，没有增加新开关。周期完整控制仍保留
原有到期行为；窗口到期提前协调的规则也保留。没有为了对齐时钟而把所有
周期恢复强行推迟到普通窗口，也没有将每次 hint、ACK 或 decode 回调改成
全工作集重选。

## 保留的行为

完整控制和剩余额度补位成为同一控制器的两个阶段。它们的候选范围和容量
口径原本不同，不能把两个阶段替换成一次无界组合搜索：

- 周期恢复继续使用工具 decay 预算选择，并执行原未折扣压力协调。
- 普通补位继续检查最多 8 个轮转 pending 成员、原 JOIN 窗口和最多 4 次授予。
  R5 搜索仍保留 6/8 候选和 0.5ms 软预算。
- 已确认的长工具 A→B 配对、实际 JOIN 容量交接与 JOIN/EOS 恢复保留原有
  及时响应路径及动作前复核，不等普通窗口，也不额外触发全局重选。
- 已有 active agent 的连续性、工具保护、sibling 选批、Host/Device 容量、
  身份、锁、DMA 和原生分配权限保持原样。
- 最终单次授予仍刷新 streaming 增长，并检查完整未折扣额度。
  统一入口不等于一次逻辑授予已经获得物理 KV 或模型服务。

同一边界按 workflow 懒读取一次预测，周期排序、组合评分和剩余额度补位
共享该边界的预测版本，正常返回或异常退出都会丢弃快照。边界外的 A→B
排序仍读取当前有效预测，下一边界也重新读取。预测线程恰好在一个控制
边界内发布新版本时，本轮保持同一版本，下轮使用更新值。
物理容量、前缀、Host 副本和动作前检查不跨阶段缓存。

## 行为核对

新增 CPU 差分检查保留旧的两时钟入口顺序，底层选择核心使用同一实现。
将相同事件序列分别交给旧入口和统一入口，逐次核对 program 全部状态、
pending 顺序、active/paused、恢复集合、授予次数、原始容量及两个截止时间。
覆盖 learned、global oracle、oracle 组合路径，排序开关、1/2 秒窗口，
以及工具衰减、连续性、延迟工具返回、受保护 JOIN、身份失效和周期错相位。

另检查事件突发只有一次完整协调和一次剩余额度补位、没有独立 500ms 唤醒，
预测快照在正常及异常退出后失效，以及剩余额度补位读取控制后的真实逻辑额度。
差分基线仅冻结旧入口编排，不能当成全部历史版本或异步运行轨迹逐位一致的证明。
有意变化的诊断计数是 timed 路径的 `free_dispatch_fallback_ticks` 不再增长；
原 workflow/oracle 提前协调计数与历史日志名称保留。

验证入口为 `tests/test_unified_admission_control.py`，并运行已有窗口、R5、
工具配对、JOIN/sibling、residency 和原生生命周期相关 CPU 回归。
结果放在现有实验的 `unified_admission_control_r1/` 证据目录，
不新增 GPU 实验版本。实际 JCT、吞吐和总控制成本仍需在用户解除 GPU 暂停后
由下一轮联合代码比较验证。

最终 CPU 回归为 **823 项通过，无失败或跳过**。新增 79 项中，72 项比较
3 种路径、2 个排序开关、2 个窗口和 6 类事件序列；另 3 项比较空闲启动后的
首次到达，因此共 75 组新旧差分序列。其余 4 项检查事件合并、两种预测快照
退出情况及控制后容量复核。

`cpu_r1.xml` 保留首轮 819 通过、1 失败的原始结果：移除独立 fallback 后，
首个 native 边界遗漏了刚就绪 JOIN 的通知。补回一次初始通知，并增加空闲
启动窗口相位检查后，`cpu_r2.xml` 为最终 823 通过。没有通过修改已有断言
或放宽物理检查消除失败。

所有检查使用 CPU0、nice19、CUDA hidden 和单线程数值库。原生树/分配器
相关测试运行在已审阅的 SGLang checkout 上，复制和 GPU 事件仍为 CPU
替身；这不是 GPU 数值、传输或性能资格验证。
