# 测量组结束协议下的 oracle 准备与比较

用户允许固定测量组全部完成后结束实验。后续 oracle 必须沿用这一协议，
不能要求控制把已经取消的背景重新执行完，也不能将不完整背景声明为
完整执行。完整原题及56项原轨迹仍保留；本改动不生成新的GPU性能结果。

## 完成证明

`scripts/verify_measured_execution.py` 复用既有停止流程的回执核对，验证：

- schema2 的到达表、测量成员、JCT边界和共同吞吐窗口。
- 完成证书绑定的登记与cohort哈希，以及未改变的原停止意图。
- 原生回执、两个新鲜空闲快照和已退出的注册进程；退出检查保留PID身份。
- 每个测量workflow的实际起止事件、全部源请求、token哈希和停止条件。
- 已完成、右截尾及未到达的非测量成员集合，不将它们计作零JCT。

原schema1仍走完整人口、排空和实际退出检查，未放宽历史要求。
schema2的完成范围明确为固定测量成员。辅助审查必须绑定同一证书、
cohort和登记，不能仅凭一个`all_measured_completed`布尔量通过。

## 准备与进度资格

`prepare_sustained_oracle_admission.py` 接受显式`--cohort`，在验证完成
证书后继续执行原负载门槛。供给、真实竞争、异构程度、背景覆盖及
原始数据绑定仍然必须通过。候选的任务、token、工具时间、到达表、
容量与执行条件保持不变，测量成员身份不加入运行时环境或oracle图。

准备文件只在离线provenance中记录测量契约和完成证书。artifact仍保留
全部56项未来图；不得只给测量成员建立剩余工作标签。

`qualify_burst_oracle.py` 对实际观察到的完整调用边界重建oracle进度：
测量成员必须消耗完全部源工作并自然关闭；背景尚未观察到的工作保持
剩余状态。分别记录`complete_measured_work_conserved`与
`complete_work_conserved`，不能通过清零背景余额伪造完整守恒。
调用边界验证仍不冒充原生逐token回调的完整重建。

进度证据绑定原事件文件的完整前缀、artifact、配置、登记、cohort、
完成证书及验证器源码。源码键使用相对路径，允许从经过核对的同内容
冻结目录启动。注册入口重新检查这些绑定，不因采用截尾协议绕过负载
验收、匹配条件、新鲜GPU采样或原生容量检查。

完整CPU资格现在显式包含这几项`experiments/reports`下的实际依赖，
并记录JUnit中的失败、错误和跳过计数，供后续注册使用。

## 比较口径

`review_sustained_oracle.py` 主指标仍为同一固定成员的完整平均JCT，
包括跨窗口尾部。两个执行必须有相同的完整测量请求及逐workflow输出。
吞吐仍按相同墙钟窗口计入全部实际输出，包括背景和prefill首输出。

更早完成测量组的一方可能执行更少背景请求，因而不要求全人口回执数量
相等。两方完成证明分别校验，不能通过比较一个共同请求子集绕过测量
请求完整性。

非测量组仅对双方都完成的成员提供配对描述，明确给出共同完成数、
固定人口、各自完成数和条件性标记。两方没有共同完成成员时，平均改进
为null。这个条件子集不能作为背景总体平均JCT或公平性提升的证据。
有截尾的执行不提供完整人口的可比均值。

## 已有验证与限制

- 89项定向CPU测试及11个子测试通过，包含旧schema1比较及新schema2
  的回执缺失、证书错配、陈旧排空、存活进程、成员变更和截尾检查。
- 真实90秒Full控制的2,819个测量请求、362,072个输出重新验证通过。
- 真实记录中的8,458个完成请求、44个关闭workflow及348次路径取样通过
  CPU进度检查；完整人口守恒为false，完整测量组守恒为true。
- 未通过负载门槛的旧轮仍被准备入口拒绝，未创建oracle GPU配置。

证据在
`experiments/reports/remaining_original_projects_20261030/measured_oracle_cpu_original56_r1/`，
最新进度为`progress_bound_r2.json`，另有`rejected_workload_guard.json`。
这只验证协议与读者，不是oracle调度收益或可部署预测器的验证。

当前60秒Full仍使用已冻结的`5f2b2f6c`，本组适配位于后续开发树；
完整源码绑定回归及后续GPU资格仍需另外完成。
