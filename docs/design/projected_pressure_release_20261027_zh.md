# FULL 压力暂停的预算计划

这个候选针对 agent 驻留连续性，使用
`configs/migration/predictive_projected_pressure_20261027.json`。
它保留 V330 的 JOIN/EOS、工具卸载、Host 备份、阻塞预算借出和
原生迁移权限，仅显式选择新的压力暂停控制。

## 发现与边界

保留的参考控制在逻辑超额、没有 ACTING 预算可暂停时，会逐个给
reasoning agent 设置 `marked_for_pause`。标记本身不归还预算，
所以原循环可将所有运行 agent 都标记。不能修改 ThunderAgent
复现来消除这个参考行为；默认策略仍为 `reference`。

CPU 反例：容量 1000，三个正在执行的 agent 各有 260 个上下文 token
和 100 个增长 buffer，总预算 1080。参考策略将三个都标记，
即使任一个完成后归还的 360 已足够覆盖 80 的缺口。
V362 保存完整反例和源码摘要。

V330 的 2259 个快照中，65 个有逻辑超额，16 个同时满足所有 active
agent 均有 pending 请求，最大观测超额为 14663 token。
历史快照没有记录每次暂停标记，不能据此声称这些时刻实际发生了
全体标记，更不能把它认定为已证明的性能根因。

## 候选行为

显式设置 `AGENT_PRESSURE_PAUSE_POLICY=projected_release`：

1. 沿用原五秒控制，不新增逐 decode 步扫描或新定时器。
2. 已到安全边界、未受 JOIN/恢复保护的 ACTING 预算仍先归还。
3. 若尚有缺口，只在正在执行的请求中追加足够的“完成后暂停”标记。
4. 已标记的未来归还量只用于停止追加标记；原始剩余容量不变，
   不允许新请求或恢复预留提前消费它。
5. 请求实际完成或按原生重排边界返回后，才由原有路径归还预算。
6. 尚未执行的排队请求不算未来完成事件；受保护的 JOIN/恢复对象
   不成为新压力标记对象。无法覆盖的缺口继续显式保留。

CPU 反例中新策略只标记一个 agent，但三个仍是 active/in-flight，
剩余容量仍为 -80。原生分配、锁、DMA、需求恢复和准入检查不变。
没有扩大工具预取、普通请求驱逐或 ready peer 替换权限。

新快照增加 `marked_for_pause`，使后续实测能区分逻辑超额、实际
标记、边界暂停和最终迁移；这些状态不能仅由 active 数倒推出。
冻结 V364 中，当缺口在下次边界前自行消失时，已有标记仍可能
造成额外切换。后续修复见下节，不能将其计入 V364 的 GPU 结果。

## 完成后的标记复核修复

后续 CPU 反例中，三个各占 360 token 预算的运行 agent 产生 80 token
缺口，A 被标记。C 正常完成并返回后，真实预算已余 280 token，
但 A 的旧标记仍会在它完成时暂停 A。修复只跟踪本模块创建的压力
标记，在已有 rebalance、实际暂停及生命周期回调处重新核对真实缺口：

1. 缺口消失时撤销本模块未消费的标记，不暂停仍可继续执行的 A。
2. 缺口缩小时只保留足量标记；新增 JOIN/恢复保护也会取消对应标记。
3. 不撤销外部标记，不把计划释放量计为可分配容量，不增加定时器。

`v370_pressure_plan_revalidation_shared_cpu_20261027.xml` 在一次运行中
通过 2951 项及 4 个子测试，无失败或跳过，保留全部 2942 项旧检查，
新增 9 项。V371 绑定完整源文件摘要及三个真实构造器；默认与工具衰减
ThunderAgent 仍为 `reference`。V369 的局部执行有 18 项环境跳过，
不能单独作为共享资格证明。上述修复尚未进行新的 GPU 性能实验。

V368 封存的 V364 前缀只观测到 3 次计划压力暂停；其中一个约 1.027 秒
的采样区间有标记但没有当前逻辑缺口。这支持修复一个可复现的边界，
不证明该边界解释完整性能差距。
