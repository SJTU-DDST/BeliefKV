# 长工具替换的事件入口与 2 秒普通准入窗口

## 最新决定

2026-10-31 用户要求普通候选合并窗口设为 **2000 ms**，并指出长工具
释放空间给 ready agent 的决策不应等待 1/2/5 秒周期。新候选同时保留
这两条规则；已经结束的 `020527dd` 轮仍是原来的 1000 ms，不能改标签。

生成配置：
`experiments/reports/remaining_original_projects_20261030/event_tool_replacement_window2s_cpu_r1/full.json`。
同目录 `oracle.json` 的窗口字段为 2000，内容哈希已重新绑定到配置，
构造检查已接受。56 个原项目、token、工具、8 初始/平均 70 秒到达、
测量成员、Host 200 GB 与设备池保持原声明。这是新 CPU 候选，尚未 GPU
登记；不能把旧控制与新配置的差异全部解释为纯排序作用。

## 修复的循环依赖

原 `DemandAwareToolOffload` 在 reference 组合下只接受已经 active 的 B。
如果 A 的逻辑额度恰好阻止 B 取得资格，B 便不能成为卸载消费者，
A 也无法通过该路径让出额度。仅在实际卸载后联动 paused 不能解决此问题。

新入口位于 native prefill 规划中、按 agent 资格过滤请求之前：

1. 工具开始/返回、后继登记、模型完成、预测结果和备份 ACK 使该入口
   可以在下一个 native 安全边界立即尝试。维护路径的 200 ms 限流与
   替换入口分别计时，避免维护扫描先消费事件机会。
2. 从真实 native 等待对象与 pending 索引取有界 ready-paused 候选；
   先用已有排序比较这些 B，再寻找能够服务它的 A。Oracle 在这里
   使用相同剩余模型与工具关键路径，但绕过普通合并窗口。
3. A 必须仍真实阻塞、没有未完成模型请求、身份与工具预测有效。
   检查完整逻辑预算和 B 当前输入、缺失 KV、增长预留、请求行及批次空间。
   不暂停仍可执行的驻留 peer 来制造位置。
4. 先形成私有、已备份节点的有界释放顺序。碎片化前缀先叶子后祖先，
   每个真实 demote 仍重新调用 native 权限检查。共享页不按整份上下文
   重复算作可释放容量；计划只用于筛选，不能充当实际空闲页。
5. 若需要备份，异步发出原有 PREPARE_HOST；此时不撤销 A 的资格，
   不给 B 预支额度。ACK 后立即重新比较实时候选，不永久绑定旧 B。
6. 确认 FULL 真正释放后，已有 residency 机制暂停 A；重新检查完整容量
   与 B 的当前就绪状态，随后授予 B，并让同次 native 规划看见它。
   正常 native demand 路径负责加载和最终选批。

工具提前返回、B 被取消或移出队列、Host 不足、锁/DMA 尚未解除，
都不能继续使用旧授权。无真实 B 时不执行预测替换。工具尚未返回的
paused A 也不能仅凭预测时间被重新激活。

恢复授予会标记该请求已经参加过比较；传输尚未完成期间不因同一
Host checkpoint 再次撤销资格，实际模型服务后清理。这里没有普通请求
1500 ms 恢复租约，没有工具预取，也没有逐层 handoff。

## 时间规则

| 入口 | 时间条件 | 权限 |
| --- | --- | --- |
| 普通首次/续接候选合并 | 新候选明确使用 2 秒窗口 | 原排序、完整预算与 native 准入 |
| 预测长工具 A 到实际 ready B | 相关事件后的 native 安全边界 | 先选 B，实际安全释放 A，再授予 B |
| JOIN/EOS | 保留已有依赖事件入口 | 保留原优先级和物理检查 |
| Full 完整工作集协调 | 名义 2 秒，窗口截止协调可能提前 | 原衰减与完整压力处理 |
| 维护检查 | 200 ms 有界检查 | 不能代替真实 ACK 或工具返回 |
| 论文 ThunderAgent | 保持原 5 秒检查 | 不继承 Full 扩展 |

当前 acting 衰减本来就是 `2 ** (-elapsed_seconds)`，半衰期为 1 秒，
起点是实际模型完成后的 ACTING 转换。5 秒不是半衰期，也不是一次固定
衰减步长；不能因为窗口改为 2 秒就把半衰期乘以 2/5。预测替换不再
等待衰减产生名义额度；预测不可用时仍有基于实际经过时间的原兜底。
工具调用与纯排队老化是不同机制，本改动没有增加全局请求老化。

## 范围与观测

该能力跟随既有显式 Full residency 开关，以及 demand-cost、
准入前工具卸载组合启用；默认和论文 baseline 均不继承。优先处理
单个 A 足以支持 B 的可验证替换，候选最多 8 个、工具 owner 每次最多
8 个、释放节点最多 16 个。无法形成完整安全组合时保留原生回退，
不宣称已实现 R5 的全局多 donor 组合最优选择。

有 checkpoint 的续接使用真实缺失前缀；首次调用没有可观察 checkpoint 时
保守预留完整输入与最坏拷贝成本，不能把 unknown 判成热前缀，也不能把
首次输入称为已经发生的旧状态恢复。未知续接不使用该推断。

`agent_predicted_tool_replacement` 保存实际 A/B 身份、授予前后逻辑容量、
绕过窗口与无恢复租约声明。实际释放字节继续使用原工具卸载记录，
资格授予继续使用统一 grant 日志。新增选择、授予、备份尝试、无完整组合
和 CPU 时间计数；GPU 实验仍须关联真实后续 batch，不能把资格授予当作
实际服务或 JCT 收益。

定向 CPU 使用真实 native CPU 树与分配器、原有 copy/ACK 替身，覆盖
事件立即替换、竞争候选比较、普通 2 秒窗口绕过、真实备份 ACK、
提前返回与取消、共享/锁/行/批次限制、碎片化前缀及恢复不反复暂停。
源码绑定与 GPU 性能证据分别登记；CPU 正确性不代表 DMA 重叠或性能收益。

最终源码绑定检查位于
`experiments/reports/remaining_original_projects_20261030/event_tool_replacement_window2s_bound_cpu_r3/evidence.json`：
**6096 项及 23 个子测试通过**，保留 r2 全部 6095 个测试身份与 2236 个
源码输入，失败、错误、跳过均为零。执行期间源码、原生树与配置/负载输入
不变。27 项事件路径专项检查也单独通过。

保留 r1 的碎片前缀失败记录：6093 项通过、1 项失败，23 个子测试通过；
问题是将拆分祖先没有独立 session 标签判作不可使用。修复并补齐有界节点
轮转后的 r2 6095 项通过，随后再补齐候选总上限与撤销后的陈旧候选保护，
最终以 r3 为当前证据。没有将早期失败改写成成功，也没有新 GPU 结果。
