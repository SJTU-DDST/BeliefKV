# 工具预测曲线与真实卸载

用户要求先修复预测卸载，再实现卸载/加载逐层重叠；重叠若为负收益
则关闭并回退。工具后继排队不自动意味着应抢占当前ready agent，
不能把工作集替换本身当作新贡献。

当前强控制的五秒周期更新逻辑agent执行资格，不直接提交物理D2H。
物理缓存驱逐、原生容量不足时冷页释放、独立预测式卸载是不同路径。
此前完整Full的41次、0.393GB仅是最后一条额外路径；另有工具等待
容量释放6.182GB及原生缓存搬运，不能据此宣称只有41次工具相关迁移。

已定位实现错误：OnlineWorkloadToolTiming输出的离线先验和混合先验
都是离散经验CDF；NativeToolWaitHint只将纯workflow/run在线CDF按
阶梯曲线处理，却把offline_prior、hybrid_workflow、hybrid_run转成
对数插值曲线。即使所有已观察完成时间都为10秒，也会产生1秒P10、
5秒中位数和未来1秒内的虚构完成概率。真实动态成本策略随后可能
错误拒绝本来满足其90%生存条件的卸载。

修复保持经验完成时刻，仍保留真实工具阻塞、已提交且有资格的
消费者、物理容量缺口、成本预算、Host ACK、私有所有权和原生锁
条件。先以CPU原生树/分配器反例验证，再量化历史预测曲线差异；
不预先断言这是所有漏卸载或性能损失的唯一原因。

六个新增反例全部在旧代码失败，包括三种scope的错误分位数，以及
真实CPU原生树/分配器中本来有收益的32槽卸载被拒绝。修复后196项
定向检查全部通过，保留 `initial_red_cpu.xml`和 `targeted_cpu.xml`。
不修改90%门槛、工作集选择、工具后继优先级或原生物理权限。
CPU copy/event替身不是GPU或完整性能证据。

共享回归单次通过3387项及4个子测试，无失败或跳过，保留先前3381项
身份并增加6项；真实Full和两种ThunderAgent构造器隔离及继承的参考
调度方法均通过。对应 `shared_cpu.xml/.sources.json/.evidence.json`。

`compare_forecasts.py/.json`复核上一轮完整Full的930份离线/混合经验
预测，在预测发布时的一秒生存门槛从682份通过变为717份，35份改变；
P10增量中位数19.98ms，均值101.68ms，最大1081.65ms。未使用未来
工具结束时间，也不重建真实物理容量或安全donor。因此这证明实现
偏差实际影响过预测解释，不能声称这些35份都会成功卸载或改善JCT。
90%本身不是全部漏卸载的已证实原因，后续仍需分别审计需求和容量。

修复Full已完成3674个请求及18个完整workflow，原生停止、两个新鲜
idle快照和实际进程退出均通过。平均JCT1635.620442秒，全程输出
236.597296token/s；相比原Full单次结果分别差0.2713%和0.7974%，
相比同工作量V345分别改善3.6501%和1.3821%。额外预测释放64次、
0.786629GB，不能据此宣称已经取得净性能提升。保留全部正常长尾。

当前网络合成场景的signature实际是(timing_domain, WebFetch/WebSearch)；
在这个分支不会进一步使用原始execute命令。冷启动同类别同年龄的
先验相同；后续仅由已完成的workflow/本轮历史和已存活时间更新。
这是分组剩余时间分布，不是精确的逐调用完成时间回归，也没有
97%逐调用准确率的结论。类别内独立合成的时长不含可由原始命令
语义预测的关联。卸载判断使用回本窗口内完成的概率，不以P90总
时长作为必然还能等待那么久的证据。

## 类别分位数与逐调用预测的边界

当前正式网络合成场景的预测路径是固定TraceLab类别先验加本轮在线
经验生存分布，没有调用旧SWE-bench回归器。`tool_signature`在存在
`timing_domain`时直接返回domain和可观测类别，不再检查原始execute
命令、URL、参数或输入大小。同类别、同历史、同已等待时间得到相同
预测；本轮在线历史按workflow至少4个完成样本或run至少8个完成样本
启用，每个key最多保留64个样本，离线先验权重相当于8个样本。

设工具总时间为T，已经实际等待a，类别及可观测历史为x，则：

```
P(T - a > r | T > a, x) = S_x(a + r) / S_x(a)
```

P90是这一条件分布的90%分位数，不是某次调用的预计精确返回时刻，
也不表示90%的概率至少还会阻塞那么久。卸载器使用的是动态迁移回本
窗口C内完成的概率不超过0.1；CDF不可用时退回剩余P10下界判断。C包含缺失
备份D2H、消费者H2D、累计donor回装H2D、控制余量及必要的资格周期。
该0.9策略门槛不是已经测得的0.9预测准确率。

从本轮固定先验实际计算，WebFetch在开始时的剩余P10/P50/P90分别为
2.300/5.314/19.206秒；实际等待5秒仍未完成后变为
0.500/3.333/17.814秒。WebSearch开始时为5.492/18.249/43.947秒。
这体现条件总体的变化，没有引入本次调用的隐藏时长。留出集的P90
上界覆盖率分别为63个WebFetch的95.24%和28个WebSearch的92.86%；
它们不能证明逐调用误差很小，也没有验证所有在线条件卸载决策的
校准效果。

V311在类别内独立采样合成时长，原始execute语义没有预测该隐藏样本
的信号。不能通过读取样本标识、实际结束时间或未来trace图改善预测。
真实工具场景若要论证逐调用预测，需要成对保留调用时可见的参数、
命令形态、输入规模及真实执行时间，并按session/project隔离训练和
评价。当前类别分布可用于保守成本判断，不能宣称精确的语义预取。

## 完整Full的Host容量证据

`experiments/reports/tool_prediction_curve_repair_20261027/predictor_and_host.py`
读取完整、已退出且封存的本轮Full，结果保存在同名JSON。其最终native
idle prepare检查9972次，其中7073次在扫描前因Host预算不足跳过，
约70.93%；保留预算5461token，即536838144字节。它们是重复检查
次数，不能解释成7073个独立工具卸载失败、可消除JCT或持续占用率。

1940个Host采样覆盖约2328.10秒跨度，剔除超过5秒的未知采样间隙后，
sample-hold覆盖约2054.29秒；该已覆盖近似区间的72.82%使用率至少
99%，66.45%自由容量小于上述备份保留量，观测到的最小自由量为0。
保留全部未知间隙，不能把这个近似值当作连续GPU时间线或策略因果收益。

安全回收HBM中仍有完整受保护副本的Host镜像是可行的工程回退，但
必须保留Host/DMA锁和源引用约束。此前镜像回收完整Full相比非镜像
Full的平均JCT及全程输出吞吐均略差，所以仍不默认启用。

逐层D2H/H2D重叠本身不会删除Host容量需求。当前事务仍先为A保留完整
Host目标，B未读取完成的Host源也必须受到保护；尚未实现逐层复用
B的Host槽存储A。A/B的上下文长度、D2H/H2D带宽和计算速率不同，必须
分别检查最终容量及每层依赖。prepare_host可以提前完成D2H并减少
切换时的依赖，不能仅凭实现逐层重叠就删除，后续以同工作量完整
实验决定保留、缩小或关闭。
