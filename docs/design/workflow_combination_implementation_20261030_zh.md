# 有界组合准入实现与验证边界

本轮实现显式开关 `WORKFLOW_COMBINATION_ADMISSION=1`，仅作用于开启
workflow预测及bounded dispatch的Full组合。旧配置默认关闭，外部paper
baseline及native臂不会继承该开关。

## 已实现

- 原周期恢复预算内和未折扣空闲预算入口共用集合评价。首次资格延后到
  共享选择边界；普通续接和sibling事件合并进入已有pending窗口。
- 默认六名候选，相关sibling需要时最多八名。保留参考集合；不能完整
  保留、资源/成本摘要不可用、预测全部失效或软搜索截止时返回参考方案。
- 在显式R5路径中，原恢复类别仅保留在参考顺序及近似同分偏好，不再
  形成不可跨越的搜索分区。已有active不因其他workflow更短而被挑作
  受害者；原decay及压力循环照常运行。
- 条件概率映射为共享workflow权重，真实阻塞ALL-JOIN按覆盖平方增量
  评价，单workflow收益封顶。oracle诊断单独采用剩余model/tool路径
  的连续权重；它与可部署条件分布不是同一个预测器或最优调度上界。
- 已知Host缺失extent按原生节点身份去重；成本使用完整输入/槽位/
  增长预留及整批decode增量。每次候选最多一次本地前缀摘要，组合枚举
  不再遍历radix或执行DMA。原生准入仍保有最终权限。
- 资格集合可以跨多个原生prefill chunk推进，不能用整组完整输入大于
  当前2048 chunk作为不可行门禁。完整新增输入用于成本，当前chunk及
  每名成员最低输入页用于即时空间检查；最终逐请求准入仍由native决定。
- JOIN/EOS预取、现有受保护parent恢复及阻塞donor交接保持原路径。
  这类既有恢复权利不会被普通短任务夺走。它们仍属于明确保留的例外，
  不能声称所有JOIN父请求也已参与无条件全局组合竞争。
- 记录首次资格延期、集合、参考集、资源/成本身份和拒绝原因。实际服务
  仍需通过同request/attempt的原生进展日志确认。

## 尚未完成的验收

组合代码要求预测工件中冻结的 `admission_cost_profile`，包括批次宽度
成本及其身份。当前CPU测试中的成本表仅为测试输入；尚无新负载匹配
标定后的正式R5工件和GPU比较，不能把测试表当作已测硬件性能。

当前资源观察优先确认原生空闲页，不把全部evictable计为无成本空间。
缺少可用摘要时回退参考方案；尚未扩展对所有真实阻塞冷页的完整成本
摘要，也未证明组合选择在实际数据中有足够覆盖。

500us仅为枚举的软预算，候选发现、摘要、后台预测和日志还要统计。
组合入口总CPU/wall计数包含同步日志提交，异步落盘及后台预测另计。
GPU数值、完整模型、运行成本及JCT/吞吐收益均待验证。旧完整oracle
和Full结果、正常长尾、源数据及用户文档保持不变。

当前相关共享CPU检查986项通过、无跳过；最终组合/运行时/工作量准备
聚焦检查66项通过，包含实际原生候选选择、周期入口、真实JOIN额度交接、
日志序列化及chunk输入口径。这不替代原5268项完整来源绑定资格，也不
构成GPU性能或成本预测准确率的证据。
