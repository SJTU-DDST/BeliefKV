## 输入、目标与执行

首版采用 CPU 字符 2/3/4-gram TF-IDF 投影和 128 维条件 MLP，
不是预训练语言语义编码器。任务文本投影每条 workflow 只做一次；
输出为 short/mid/long 的完整概率分布。概率进入已有组合评分：

`q = p_short + 0.5 * p_mid + 0.25 * p_long`。

输入仅含显式任务元数据和已发生的执行进度。共 36 个数值特征，包含
root/child 各自的必要新增输入、实际输出、已完成请求，观察到的子代理
角色类别、委派字符数、child 状态、spawn/JOIN 数量及深度等。
不解码完整 prompt，不编码源码或工具输出，不使用未来调用数、子代理数
或录制的最终输出长度作为线上输入。旧版 prompt-tail 回退在 R5 关闭。

已有 capture 的执行规则不完全相同；本版没有把当前一个全局 ENV
冒充为所有历史 workflow 的原始指令。该版也未编码每段委派文本的语义，
只使用已观察的角色类别与长度。显式逐 workflow 执行规则和更强的语义
编码器属于后续扩展，当前精度不能作为这些扩展的证据。

标签为完整逻辑 workflow 的剩余 `0.01 * necessary_input + actual_output`，
包含 root 和所有 descendant，各项只计一次。未来完整轨迹只生成标签；
工具等待、排队、DMA、重试与缓存丢失导致的额外计算不计入该目标。
这不是剩余墙钟 JCT 或 GPU 秒数预测。现有工具时间预测仍是独立路径。

必要输入在首次观察到输出时计入已获服务，后续粗粒度输出只增量记账。
调用完成时保存同 context 的真实 token 前缀历史，重试不重复计费。
离线导出复用已经来源绑定的实际输入增量，避免物化所有长 token 包；
在线与离线的小型完整执行检查核对相同的逻辑工作量与特征。

预测事件经现有后台队列合并，每 workflow 最多每秒推断一次，长 decode
复用已有 128 token 观察阈值。spawn/RETURN/JOIN 等结构事件立即撤销旧
预测；新缓存发布必须匹配结构版本。缓存超过 3 秒或观察积压超过 2 秒
时撤销预测。dirty 更新在没有新事件时仍会被后台线程补算。

工具与 JOIN 状态只由真实事件更新。后继请求提前登记不能越过尚未结束的
工具或 JOIN；最后一个真实依赖返回后才恢复相应 ready 状态。预测时间
不会唤醒 agent。过期、缺失、队列溢出或 worker 出错时使用中性权重，
全部无效时回到原参考集合。

R5 的支持状态基于校准资格、各类别独立执行支持、任务词表覆盖及进度
支持范围，不使用旧版最大 softmax 0.6 门槛。模型格式独立，加载时拒绝
混入未来 workflow 图/逐请求标签，且必须启用组合准入，避免退化成旧
argmax bucket 排序。

本版概率只改变组合准入，不改变 active 的压力暂停顺序或 A→B 工具
替换候选顺序。现有工具权重、预测卸载、JOIN/EOS、prepare_host、
agent 连续性及 native 最终容量/锁/DMA 权限保留。工具预取与逐层 handoff
保持关闭。控制周期 2 秒、补位兜底 500ms、普通合并窗口 2 秒；
搜索保持六候选、需要 sibling 时至多八候选及 0.5ms 软预算。

## 训练与评价证据

证据根目录：

`experiments/reports/remaining_original_projects_20261030/useful_token_cost_r1/r5_distribution_cpu_r1/`

复用 73 个不同原项目的完整自然执行，没有改题、截断 child 或修改源码/
测试。导出 53,890 个快照，覆盖 11,796 个实际模型请求和 6,429 个原生
粗粒度 decode 观察。实际事件流、原生服务日志、原始 token 包、overlay
与标签文件均核对来源；未来工具时长不进入模型工作标签。

按整条执行划分为 43 条训练、12 条校准、18 条评价，评价组等于预先
声明的 400GB / 20 初始 workflow 方案的 18 个测量成员。没有拆分同次
执行的快照；温度仅用校准组拟合，分类阈值仅由训练组初始工作量确定：
13062.96 和 22971.15。该划分属于开发评价，不作未见项目泛化保证。

固定训练 200 epoch、8192 词表、dropout 0.1、weight decay 0.05，
没有根据留出组结果搜索参数。每 workflow 总权重相同，训练另做类别
平衡；报告中的精度和校准也按 workflow 等权。

最终模型为 `train_dependency_state_r2/model.json`，其评价如下：

| 指标 | 校准 12 条 | 留出 18 条 |
| --- | ---: | ---: |
| 全进度准确率 | 80.09% | 75.54% |
| macro-F1 | 0.697 | 0.562 |
| 初始分档准确率 | 75.00% | 61.11% |
| 支持范围内 long→short | 9.78% | 32.25% |
| 10 档 ECE | 0.0605 | 0.0569 |
| 支持概率分布覆盖 | 100.00% | 96.19% |

long→short 的分母为受支持的真实 long 快照质量，不使用旧 0.6 门槛
隐藏误判。类别支持、macro-F1≥0.5、long→short≤0.1、ECE≤0.15、
支持覆盖≥0.5 均在校准组检查；校准通过不保证留出组排序可靠。

`prediction_slices_and_cost_r3.json` 保留了按已完成固有工作比例的
后验诊断：留出组前 1/3 的准确率仅 53.79%，后 1/3 为 95.77%。
因此全进度 75.54% 不能当作准入竞争精度或初始工作预测精度；
后期 short 快照确实使聚合值更好看。中段 long→short 率还更高，需要
结合各类质量、支持覆盖和整个混淆矩阵判断。

初始 18 个 workflow 的 153 个非等量配对中，概率权重的大小排序正确率
为 55.56%，不是实际 ready-paused 竞争精度。初始真实 short 的平均权重
0.4671 还低于 mid 的 0.4913；long 为 0.3697。这说明早期短/中识别
仍不可靠，不能只靠“不用 argmax”解释掉留出问题。独立只读诊断为
`initial_probability_order_diagnostic_r1.json`，不因此调整模型或划分。

组件 CPU 微基准使用固定步长的 4,146 个真实特征快照：

- 单次缓存推理及支持检查：P50 0.0407ms，P99 0.0442ms，累计 169.57ms。
- 73 次任务编码：P50 1.929ms，P99 3.613ms，累计 152.11ms。

这些值不包含完整后台队列、进度核算、候选发现、native 检查或日志成本，

继续记录，GPU 服务干扰与真实准入竞争中的准确性仍待匹配实验。

## 到达压力与下一步

`prepare_host_pool_pressure.py --mean-interval-s` 现在支持显式缩短平均
间隔；保持原任务、排列、泊松随机种子和固定测量成员，只改变到达时序。
默认仍为已有 20 初始 / 平均 70 秒方案。测试覆盖原始和替换背景来源、
成员不变及同一指数样本的时间缩放；没有把测试中的间隔值注册为 GPU 实验。

先验证完整 400GB 分配/注册和实际模型资格，再运行非排序压力诊断。
如果 ready-paused 的真实容量竞争仍不足，可以缩短平均间隔，例如先从
70 秒改为 60 秒；需重新冻结双方到达表和共同吞吐窗口。缩短间隔可能
使有限负载过载或让背景提前到完，不能自动称为稳定 serving。

随后在同一 selector、成本、资源和到达条件下核对 oracle 是否改变集合、
授予能否保留以及是否改变实际服务，最后比较完整测量组 JCT。
只有 oracle 显示有价值后才推进 learned 对照；本次实现预测器不等于已
满足 oracle 收益门槛。预测的明显风险是中段剩余工作低估，不应只因为
初版校准通过就推广，也不能用留出组反复调参后仍称它为未见评价。
