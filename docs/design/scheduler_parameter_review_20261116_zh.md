# 调度参数与评分规则审计

本轮接续有界等待老化修复，检查还会隐式改变长短任务优先级的参数、
档位和计分函数。保留当前 133 个不同原项目、20 个初始 workflow、
平均 60 秒到达、400 GB Host、固定 18 个测量成员。
不修改 trace、工具时长、已完成结果或正在排队的冻结注册。

## 需要修正的三项

### JOIN 覆盖率不再额外平方

旧组合收益中，一个 ALL-JOIN 有 `n` 个未完成成员，其中 `a` 个
已经 active，本次新选 `k` 个成员时，workflow 的边际覆盖率为：

```text
((a + k)^2 - a^2) / n^2
```

这隐含了“越接近所有分支同时获得资格，收益越高”的额外偏好。
当前预测器只有 workflow 剩余总工作量，没有可信的分支剩余量和
关键路径完成概率；平方关系并不来自模型预测或实测完成收益。
四个未完成分支中首次选一个，只得到 workflow 权重的 1/16，
相对于均分份额又缩小四倍，可能压过短 workflow 的本来优势。

新配置显式声明 `admission_cost_profile.costs.join_progress="linear"`：

```text
边际覆盖率 = k / n
```

这是在缺少分支预测时采用等份工作份额的假设，不是分支完成收益
的精确估计。每个 workflow 总收益仍封顶一次，不能靠 fanout
放大权重；同组可共同放入的 sibling 仍接受 maximal 集合检查。
既有 JOIN 必须保留成员、输入预留、完整逻辑预算和原生容量权限不变。
不新增等待未 ready sibling 或 active 抢占的权限。

为了让旧日志与冻结产物可精确重放，未声明该字段时继续采用历史
`quadratic` 规则。准备脚本同时更新 Oracle/R5 的声明及成本身份，
测量得到的 prefill、H2D、decode 成本表原样保留。

### 工具保留权重不再按四分位粗分

旧压力选择先使用 `int(4 * retention)` 分档，再在最低档内沿用
工作量或原 KV 顺序。例如 retention 为 0.02 和 0.24 的两者同档，
而 0.249 和 0.251 却跨档。前者可能忽略明显的冷暖差别；
后者可能让很小的预测变动硬覆盖原排序。

新配置只把与最低保留权重相差不超过 1% 的候选视为接近：

```text
候选 retention <= 最低 retention * (1 + relative_tie)
```

接近者继续使用原压力排序。零权重只与零权重接近，不引入任意
绝对容差。该规则不增加候选扫描或 KV 探测，也不会让 R5 开始
按工作量抢占正在执行的请求。当前条件工作量分布模式的压力工作量
排序仍回退到原基座顺序；Oracle 的显式扩展压力实验保持其独立身份。

同时把短工具保护和兜底衰减从控制周期中拆出：

```json
{
  "tool_retention_policy": {
    "kind": "relative_tool_retention_v2",
    "short_grace_ms": 2000,
    "half_life_ms": 1000,
    "relative_tie": 0.01
  }
}
```

2 秒保护和 1 秒半衰期保持当前 2 秒控制配置下的既有时长语义，
后续改变控制周期不会静默改变它们。工具返回预测的观察时域仍取
`max(控制周期, 已缓存的完整迁移往返成本)`，因为它表示下次决策
和往返开销的时间尺度，不等于短工具保护时间。

1% 是限制接近比较的显式工程容差，尚未证明为预测噪声的最优值；
2 秒和 1 秒也不是本轮重新拟合的最优参数。缺少完整声明的产物
仍保留历史分档和周期绑定语义，避免改写历史运行含义。
参数声明必须完整、有限、类型正确；Oracle/R5 不一致时拒绝比较。

### 连续工作量与三档权重不能混用

当前有效连续预测已经使用训练参照尺度的 `effective_weight`，
并非仍用 `1:0.5:0.25`。缺口在异常回退：如果产物声明连续权重，
却只有三档概率或带非法权重，不能把它重新解释为旧三档单位。

新路径在周期准入、A→B 消费者排序和容量累积中统一验证权重。
缺失或非法时使用相同训练尺度的中性权重；所有预测都不受支持时，
沿用原参考选择。不会新增模型推理或使用未来轨迹。
552 条已封存 Oracle 快照没有出现缺失连续权重，不能用本修复
解释历史回退。成本声明也显式拒绝把布尔值当作数值参数。

| decode 成本时域 64 步、epsilon 0.1ms | 保留 | 当前 maximal benefit 不除以成本，这两项只影响成本诊断，不影响该目标的排序 |

| 卸载逻辑交接预算 1000ms | 保留兼容路径 | 已配对的即时 reference A→B 在此处实际取 0；不是当前活动路径的额外 1 秒等待 |
| ThunderAgent acting-decay 与长期逃生 | 保留论文臂 | 与 ready 排序老化不同，不静默调整 baseline |

## 同状态敏感性与证据边界

复用上一轮 `bounded_aging_r1/same_state_r2/observed_choices.json`，
其 552 次真实搜索全部精确重放，其中 234 次含未完成 JOIN 候选。
固定候选、真实资源、JOIN 必须保留成员、原参考集合及实际搜索截止条件。

| 变体 | 相对有界老化＋平方规则的改选 | 相对有界老化＋线性规则的改选 |
| --- | ---: | ---: |
| 有界老化＋线性 JOIN | 23 | 0 |
| 线性 JOIN，等待倍率上限 1 | 23 | 0 |
| 线性 JOIN，等待倍率上限 1.1 | 23 | 0 |
| 线性 JOIN，等待倍率上限 1.5 | 24 | 1 |
| 线性 JOIN，评分接近容差 0 | 30 | 11 |

| 线性 JOIN，仅将诊断成本时域改为 1 步、epsilon 改为 1000ms | 23 | 0 |

共同选中多个 sibling 的 group 记录从 61 到 62，不是消灭 JOIN
共同准入。相对原始无界老化实际选择，新组合改变 90 次选集；
其中 72 次来自前一轮有界老化基准，两个变化不能简单相加归因。
调大等待倍率并未带来更多有用选择的证据，不据此选择 1.5。

这些只说明参数改变了哪些局部决策，没有模拟新候选窗口、服务、迁移、
队列和完整 workflow JCT，也没有量化工具保留规则在运行中的净收益。
敏感性入口为 `scripts/audit_scheduler_parameters.py`。

## 匹配准备与资格

`scripts/prepare_scheduler_parameter_review.py` 从上一轮匹配产物生成新
Oracle/R5 配置，只修改显式 JOIN/工具保留规则、对应指纹和声明。
预测参数、老化、容量累积、成本测量、工作、到达、测量和资源保持原值。
准备不注册 GPU，不热改当前排队工作树，不重跑 Full。

准备和敏感性产物均保留在既有 `ready_capacity_accumulation_r1/`
下的 `scheduler_parameter_review_r1/`，不新增主实验版本。
真实 runtime attach、native 可服务候选、成本/参数类型、历史重放、
匹配准备与 Oracle/R5 同目标拒绝均有 CPU 覆盖。新参数非法时关闭已创建
的预测 worker，避免构造失败后残留后台线程。
完整源码绑定结果以 `bound_cpu_r3/evidence.json` 为准。`bound_cpu_r1`
保留验证器误传源码根目录的启动记录，`bound_cpu_r2` 保留验证器未传
真实事件 socket 的构造失败及精确错误；两次均未执行完整回归。
补齐验证器后，匹配 Oracle/R5 的真实构造、缓存挂接及参数检查均已通过，
没有修改生产策略来绕过检查。CPU 通过不代表 GPU JCT 通过。
下一次 GPU 应合并相关改进后再验证完整目标。
