# 物理卸载联动暂停与剩余工作量驱动的压力选择

## 本轮用户要求与修正

用户指出：已移出 HBM、返回后需要恢复 KV 的 agent 如果仍保留免竞争的
active 资格，恢复排序便覆盖不到它。此前只解释物理和逻辑状态独立，
没有解决本系统需要维持的工作集约束。这是实际的策略覆盖缺口。

用户同时要求将工作量用于 HBM 压力下的暂停选择，不能仅在
ready-paused 恢复时排序。这里实现两个分别声明的 Full 候选能力：

- `AGENT_RESIDENCY_PAUSE=1`：实际 FULL KV 释放后联动暂停；
- `AGENT_PRESSURE_PAUSE_POLICY=workflow_remaining`：必要容量控制中，
  在原有安全阶段内优先暂停剩余 workflow 工作较多的对象。

默认均保持旧行为，paper ThunderAgent 不继承这两个候选。实际构造、
运行状态、服务环境传递与声明验证均检查同一设置；没有改写历史结果。

## 工作集不变量

| 状态 | 是否有执行资格 | 是否参与 ready 恢复比较 |
| --- | --- | --- |
| KV 仍在 HBM、保留连续执行资格 | active | 不需要重复竞争 |
| KV 已卸载、工具尚未返回 | paused | 否，当前没有可执行请求 |
| KV 已卸载、真实后继请求已就绪 | paused | 是 |
| 已被本次准入选中、正在恢复 KV | active | 不因尚未复制完而重复撤销选择 |

因此，paused 总数与 ready-paused 数仍须分开。修复前者不能制造真实
工具就绪；目的在于让已返回的冷 agent 进入正常比较，而非堆积计数。
仅 D2H 备份、仍驻留的共享页、无关旧分支和新增输入都不能推导出
当前有效状态已经卸载。暂停也不代表相同数量的物理页立即可用。

## 实际卸载到暂停的链路

`ReferenceResidencyPause` 复用 reference adapter：

1. 预测工具卸载和原生 parent-pressure 物理释放回调，在确认
   FULL 释放量大于零后，核对当前 invocation/context/session 身份。
2. 只对真实阻塞、没有未完成模型请求的 owner 立即撤销资格。
   该资格释放不创建物理容量信用；原生页分配、锁和 DMA 条件继续生效。
3. 周期恢复不能把仍在等待工具的这类 owner 提前重新激活。
   TOOL_END 与实际后继登记后，它才成为普通可执行恢复候选。
4. 不经过上述因果回调的原生缓存驱逐，在后继登记、返回事件及 native
   选批边界补查：确认当前输入匹配的 Host checkpoint 确实缺少 FULL KV，
   才将原本 active 的续接退出免竞争集合。
5. 已授予恢复机会的同一请求记录一次比较结果；实际 native 服务后清理。
   不设置普通恢复的 1500 ms 绑定，也不重新启用工具预取。

选批补查每 200 ms 最多轮转八条等待请求，先读已有轻量驻留提示；
只有提示有 Host 缺失时才验证实际输入与 session checkpoint。提示不能
独立授予物理动作权限。注册和工具返回是事件更新，不按每个 decode token
扫描全部 agent。未知 checkpoint 保持 unknown 并计数，不按上下文大小猜测
已经发生卸载；纯丢弃后无可验证 checkpoint 的场景不能冒充已覆盖的迁移。

对已取得原生 request slot、已有可变 KV/输出或仍在 running batch 中的
对象，补查不直接暂停。已经选中的恢复在传输完成前可以持有资格，这是
必要的执行状态，不能要求所有 active 在每一时刻都完全驻留。
JOIN/EOS 的现有恢复与 sibling 路径保留。

新增 `paused_invocation_ids` 与 `residency_paused_invocation_ids`，
与原来的 `paused_pending_invocation_ids` 分开。日志
`agent_full_offload_paused` 分别记录实际缺失 FULL token、释放的逻辑预算、
是否已有请求以及来源；不能把整个逻辑预算当作实际搬运或释放字节。

## 容量压力下的暂停选择

原 reference core 在完整预算为负时，先按 KV 上下文由小到大暂停 acting
对象；没有 acting 对象时，再为 reasoning 对象标记在请求完成后暂停。
这与 workflow 的剩余模型和工具关键路径并不等价。

新候选在相同必要压力入口、相同安全阶段内使用缓存的 workflow 剩余工作：

1. 先处理可以立即暂停的 acting 对象；有可靠预测时，剩余工作由长到短。
   同分优先选择较大逻辑预算，以减少需要暂停的数量。
2. 所有候选中只要有未知预测，这一候选池回退到原上下文长短顺序。
   已 ready 的受保护 JOIN parent 在可靠预测排序中尽量保留。
3. 不足部分为 reasoning 对象做请求边界标记，仍优先选择剩余工作较长者。
   不打断正在运行的 kernel，不在 token 中途强制换出。
4. 标记计划只用于避免标记超过缺口所需的对象；已经存在的标记也计入计划。
   实际 `remaining_capacity()` 仍不回收这部分额度，直到请求真正结束。

例如，容量为 100，两条 active agent 的上下文分别为 20 和 90，总计 110。
若前者所在 workflow 剩余工作为 1，后者为 100，reference 会先暂停 20；
新策略在允许安全暂停时优先保留短 workflow、暂停 90。若两条都正在执行
模型请求，只标记长者，当前剩余额度仍为 -10，不能据此授予新请求。

oracle 使用已有剩余模型服务与工具关键路径；后续学习模型使用已缓存的
可靠档位，未知时回退。不在暂停时读取完整 prompt 或同步运行新预测器。
这不是全局最优 JCT oracle：物理独占可释放页、备份/恢复成本、decode
宽度和 JOIN 临界分支仍会影响收益。当前 tie-break 的上下文 token 也不是
共享页去重后的可释放字节，不能宣称已经完成最优组合或物理成本评分。

新增日志 `workflow_remaining_pressure_pause` 同时保存新/旧受害对象、
预测是否可用、是否仅做暂停标记和实际剩余预算。选择和服务必须继续关联，
不能以“改变了更多暂停对象”替代完整 JCT。

## CPU 与 GPU 证据边界

37 项专项测试已经通过，使用真实 native CPU 树/分配器与原有拷贝队列
替身，覆盖实际预测卸载、原生压力释放、备份与失效身份保护、
真实后继返回、排队期间驻留丢失、选定恢复不被重复暂停、
新暂停策略的 acting/请求边界行为、未知预测回退与 paper 隔离。
联合定向检查 266 项通过；完整源码绑定检查位于
`experiments/reports/remaining_original_projects_20261030/residency_pressure_bound_cpu_r1`。
该检查已通过 6069 项及 23 个子测试，保留全部 6032 个旧测试身份和
既有源码路径，共 2234 个源码输入，无失败、错误或跳过。执行期间
应用源码、原生树和外部配置/负载输入保持不变；此证据仍仅为 CPU。

CPU 配置为 `residency_workflow_pressure_cpu_r1/full.json`，派生自同一
56 原项目、8 初始/70 秒、原工具 overlay、Host 200 GB 的 oracle，
仅显式启用两个候选。实际 runtime 构造及完整模型配置检查已接受。
它保留原 1 秒声明，不假装已经完成新 GPU、配对控制或纯排序消融。
新 GPU 登记、当前位置采样检查与配对控制仍需另行执行。

旧冻结 `020527dd` 轮已经完成 18 个测量 workflow、2819 条请求和 362072
输出 token，平均 JCT 985.656618 秒，对照 931.500654 秒，回退 5.813841%；
共同窗口输出吞吐仅提高 0.343935%。完整测量回执、排空和实际退出已验证，
非测量尾部按协议截尾。原背景覆盖不足结论保持。
旧结果没有达到目标，且不包含本候选与上一轮链路修复，不能当成新策略的
GPU 结果，也不能将全部回退事后归因于某一个已发现的缺口。
