# 逐层卸载与加载重叠的当前验证范围

本候选保持默认关闭，仅用于Full已选定且有逻辑执行资格的消费者。
原生分支为`beliefkv-layer-handoff-20261027`，组件验证使用已提交的
`2a927b88939cc687617c32e23bb3440fabb6d7f7`。没有更改共同基线引擎
或把原有ThunderAgent结果重新标记为使用此候选。

事务将工具阻塞的私有donor A逐层D2H备份，在对应层备份完成后把B的
Host状态H2D写入相同Device索引；B的该层只等待自身就绪事件，不等待
A最后一层ACK。索引在事务期间保持保留，不进入普通free pool。
A多于B的尾部索引只有在donor原生D2H ACK之后才能释放。A/B大小可以
不同，但完整Host目标、B源引用、剩余输入及增长预留仍须成立。
尚未实现无额外Host容量的逐层双向Host槽交换。

真实GPU组件检查保存在
`experiments/reports/layer_handoff_20261027/gpu_components_r1.json`。
128个Device槽和257个Host槽、两层MHA的场景中，A48/B32/受保护
resident48及额外占用28，使初始只剩4槽，A和B无法同时驻留。
提交后仍只有4个free槽，donor ACK后才成为20槽；全部A Host和B
Device K/V字节、受保护resident及真实在途A读取均核对通过。
有限的末层D2H延迟夹具证明B首层读取可早于A最后一层ACK；自然微小
拷贝场景没有观察到该提前关系。这是组件依赖与数据正确性证据，
不是完整模型数值恢复或性能收益。

首次真实模型资格测试保存在同目录`model_r1/`，状态明确为failed。
它完成B初始、C、A初始和B后继四个不强制输出的调用，但资格操作器
没有取得恰好一次`layer_kv_handoff_submitted`的证明，因此没有进入
B/A恢复后与各自参考调用的贪心token及logprob比较。B后继响应报告
4096个Device命中token及12295个Host命中token，不能仅据此推断这些
Host状态由逐层handoff恢复。日志的异步刷新及原生需求恢复路径仍须
进一步区分。保留原始失败与所有请求、响应及owned cleanup证据，
不以组件成功覆盖此次失败，也不将它当作性能负收益。

下一次独立模型检查等待实际A预测和B handoff日志刷出后再判定，
同时保存每个阶段最后的runtime快照及非快照事件；超时仍然失败，
不把普通Host命中当作handoff。预热使用8次实际4秒工具等待，不向
预测器提供未来等待时间；仅此数值夹具关闭普通工具预取，隔离目标
路径，生产实验配置不变。共享CPU检查单次通过3423项及4个子测试，
包括两个新增的日志刷新与错误目标拒绝反例，保留此前3421项。
原生组件测试首次误导入已安装包的15项失败保存在
`native_current_cpu.xml`；明确设置候选checkout的PYTHONPATH后，
同15项全部通过，保存在`native_current_checkout_cpu.xml`。
