## 1. 负载、到达与评价先验收

复用完整原题及已完成轨迹；缺少任务档位或项目时再补采，不改写题目、
截断正常尾部或预先修复任务源码与测试。保留不同项目与长短上下文的
交叉覆盖。模型工作 P80/P20 最低 3，同时报告 4；工具工作按真实依赖
关键路径统计，不能直接累加并行等待，也不用旧 JCT 定义任务大小。

当前 46 项目、固定到达表和工具 overlay 的 Full 是待验收的控制实验，
不是已经合格的理想负载。10 个预热、18 个固定到达序号的测量成员及
18 个背景成员保留各自完整执行。全部方法复用同一完整到达表；JCT 从
预定到达到自然结束，吞吐在共同墙钟窗口内包含背景输出。不能选择
最早完成的成员，不能按某一策略测量组结束时刻停止背景提交。

验收依据必须包含：

- 测量成员完整完成，背景提交和有效工作覆盖测量尾部；预热后积压与
  ready 人口分时统计，单凭预热数量不宣称稳态。
- 在恢复边界反复出现不同剩余工作量的 ready-paused 候选，单独可容纳、
  合并不可容纳；分别核查逻辑预算与物理页/输入/请求槽位条件。
- 空位释放到资格授予、再到同一 request attempt 实际模型服务的关联；
  统计准入类别、保护入口、原压力撤销和 native 拒绝。
- HBM 空闲、可回收及不可回收状态，Host 重复备份与有用前缀损失、
  实际额外重算；Host 使用率高本身不判失败。
- 多成员阻塞 JOIN、单 child 工作量、root 工作和重复并行轮次。当前
  结构短板独立公开，不能用总体工作量倍率掩盖。

负载未通过时，先修复到达供给、实现或更换完整原题组合；保持原实验、
被移出轨迹及失败证据。选择不能依据哪个策略获胜。

## 2. 先验证 oracle 的选择价值

同一任务、token、依赖、工具时间、到达、容量及评价下，以关闭工作量
排序的 Full 为匹配控制。oracle 显式使用未来工作及冻结工具时间，只是
诊断，不是可部署结果，也不是最优 JCT 上界。

先核查现有 oracle 与组合实现，不把“类别内排序”称为完整 R5。检查
周期恢复、首次注册、免费续调、sibling 等入口的覆盖；保留 JOIN/EOS
预取及必要恢复权限，不为增加 oracle 覆盖而取消 JOIN 安全或真实依赖。
尽量将合法竞争者放入同一有界集合比较，保留原入口预算和 active
连续性，由 native 检查最终决定物理准入。

验收链为：选择集合改变 → 原压力处理后保留 → 同 attempt 实际服务
→ 分支推进/恢复等待改变 → 完整 workflow 平均 JCT 与共同窗口吞吐。
同时报告 P95、长任务与背景等待、迁移、重算和累计控制 CPU 成本。
微基准、逻辑 grant 或排序变化不替代端到端收益。

若收益不明显，依次检查竞争机会、硬类别和旁路入口、单体贪心与组合、
物理准入及实际服务、batch 效率和控制成本。必要时扩大完整原题之间的
工作量差距或调整持续供给，再使用新的匹配控制验证。短任务优先有收益
是需要检验的假设，不预先保证任何固定轨迹必然获益。

## 3. oracle 取得明确收益后再实现预测

再按 [R5 第 14 节](workflow_size_join_frontier_20261029_zh.md#r5-conditional-join-admission)
实现条件剩余工作分布与事件更新，沿用已经验证的选择和服务路径。
默认 6 名候选，真实 sibling 比较按需扩展至 8 名；新增组合计算的
0.5ms 是软预算及待测 P99 目标，候选发现、页摘要、native 检查、
日志与后台推理的开销另行完整统计。

预测器只读取任务指示、委派/角色、已观察进度和历史，不读取完整模型
prompt、私有未来图、未来输出和隐藏工具采样时长。预测缺失、过期或
不受支持时撤销长短偏置。工具等待与固有模型工作分别建模，不能让墙钟
等待自动消耗模型剩余工作。学习标签、工具感知 oracle 的关键路径和
真实 JCT 明确区分。

oracle 收益建立前不训练/推广新工作量预测器，也不启动其他 baseline。
保留 JOIN/EOS、工具预测卸载、prepare_host 和 agent 连续性；工具预取、
普通恢复绑定、逐层 handoff 与 mixed chunk 继续关闭。
