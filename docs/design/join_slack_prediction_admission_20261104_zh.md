# 基于条件分支预测的 JOIN 余量准入

2026-11-04，Asia/Shanghai。回应用户对 JOIN 瓶颈与余量调度的细化要求。
本文是 D1 的候选升级设计，不是运行中的新策略或已验证性能结论。
不改变当前联合实验，不开启额外 GPU 实验。

## 目标和决策边界

对一个真实已阻塞的 ALL-JOIN，parent 恢复取决于最后成员的 RETURN。
服务有余量的分支，不一定立即改善 JOIN；但延后过久，又会把该分支变成新瓶颈。
目标是把余量暂时用于其他 workflow，同时避免明显推迟 JOIN。

仍以单个 agent invocation 为执行身份、workflow 为评价身份。
选择只发生在可变更的新准入、ready-paused 恢复和真实阻塞 donor 容量替换入口；
不抢占已有 active agent，不因短任务到来轮换其 KV。
若 B 与 C 能共同通过正常准入并获得服务，就不为制造选择窗口而刻意搁置 B。
没有其他真实可执行消费者时，也不单独因为某个分支“有余量”而暂停或卸载它。

只使用运行时已观察 JOIN、成员和 RETURN。不采用回放未来图补出在线依赖。
SPAWN 不等于 parent 已阻塞；parent 的 JOIN/EOS 恢复保留原有授权和准入规则。

## 为什么现有模型还不够

当前组合分子按 unfinished/active/selected 成员数计算二次覆盖，
同一 workflow 共用一个 short/mid/long 概率权重。
它没有分支级剩余需求，也没有工具阻塞造成的 JOIN 完成余量。
不能把现有三档权重直接当作分支的剩余秒数，更不能把所有 sibling 赋成
同一个 workflow 的剩余工作量。

已有完整对照的测量组包含 19 个完整多成员 JOIN，首末 RETURN 差
P50 为 33.790 秒，P90 为 217.622 秒。
尾差同时包含固有工作、工具等待和调度，不能当作可消除等待。

当前联合实验的一个封存前缀还有更具体的选择证据：
7804 条组合日志中，444 次完整搜索精确重放，37 次不完整搜索排除；
146 次完整搜索涉及未完成成员数至少为二的 JOIN。
其中 46 次存在改变 JOIN 成员选择的极大可行集合，34 次可以保持
准入 agent 总数相同，22 次涉及测量 workflow 的替代选择。
这些替代窗口合计覆盖 21 个不同 JOIN，其中 4 个属于测量 workflow；
不能把重复窗口当作独立 JOIN 或独立 workflow 样本。
这是规划资源下的机会，不证明即时原生可执行、这些替代更好或 JCT 已改善。
其余 7323 条是元数据不足或没有进入搜索的日志，不统一归为失败。

## 预测什么

分开预测需求与资源占用，再由候选集合决定服务时间，避免直接学习旧策略的排队。

| 对象 | 预测输出 | 可用输入 |
| --- | --- | --- |
| 当前 child 到本次 invocation RETURN 的剩余模型需求 | 连续需求分布或校准分位数；自身与已观察后代分别归属，工具时间不混入 token 工作量 | 任务委派、角色、已经完成的模型调用/生成量、当前已观察委派与返回进度、当前上下文 |
| 正在执行工具的剩余时间 | 条件生存分布 `P(R_tool > h | T_tool > elapsed, x)` | 工具类型、真实可见命令类别/参数规模、已等待时间和已完成历史；缺少的特征不虚构 |
| 分支后续外部阶段 | 剩余外部关键路径的不确定性，或明确标记不支持 | 已观察阶段和历史统计；未来工具仅可作离线标签 |
| 一次服务的执行/恢复成本 | KV 恢复、必要备份、输入处理和 decode 成本估计 | 真实缺页字节、近期传输成本、输入增量、上下文与 batch 形态 |
| 竞争者 C 的占用窗口 | 从准入到能自然释放相关容量的时间分布 | C 的剩余模型需求、已观察阶段、连续性和正常工具期释放规则 |

训练标签可以来自完整轨迹的后续内容，但在线输入不能包含未来 RETURN、
完整未来调用数、实际采样工具时长或完整 prompt。已有原始 task/delegation
元数据可保留，不把模型尚未获得的信息塞进特征。

工具模型首先复用现有条件生存预测，不能只拿工具开始时的固定 P90 减去 elapsed；
已经持续很久且仍未结束这个事实会改变条件分布。
现有分层模型对观测尾部不支持时返回未知，不把它解释成“马上结束”。

分支模型不能直接用一次实际“从现在到 RETURN 的墙钟时长”作需求标签：
其中含有我们正在优化的准入、迁移排队和其他 workflow 干扰。
优先从固定模型工作与工具依赖重建服务需求，运行时再映射到当前资源下的完成分布。
只掌握模型工作、无法支持未来外部阶段时，不声称已经准确预测了 RETURN 时间。

## 如何计算可借用的余量

对准备恢复的 ready-paused 分支 B，定义：

- `L_other`：其他未完成 sibling 的 JOIN 完成时间的保守低侧估计。
- `U_B`：B 在计划服务下到 RETURN 的高侧耗时，包含必要剩余模型和外部阶段，
  不重复计入初次 KV 恢复与排队。
- `R_B`：B 初次恢复和再次准入的成本。
- `M`：控制、批次交接和预测误差的安全余量。

```text
slack_B = L_other - U_B - R_B - M
```

这里要防范其他分支提早结束，所以 `L_other` 不能直接取工具 P90。
可以用经过验证的低分位数；B 的完成和恢复用高侧估计。
具体分位数由条件覆盖率和误判代价校准，不能把 P10/P90 当作天然正确的常数。
它们也与工具卸载现有 75% survival 门槛不是同一个参数。

若有联合情景预测，从情景中的 `max(other branch RETURN)` 得到组的分布；
若只有各分支的边际分布，不能直接把若干 P90 的最大值称为 JOIN P90。
简单保守实现可以取其他分支低侧界中的最大值作为余量下界，
但不能声称由此获得了完整联合分布或任意状态下的严格保证。

当前 invocation 若可能继续生成大量工作、后续工具或嵌套子任务，
这些不确定性应放宽 `U_B`。支持不足或 `slack_B <= 0` 时，不享受延后优惠。

## 不是有余量就无条件让给 C

还要检查 C 的占用窗口 `U_hold_C`：

```text
U_hold_C <= slack_B
```

这里的占用包括为 C 腾空间和恢复的相关代价，直到 B 能再次进入正常准入；
不能只看 C 当前模型请求生成几个 token。若 C 取得 active 后会连续执行很久，
即使当前请求很短，也不能据此把 B 的余量承诺给它。
如果无法支持 C 的自然释放预测，初版不允许这种余量特例。

这个式子是易解释的保守筛选，并非完整多资源调度的保证。
最终还需使用真实输入、增长、槽位和 KV 容量检查，并估计改变 batch 对其他
active workflow 的服务影响。恢复、分支执行和容量占用不能各重复计费。

例如 A 的工具点预测还有 8 秒，但早侧估计只支持 6 秒。
B 的高侧 RETURN 耗时为 1.4 秒，恢复为 0.3 秒，安全余量为 0.3 秒：

```text
slack_B = 6.0 - 1.4 - 0.3 - 0.3 = 4.0 秒
```

若 C 到自然让出相关容量的高侧窗口是 2.5 秒，就可以比较先服务 C 的方案。
若 C 当前请求只需 2 秒、却可能继续持有资格 12 秒，则不能通过这个特例。
如果 A 的早侧返回估计改为 1.5 秒，B 就没有正余量。

## 统一集合评分

余量是安全筛选，不是新的全局硬优先级。通过筛选后仍与其他 workflow 统一比较，
不能让一个多分支 workflow 因 fanout 获得多倍分值。

在同一候选宇宙和资源约束下，以当前方案 `S0` 为参考：

```text
gain(S) = sum_over_visible_workflows E[T_w(S0) - T_w(S)]
```

其中 `T_w(S)` 是有限情景推演得到的预计完成时间，不是源轨迹的实际排队时长。
每个 workflow 只计一次；不识别或偏袒固定测量组。
可以直接选择预计平均 JCT 更低的集合，不再额外除以 KV 或计算成本。
恢复和 batch 效率的代价通过 `T_w(S)` 与真实容量约束体现。

对于 JOIN，使用已观察 frontier 的 `max(branch completion)`，不用 sibling 数量
替代完成时间。共享资源会使各分支相关；若情景模型暂时不能可靠表达这种影响，
应明确限制为局部代理，不能把算出的 gain 宣称为真实 JCT 改善。

初版分支模型和情景推演的支持范围可以较窄：
优先覆盖真实工具阻塞加 ready sibling 的已观察 frontier。
其他分支或 workflow 估计不可比时，使用现有 D1 方案，而非赋零工作或零等待。
不将独立分支边际分布相乘冒充已经验证的联合完成模型。

## 与现有 KV、连续性和事件路径结合

1. 延后只改变尚未消费的新准入选择，不撤销已有 active 或在途恢复事务。
2. 有真实替代消费者且容量不足时，工具阻塞 donor 继续走原有预测卸载路径，
   保留 ACK、Host、锁、DMA 和原生动作前检查。
3. B 已在 Host 时，代价包含实际恢复；B 尚未需要卸载时，不因为有余量就额外迁移。
4. 真实 TOOL_END/RETURN、容量释放、传输 ACK 或阶段变化可立即重评；
   不为了等待普通 2 秒合并窗口而延迟已经有效的事件替换。
5. 普通窗口仍沿用当前 2 秒，背景工具重试沿用当前 400ms。
   余量边界可用有界期限索引唤醒，不新增每 200ms 全量扫描。
6. 工具结束使原余量依据失效时，撤销 B 的延后优惠并重新比较。
   尚未消费的选择可取消；已开始执行的 C 不会因此被强制抢占。
   预测错误造成的 JOIN 推迟必须如实记账，不能声称回退会消除既有代价。
7. JOIN/EOS 恢复保留，但预测时间不授权 parent 提前执行，
   也不新增普通恢复绑定或重新开启工具预取。

## 开销和预测错误控制

分支需求模型异步更新，原生调度线程不等待推理。
每组缓存分支分布、瓶颈摘要和余量期限，仅在阶段/服务进展有意义变化时更新。
组合搜索仍使用当前 6 候选、必要时扩展到 8 的边界；
0.5ms 仍是组合子步骤的软预算，不冒充全部控制回调的硬上限。
若分支情景计算超出预算，使用已支持的参考方案，不增加前缀树重复检查。

评估至少包括：

- 原工具阻塞分支早于低侧预测结束的频率。
- B 晚于高侧估计 RETURN、C 晚于预计自然释放的频率。
- 因策略延后而成为新 JOIN 瓶颈的次数、尾延迟和迁移成本。
- 实际被帮助 workflow 的完整 JCT，而非仅逻辑资格或首 token。
- 同一共同墙钟窗口的吞吐、完整请求 E2E normalized interactivity 和长任务等待。
- 分支预测与集合比较的线程 CPU 成本和回退覆盖。

开发阶段可复用现有轨迹检查可行性，但若数据用于训练和调参，
分位数覆盖就不能冒充独立验证的保障。后续按项目分组和时间顺序检查校准，
保留失败与右删失样本，不把未完成分支当作零剩余工作。

## 实施顺序

1. 先完成当前联合实验，复用已有同资源 Full 与 ThunderAgent 对照。
2. 已增加 CPU 容量机会读器，保留实际选择、原生资源摘要与必需 JOIN 权利，
   只枚举记录候选的可行集合，确认有实际选择空间。
3. 下一步用分支级 oracle 替换成员覆盖，观察它是否改变有效选择；
   同时检查替代集合的后续完成和受损者，不把局部 set change 当作 JCT 收益。
4. Oracle 对这些机会有效后，再加入连续分支需求和条件工具剩余时间预测，
   对比 oracle、预测和现有方案的选择一致性与错误代价。
5. 有足够净收益余量后，与其他完成改动合并为下一次 GPU 候选。
