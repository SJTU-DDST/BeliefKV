# 工具卸载门槛、Host 空间与逐层交接联合验证

2026-10-28。按用户最新要求，第一轮直接测试联合 FULL，不先增加门槛或 overlap 的消融。

## 工具卸载

保留旧配置的 90% 默认值；新配置显式声明
`BELIEFKV_TOOL_OFFLOAD_MIN_SURVIVAL=.75`。判断的是工具在实际迁移成本窗口之后
仍阻塞的条件概率，不是工具总时长的 P90，也不是 75% 的预测准确率。
成本继续包含缺失 D2H、消费者 H2D、累计 donor 的恢复 H2D、控制周期与必要逻辑准入等待。
真实消费者、HBM 缺口、当前 agent 资格、工具仍阻塞及原生锁/DMA/身份条件不变。

完整经验 CDF 使用可配置概率；只有 P10/P50/P90 的旧提示使用不弱于目标的已有档位，
例如 75% 门槛仍使用 P10，不插造 P25；要求超过 90% 而没有更低分位证据时放弃。
预测刷新与生存尾部支持检查继续保留。

## Host 容量

新配置声明 2 GiB 可选备份余量，并可按最近一秒的实际卸载缺口提高。
SPAWN 备份限制单次字节数；idle prepare 在不足以保留余量时让步。
这不是把 Host 池缩小：实际需求卸载仍可使用这些容量。

有实际获益对象且成本通过后，若额外工具卸载或逐层交接缺 Host 目的空间，
最多检查 64 个原生冗余副本，回收完整、Device 已锁定、无 Host 锁及在途 DMA 的 Host mirror。
保护当前 donor、消费者与预取服务租约；不释放 Device，不删 Host 唯一副本，
不为可选备份主动回收 mirror。原生 demand eviction 原本已经优先回收冗余副本；
本改动补充的是显式非驱逐备份/交接路径及可选备份的预算。

Host-only 的必要工作集本身超过容量时仍可能无法无损卸载，不能承诺任何压力下都不失败。
逐层交接同样需要完整 donor 的 Host 目的空间及受保护的消费者来源，因此暂不移除 prepare_host。

## 联合实验

声明：`configs/migration/predictive_host_demand_layer_handoff_20261028.json`。
保留 V230 的 18 个不同项目、3674 个请求、549671 个输出 token、72 次 JOIN，
使用同一 V311 分类工具时长、200 GB Host、805198 Device token、running/decode 24 和 seed 21。
保留所有正常长尾。新增 native tree 为
`0d407f981c5179b20859e82e7088d85589cd08b3`，以独立 patch 和树哈希注册，
不改公共 staging patch，也不复用旧引擎的 position smoke。

真实小池组件和模型 R5 已验证逐层交接原生实现；R5 的约 1.21 GB 交接后，
消费者与 donor 恢复的贪心 token 均与参考一致，最大 logprob 差为 0。
这些是正确性证据，不是完整轨迹的性能结果。当前联合策略仍须通过源绑定 CPU、
当前模型检查与新引擎 24 请求重放校验。

第一轮比较整体组合与完成的 ThunderAgent decay V345，并参考刚完成的在线刷新 FULL。
新引擎与多个策略同时变化，结果不能归因到某一个模块。
若联合 FULL 无收益，按迁移/计算干扰与首用证据定位，再关闭 overlap 做针对性对照；
负收益方案不提升为默认。
