  自然完成后即可停止背景。共同墙钟窗口统计全部服务输出。

## 执行顺序

1. 解除当前启动路径对 NUMA 均匀性和逐页计数完全相等的强制要求。
   保留实际池容量、CUDA 注册、传输正确性、原始 token 和停止条件检查；
   页面分布、计数差额和远端比例只记录为诊断。新的匹配控制使用同一内存
   策略，实际分布不必精确相等。已实现显式 `diagnostic` 模式，容量与页面
   均匀性独立判断；597 项相关定向检查全部通过，新压力控制已进入
   实际服务，历史失败不改判。
2. 运行一轮非排序 Full，检查真实 ready-paused 供给和恢复竞争：
   不同 workflow 的候选各自可执行，但不能全部装入。分别统计独立竞争、
   改变准入集合、保留资格和实际获得服务，不以重复 tick 或排序改变替代。
3. 在相同 Host、任务、到达表、测量组和执行配置上运行 oracle。
   第一阶段目标是可重复的约 1% 或更高平均 JCT 改善，同时共同窗口吞吐
   无明显下降，长任务和背景等待可解释。单次小幅正收益只作为继续依据。
4. 若竞争不足，优先缩短平均到达间隔或调整在途人口；一次只改一个配置。
   若已有竞争却无收益，先核对资源组合、准入到实际服务、decode 效率和
   控制成本。确有工作量区分不足时，再调整原始 workflow 的选择。
5. oracle 明确获益后再评估 R5 条件剩余工作分布预测器，并补相同配置的
   ThunderAgent acting-decay 对照。旧 200GB 结果不作为 400GB 的匹配对照。
